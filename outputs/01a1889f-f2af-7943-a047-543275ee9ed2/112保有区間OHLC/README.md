CSVはUTF-8 BOM付き。日時は日本時間（`+09:00`）の文字列。空欄は未到達・不明・対象外のいずれかで、0とは区別する。意味は列定義とその行の価格・政策により判断する。

取引0の場へ架空の建玉行は作らない。0件を含む24×70の場別収支は、既存の[全セッションCSV](../112損益CSV/全セッション.csv)が正本であり、このOHLC表から除外条件を加えたものではない。

## 読む順序

1. 候補別で `S0_C0_D0`（元手法）と `P100_C0_D0`（支持否定＋MACD失速で可変幅）を比べる。
2. 建玉全体で `口座=P100_C0_D0`、`実正益後赤字=true` に絞り、`実現純利益円` の損失が大きい順に並べる。
3. `全玉最大W円`、その初回時刻、`H50初到達時刻`、`H100初到達時刻`、`利益保護起動時刻` を見る。Lastの最高値だけで利益を判断しない。
4. 気になる `建玉ID` を返済片へ接合する。部分返済・要求時刻・実約定価格・返済前後のn/R/Wを確認する。

11/06の代表例は、デイの元 `S0_C0_D0-P000016` と保護 `P100_C0_D0-P000015`、同日保護の `P000029`。ナイトの保護 `P000037` も調査へ掲載した。CSVの完全なIDには日付・Day/Nightが付く。

## 列の定義

- O/Cは実取得・返済行での当該価格の最初/最後の値。実取得価格・実返済価格は別列。Last・Bid・Askを混ぜない。
- H/Lの初回と最後の日時・Index・物理行を保存する。同じ日時でも物理行が違えば別更新。Indexは採用されたNK原行の0始まり、物理行は元JSONLの1始まり。
- 買いの返済側はBid、売りはAsk。Bid/AskのOHLCには有限の `0<Bid<Ask` の正常行だけを使う。正常Lastがある異常BBO行はLastへ残す。
- `全玉最大W円` などのWは、実既返済純額R＋残枚数n×1枚費用後評価u。部分返済後に返済済み枚数へ後の値動きを適用しない。
- 返済片のWはその実返済枚数だけの区間評価（R=0）。返済片の `曲線基準枚数` は当該枚数であり、親建玉の `初期枚数` と区別する。
- `1枚最大費用後益円` はその時点の返済側BBOでの1枚評価。既返済Rは含めない。建玉全体の最大Wとは尺度が違う。
- `全玉正益後初負時刻` は初回正益の後に初めて負となった時刻。最高益の後とは限らない。
- H50/H100はWが初期1枚当たり費用後5,000/10,000円に初めて達した点。S0では観測水準のみで、追加保護起動を意味しない。候補別のS0の保護起動前/後の列は対象外空欄。
- `要求後不利BBO移動pt` は当該実要求から実約定までの返済側気配の不利方向変化。負なら有利方向。全玉の `最大` 列も符号を保つ。
- `取得後逆行で完結した赤字` は実現粗額<0かつ実現純額<0の成立玉。全経路が一方向だったという形状分類ではない。
- `価格同値の費用赤字` は実取得・返済の価格差0で費用だけが負となった返済片。建玉単位の勝ち負けと返済片数を混ぜない。

## 費用と限界

日経mini100円/pt、片道税込38.5円/枚。C0/C5は追加片道滑り0/5pt、D0/D1は追加0/1価格秒。滑りは約定価格へ二重加算せず費用として配賦する。ラージのBBOによるmini約定代理であり、実miniの板約定を証明するものではない。

原板の時計はCurrentPriceTime。実受信時刻は入力に無く、0秒差でも次の物理行で約定している。原板のセッション累積高安はこの集計に使わない。全24条件は同じ入口の対照を多く含むため、延べ件数を独立サンプル数としない。

未参加・退出後の仮想利益、最高点で決済した仮損益、機会損失は含めない。入力70場は既使用、11/09は未読。CSV全6,175,316セルを別処理系で再読し、元の統合集計と照合した。
