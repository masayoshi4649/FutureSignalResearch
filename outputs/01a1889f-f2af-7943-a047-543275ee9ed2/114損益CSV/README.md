## 候補と費用

候補A0は元の全出生を追加技法で選別せず、Tは順行票が真の出生、TRは順行T又は反転回復Rが真の出生を受ける。候補はentry_modeであり、保護政策は全12条件でP100共通。H100、MACD失速と動的支持否定による狭幅、適格な取得後構造床を維持する。条件の詳細は[試行114](../../../study/00114_順行と反転の取得確認を分ける/README.md)を参照。

日経mini、買い・売り各上限10枚の可変数量、点価100円、片道税込38.5円/枚。C0/C5は追加片道滑り0/5pt、D0/D1は追加価格時計遅延0/1秒。C0でも指定手数料は控除する。C5の往復追加費用は1枚1,000円。D0も同原行で約定せず、要求後の正常な後原行でfillする。スプレッドは実新規・返済価格へ含まれている。

全口座はセッション内で建玉・予約0まで完結。全セッションCSVの累計は条件IDごとに0から始まる。利益/損失総額と勝率は完結した実玉単位、同値も勝率の分母に含む。PFや平均値の分母0は空欄とし、0の成績へ補完しない。建玉全体の費用後清算評価はW=R+n×u（Rは既返済分の往復費用後実現額、nは実残枚数、uは残玉1枚当たりの費用後評価）。正益後赤字はWが一度正になった実玉の最終赤字で、WへRを二重加算しない。起動後赤字は追尾が実際に起動した実玉の最終赤字で、二つは重複し得る。全体の保存点連結時価DDと場内時価DDは列名どおり区別する。

## 入口分母の読み方

元新規要求数source_newはSourceのnew通知数。入口許可allowedは採用モード票が真だった要求数。受付acceptedは要求時の容量と同原行の元取消を反映した実新規要求/枚数、実取得actual_new_fills/actual_quantityは実際の新規fill/枚数。受付後に取消され、未取得になる場合もある。元要求、許可、受付、実取得を同じ件数として扱わない。

採用票はA0では全許可、TではT、TRではT OR Rである。A0の真票が全件でも、元のT/R条件が常に成立していた意味ではない。真＋偽＋未知は元要求数へ一致する。入力不足あり/条件の否定ありは、T/Rのいずれかの不足又は否定を含む要求数で、互いにも許可件数にも重複し得る。未知票と入力不足あり要求数も同じ件数とは限らない。

同じ出生を入口/費用条件ごとに反復しているため、12行の要求数を独立した市場機会数として合計しない。固定5分/15分枠の参加率はこの比較では定義・生成していない。元要求を分母とする入口指標と、実新規件数・実保有時間・数量秒を分けて参照する。

開始日はJSTのセッション開始日をYYYY-MM-DD JSTという文字列で保存した。表の作成時にも@文字列書式を適用し、CSVへ日付の通し番号を出さない。CSVはUTF-8 BOM/CRLF、一段ヘッダ。xlsxは生成していない。未参加/退出後の仮想利益、機会損失、MFE回収率、ROIは含めない。C0だけで採否を自動決定する資料でもない。
