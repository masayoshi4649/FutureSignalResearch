# RC20の口座と出口

日経225miniの日中に、[日経199_02の入口](入口と指標.md)で1枚を建てる。入口が決めた値幅で利確と損切を監視し、利確に近づいた場合、または保有と逆向きの主シグナルが続いた場合に利益を保護する。追尾で早く返済した後も、元の上下の価格に届くまでは次の取引を待つ。研究上の識別子は、追尾方法が `R02`、再開方法が `C`、開始待機が20分で `RC20`。[定義を固定した試行224](../../../study/00224_利益保護後の再エントリーをシグナルで待つ/反対信号保護の追試方針.md)

## 時計と気配

|項目|値・扱い|
|---|---|
|対象|日本時間のデイ08:45〜15:45。買い・売り共通の1枠。予約、未決注文、保有の間は次を追加しない。|
|新規判断|09:05を含み、それ以前の要求は破棄する。199_02の純入口自体は14:40未満まで。14:40までに取得できなかった予約も失効する。初参加補完は09:30以降かつ当日取得0件の場合だけ使う。|
|出口|価格監視は取得直後の次の原板行から場末まで。元入口が持つH60等の属性で保有を打ち切らない。|
|場末|口座として15:29:00に新規・新規取得を締め切って予約を取り消し、残玉に場末返済を要求する。研究上の約定窓は15:29:01から15:30:00までの最初の正常な気配。|
|原板|当場・当限月で価格時刻が有効な日経ラージ板。正常気配は有限で `0 < Bid < Ask`。同一時刻に複数行あれば原行順に処理する。研究では買い新規をAsk、売り新規をBidで取る。|
|評価|買い保有はBid、売り保有はAskで清算できるものとして評価する。ローソク足の高値・安値では上下のどちらが先だったか決められない。|

## 口座の状態遷移

|現在の状態|イベント|次の状態と記録|
|---|---|---|
|空き|当時の有効な主シグナル、または初参加補完が成立|新規予約とし、原行・判断時刻 `q0`・売買方向・片幅 `R` を保存する。同時なら主を優先する。|
|新規予約|後続の別原行で `q0+1秒 ≤ 時刻 < q0+30秒`、入口データの有効期限内、正常な気配|研究はこの最初の原行で1枚取得する。運転器は成行新規を依頼し、約定通知の受理まで未決とする。|
|新規予約|期限到来、入口の品質失効、または新規を禁止する状態|未執行の予約を解除する。同じ原行で新しい有効な判断があれば、改めてその判断を予約できる。|
|保有|有効な主シグナルが公表される|注文追加はせず、当場で直近2個の主通知の方向・時刻・原行を更新する。初参加補完や無通知の原行ではこの2個を押し出さない。|
|保有|固定幅到達、追尾発動後の約定条件、または場末返済|最初に有効になった出口により所有1枚を返済する。未決済で同じ返済を重ねない。|
|固定利確・固定損切で返済済み|決済時刻より後|口座を開放し、その時点以降に成立する新規を待つ。|
|利益保護で返済済み|元の建値・元の売買方向の清算側で `m ≥ R` または `m ≤ −R` を初めて確認|到達時刻を記録し、その時刻より後の新しい判断から再開する。到達秒の別原行でも新規を受けない。場末が先に来ればその日は終了する。|

休止中は建玉0枚。休止の長さを実保有時間に加えず、元価格まで保有していた場合の損益・手数料も計上しない。未知の決済で口座を空けず、元価格の経路が欠測で確定できなくなったときも研究では場末まで再開を保留する。[再開規則Cと比較した4規則](../../../study/00224_利益保護後の再エントリーをシグナルで待つ/比較方針.md)・[予約と再開の再生コード](../../../study/00224_利益保護後の再エントリーをシグナルで待つ/再エントリーを再生する.py)

## 固定利確・損切と二つの追尾

売買方向を `s = +1`（買い）または `−1`（売り）、建値を `e`、現在の清算側気配を `p` とする。順行幅 `m = s × (p − e)` を指数ポイントで追う。片幅 `R` は入口から受け取る150・200・350・400ptのいずれかで、保有中は変えない。保有後の最大順行を `M`、既に保護した順行幅を `F` とする。取得時は `M = 0`、`F = −R`、広い追尾・狭い追尾とも未起動とする。

1. **固定利確と損切。** 取得より後の正常原行で `m ≥ R` なら利確、`m ≤ −R` なら損切。最初に条件を満たした原行の清算側気配で評価する。価格が飛べば決済幅はちょうど1Rにならない。
2. **広い追尾。** 固定価格未到達なら `M = max(M, m)` に更新する。`M ≥ 0.95R` で広い追尾を起動する。その後の床候補は `max(20, M − 0.80R)`。
3. **狭い追尾。** 保有後の直近の有効な主通知2個が連続して `−s`、最新の通知から90秒以内、その一つ前から180秒以内で、かつ `M ≥ 0.25R`、現在の `m ≥ 20` が同時に成立したら起動する。2個とも取得原行より後でなければならない。判定する行までに公表された通知はその行から使える。起動時の `m` で別の最大値 `N` を初期化し、以後は `N = max(N, m)`。狭い床候補は `max(20, N − 0.25R)`。古い順行高値をこの `N` に持ち込まない。通知の有効時間が切れても起動状態は決済まで維持する。
4. **床の更新・発動。** 起動している各床候補と前回の `F` の最大値を、新しい `F` にする。前の正常原行ですでにいずれかの追尾が起動済みで、今回の `m ≤ F` なら、今回の原行・時刻を発動として記録する。最初に床を置いた原行では発動させない。狭い追尾が広い追尾より先に起動することもある。
5. **返済。** 追尾による返済可能時刻は**床への接触時刻＋1秒**。そこから最初の正常気配で返済する。床を起動した時刻からの1秒ではない。待ち時間に価格が戻っても返済要求は残る。固定価格または場末の有効な返済原行が先に来ればそちらを使う。同じ原行で競合するときの研究上の優先順位は **固定利確・固定損切 → 場末返済 → 追尾返済**。これで建玉1件につき決済は1回となる。

[R02の原定義と原行順](../../../study/00223_保有期限なしの利益保護を順行幅と値動きで比較する/反対の入口シグナル/出口条件.py)・[固定注文を先に判定する研究コード](../../../study/00220_日経199デイの損切位置と利益の確定方法を比較する/主比較/出口条件.py)・[運転器の6条件式](../../../../SessionTradeExecuter/conf/rules/NK225_RC20.toml)

例えば買いで `R = 200pt`、反対通知なしの場合、清算側が建値から190pt上がると広い追尾が起動し、床は `max(20, 190 − 160) = 30pt` になる。その後30ptまで戻った原行で発動し、1秒後以降の最初の正常な買い気配が建値＋10ptなら、研究上の費用後収支は `10 × 100 − 1,077 = −77円`。20ptの最低床は発注判断に用いる水準であり、飛んだ後の約定損益は実際の気配で決まる。これは計算例である。

## 損益・欠測・運転器での約定

研究ではmini 1枚を1pt当たり100円、手数料片道38.5円、想定滑り片道5ptとする。建玉ごとの費用後損益は `s × (決済代用値 − 建値) × 100 − 1,077円`。1,077円の内訳は手数料往復77円と追加滑り往復10pt相当1,000円。新規を対当気配で取り返済も対当気配を使うため、スプレッドはすでに価格差に入っている。含み損益の両極値は取得原行から返済原行までの正常な清算側気配を対象に同じ往復費用を控除し、最初の到達時刻を残す。[損益・含み損益の研究実装](../../../study/00219_日経199デイの利益保護と出口条件を比較する/口座再生.py)

研究の原板評価は、価格時計または正常気配の観測が300秒を超えて途切れ、その前に決済を確定できなければ未知として打ち切る。場末返済窓内に正常気配がなかった場合や、板の記録が決済前に終わった場合も未確定を残す。未知は0円にせず、未知のある場の確定収支を空欄とする。[価格索引と打切りの保存済みソース](../../../study/00179_保有時間参加率と終了前決済で入口を広げる/再現資料/Source.zip)・[追加日の未知の表記](../../../study/00224_利益保護後の再エントリーをシグナルで待つ/追加日への適用.md)

運転器はラージの気配で出口を監視し、実建値にはminiの約定価格を使う。固定価格・追尾ともクライアント側で監視して成行返済を要求する。サーバーに利確指値と逆指値を常駐させる執行とは、通信中断・価格飛び・約定遅延時の挙動が異なる。15:29:01には原板の追加更新がなくても壁時計で返済処理を起動するが、実際の約定時刻・価格は注文照合で確定する。新規・返済は発注意図、受付、所有建玉IDと1枚の約定を区別して記録する。再起動時の履歴は指標準備に用い、過去注文を新規送信しない。研究上の滑り仮定を実約定の価格に重ねて控除しない。運転器のセッション損益CSVは手数料控除前なので、費用後の研究CSVとの比較では集計基準も合わせる。[運転仕様](../../../../SessionTradeExecuter/docs/RC20.md)・[注文照合と保護の実装](../../../../SessionTradeExecuter/internal/strategy/rc20.go)・[セッション損益CSVの定義](../../../../SessionTradeExecuter/docs/セッション損益.md)
