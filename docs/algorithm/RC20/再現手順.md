# RC20を原板から再現する

2026年11月23日に、日経ラージの45デイを原行順に再生し、固定したRC20の新規・返済が研究結果と一致することを確認した。入口通知から再生するテストと、**原板・確定足から入口通知そのものを作るテスト**の両方がある。以下の全期間照合は後者を使う。

## 1　必要なファイルを揃える

すべてのコマンドの開始位置は `FutureSignalResearch` のルート。次の3フォルダを同じ親に置く。45日の照合に使うGoは1.24以降で、確認環境はWindows amd64、Go 1.24.2。取引口座・WebSocket接続・GPU・研究用Python仮想環境はこの照合に必要ない。

|置き場所|使うもの|役割|
|---|---|---|
|本リポジトリの `outputs/00228_…/228_E0RC20_元の入口と出口/`|[建玉明細.csv](../../../outputs/00228_日別の損益偏りと入口出口の比較/228_E0RC20_元の入口と出口/建玉明細.csv)・[デイ.csv](../../../outputs/00228_日別の損益偏りと入口出口の比較/228_E0RC20_元の入口と出口/デイ.csv)|正解の建玉と日別合計。日付・方向を入力シグナルとしてエンジンに渡さず、再生結果の照合に使う。|
|隣の `JP_OSE_Data/future/NK225/YYYY-MM-DD_Day/`|各日の `book.jsonl.gz`、`candle_1min.csv`、`candle_5min.csv`|板の `CurrentPriceTime`、`Symbol`、`CurrentPrice`、`Buy1.Price`（Bid）、`Sell1.Price`（Ask）。分足の列は `time,open,high,low,close,volume,volume_complete,closed`。日付はデイCSVで特定する。|
|隣の `SessionTradeExecuter/`|[RC20の原板再生テスト](../../../../SessionTradeExecuter/internal/runner/rc20_market_replay_test.go)・[日経の前史読込](../../../../SessionTradeExecuter/internal/runner/rc_history.go)・[標準の出口6式](../../../../SessionTradeExecuter/conf/rules/NK225_RC20.toml)|RC20を含むソース版を使う。全期間テストは組込の標準条件を使う。運転端末で独自編集したTOMLを使う場合は、その設定との差を別途確認する。|

過去場の足は[同梱の初期化用データ](../../../../SessionTradeExecuter/internal/runner/rc_history_seed.json.gz)から各対象日の開始までに終了した同一限月分だけを選ぶ。収録末尾は11月20日ナイト、全体で90場・10,707本。最後のナイトは11月20日デイの判断には入らない。別実装では同じ範囲のラージの昼夜5分足を日付・立会順に処理する。[足と時計の定義](指標と観測時計.md)・[初期化用データの生成器](../../../../SessionTradeExecuter/internal/runner/testdata/前史を更新する.py)

## 2　全45デイを照合する

```powershell
$env:RC20_RESEARCH_ROOT = (Resolve-Path .).Path
$env:RC20_MARKET_ROOT = (Resolve-Path '../JP_OSE_Data/future/NK225').Path
Push-Location ../SessionTradeExecuter
try {
    go test ./internal/runner -run '^TestRC20MarketReplay$' -count=1 -v
    if ($LASTEXITCODE -ne 0) { throw 'RC20の45デイ照合に失敗' }
} finally {
    Pop-Location
}
```

`TestRC20MarketReplay/2026-…_Day` が45日分 `PASS` したことを確認する。研究パスを設定しない実行ではこのテストは `SKIP` する。原板の元ファイル先頭を1行目として、検証対象外の行にも行番号を割り当てる。同じ価格時刻を持つ別の行をまとめると、時計が同じでも取得・決済の原行がずれる。

|照合する単位|期待する結果|
|---|---|
|各建玉|判断日時、方向、取得原行・日時・価格、片幅R、返済原行・日時・価格、費用後円が対応する。余分・欠落・未返済があれば不一致。|
|各日|取得件数、利益合計、損失の絶対額合計、差引が日別CSVと一致する。45日参加、確定損益不明0件。|
|全期間|133建玉、91勝42敗。総利益2,067,993円、総損失1,061,234円、純額＋1,006,759円。34黒字日、11赤字日。|

**原行を追う例。** 10月14日11:26:02の買い判断は11:26:06に68,390で取得し、幅は400pt。狭い追尾による返済は14:19:14の68,420で、`(68,420 − 68,390) × 100 − 1,077 = 1,923円`。10月8日は買いが2件、静的損切−36,077円と場末決済−27,077円、合計−63,154円になる。前者だけが合っても、後者で保有を60分で打ち切る実装や、含み益を実現利益に足す実装は再現にならない。[2日の建玉をViewerで比較する方法](../../../study/00224_利益保護後の再エントリーをシグナルで待つ/Viewer/README.md)・[10月8日の2建玉](../../../study/00228_日別の損益偏りと十月八日の入口出口を検証する/十月八日/README.md)

## 3　ずれた箇所を特定する

1. **判断が異なる場合**は、限月、夜間からの5分足の継承、足の終了＋60秒の公開、初期値・欠測、同秒の原板順、反転保留中の優先順位を確認する。運転器のルートで `go test ./internal/rcsignal -run '^TestHistorical$' -count=1 -v` を実行すると、同梱資料の45デイについて、適格判断15,530行、主通知634件、補完候補2,743件が一致する。両方の候補が同じ判断行に並ぶことがあり、これらは約定件数とは別の分母である。[入口照合資料](../../../../SessionTradeExecuter/internal/rcsignal/testdata/README.md)
2. **判断は同じで取得や出口が異なる場合**は、予約の1秒待機・30秒失効、14:40の期限、売買側の気配、床接触後の返済待機、元価格到達後の再開時計を順に見る。運転器のルートで `go test ./internal/strategy -run '^TestRC20ResearchReplay$' -count=1 -v` を実行すると、同梱の10月8日・14日、計3建玉で出口を確認できる。[口座と出口](口座と出口.md)・[代表日と全日版の違い](../../../../SessionTradeExecuter/internal/strategy/testdata/rc20/README.md)
3. **価格と時刻は合うが円額が異なる場合**は、倍率100円/pt、片道手数料38.5円、片道滑り5pt、往復計1,077円を確認する。損失列は赤字取引の絶対額の合計。研究上の気配はラージ、運転器がDryRunで約定に使う気配はmini。実運転では自身の約定を使う。[運転器の仕様](../../../../SessionTradeExecuter/docs/RC20.md)

照合した版のSHA256を示す。PowerShellの `Get-FileHash -Algorithm SHA256` で調べられる。指紋は配布時のファイルバイトに対する値で、CSVの改行・BOMを変えた場合も変化する。

## 4　日付を追加する／別実装で検算する

既使用45日のテストは件数も固定した回帰試験である。新しいデイでは[試行228の追加日手順](../../../study/00228_日別の損益偏りと十月八日の入口出口を検証する/追加日/README.md)を使い、原板から199_02の入力を作り、同じ入口でRC20とX2をそれぞれ1枚口座で再生する。日付を指定し、既使用日を確かめるオプション `--既使用照合` は新しい日には外す。生成される `RC20_デイ.csv` がこの仕様の日別損益。0取引日も残し、欠測による未知を0円に置き換えない。

研究側のPython・NumPy経路を初めて使う場合は、[保存済みの生成器とGo部品の展開手順](../../../inputs/00213_日経型TOPIXの純入口/README.md)と[研究の入力再現手順](../../../study/00219_日経199デイの利益保護と出口条件を比較する/再現手順.md)を参照する。45デイの研究元帳と単純IFD対照を再生成する手順、候補別CSVの出力手順は[試行224の再現節](../../../study/00224_利益保護後の再エントリーをシグナルで待つ/README.md)にある。出力は新しい作業フォルダに置く。今回、既存の199_02入力をこの経路にも渡して11月20日を再計算し、3建玉・利益47,846円・損失16,077円・収支＋31,769円を照合した。
