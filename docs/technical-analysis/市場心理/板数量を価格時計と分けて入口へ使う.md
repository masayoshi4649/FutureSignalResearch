# 板数量を価格時計と分けて入口へ使う

確認日：2026-11-18。[既存の需給解説](需給と流動性.md)と[時間尺度の調査](指数差と注文圧力の時間尺度.md)を、実データへ接続するための調査。**数量は利用できるが、独立した板更新時刻と成行売買量は今回の原板から復元できない。** 価格の方向・構造・勢いを主軸に、数量が確認材料になるかを次の仮説として扱う。

今回新たに読み込んだのは、2026-11-16ナイト・11-17デイのNK225/TOPIX原板4ファイル、計771,789行と、保存済みの純特徴だけ。金融結果・先着ラベル・将来方向はこの棚卸しへ入力していない。既存の194/195等の売買条件へ後付けしていない。[実行コードと集計](../../../scripts/板数量と時計の棚卸し/README.md)。

## 1. 何があるか、何がないか

|材料|今回の確認|使える意味・限界|
|---|---|---|
|`Buy1..10` / `Sell1..10` の `Price`・`Qty`|全4ファイルに存在。夜は全行で20段とも正値、昼は各商品3行だけ20段が零、その他は正値|見えている価格別気配量。約定量・取消量・注文者の意図ではない|
|`Buy1` / `Sell1`|最良買い／売りとして既存研究と同じ対応|正常な `Buy1.Price < Sell1.Price` を別に確認。量が正でも板寄せや不正常BBOは正常扱いにしない|
|トップレベル `AskPrice/Qty` / `BidPrice/Qty`|それぞれ買い／売り。Buy1/Sell1と全行同値ではない|名称を通常の英語の意味で読むと逆になる。同じ計算の途中でトップレベルと段内の値を混在させない|
|`TradingVolume` とその時計|累積売買高と `TradingVolumeTime` がある|累積差分は板数量変化とは別物。買い成行／売り成行への分解はない|
|成行数量、OVER/UNDER|今回の全原行に該当フィールドなし|零という意味ではなく、未取得。成行吸収量や全深度へ補完しない|
|時計|現値、累積量、始値、高値、安値、前日終値の時計|現値時計は板更新時刻ではない。過去の高安時刻等も受信時刻の代用にならない|
|受信・保存・段別時刻|全行が外包みなしの板JSON。段内キーはPrice/Qty/Signだけ。同じ4フォルダには原板と1/5分足CSVだけ|行別の独立した受信時刻や時刻サイドカーは確認できない。ファイル更新時刻も各行の受信時刻にはならない|

公式PUSH仕様も、先物の`BidTime/AskTime`、`Buy1/Sell1.Time`、`MarketOrderBuyQty/MarketOrderSellQty`、OVER/UNDERを配信対象としていない。これは今回の観測と整合する。[公式PUSH仕様](https://kabucom.github.io/kabusapi/ptal/push.html)。名称の逆転は[運営者による説明](https://github.com/kabucom/kabusapi/issues/1004)でも確認できる。

公式FAQはPUSHの間引き間隔を400msと説明している。しかし、この原板の各物理行が取引所の全注文イベントを保存しているとは証明されない。行数を取引件数や全注文数へ読み替えず、400msを掛けて各行の受信時刻を作ることもしない。[公式FAQ](https://kabucom.github.io/kabusapi/ptal/faq.html)。

## 2. 同じ現値時計でも板は変わっている

最良気配だけが不変でも、二段以深の変化がNK夜45,870対・昼20,578対、TOPIX夜23,713対・昼15,014対あった。最良価格・累積量等を持つ既存8列索引やNK48byte索引には20段の数量がなく、数量だけの更新をそこから復元できない。必要な特徴を原板から一度生成する。

今回の追加2場に限ると、十段変化の大部分が同じ有効な現値時計を持つ隣接行にある。分母は各原板ファイルの十段が変化した隣接対の全件、分子はそのうち現値時計が欠測でなく同値の対。両方の時計がnullの対は分子へ含めない。

|商品・場|十段変化の隣接対|同じ有効な現値時計の対|割合|
|---|---:|---:|---:|
|NK225 11/16夜|242,878|239,061|98.43%|
|NK225 11/17昼|168,605|163,896|97.21%|
|TOPIX 11/16夜|182,888|179,035|97.89%|
|TOPIX 11/17昼|136,625|131,443|96.21%|

**この観測は「板が同時に動いた」ことを意味しない。** 現値時計が更新される前に複数の板スナップショットが保存されている。同じ`TradingVolumeTime`のまま累積量が変わる行もある。保存された時計の粒度・更新仕様と実際のイベント発生時刻を区別する。

`Current.SourceIndex`は特徴更新の連番、`SourceLine`は物理原行、`AvailableAt`は再生系の論理公表時刻であり、相互に代用できない。旧E08の`Band.Line`は特徴連番なので物理原行ではない。[旧読取設計](../../../scripts/FAR5分枠の技法判定の監査/読取設計.json)、[旧監査説明](../../../scripts/FAR5分枠の技法判定の監査/README.md)。

## 3. 旧数量式は計算できるが、既知率が違う

判断時点の原行までを順に読み、旧式を変更せず適用した。単純な板不均衡は `QI_k = (買い上位k段合計−売り上位k段合計)/(両側上位k段合計)`。k=1/3/10の既知件数は今回同じだった。

|商品・場|純q0数|正常BBOでQI既知|旧OFI30既知|旧E08量既知|
|---|---:|---:|---:|---:|
|NK225 11/16夜|661|654|181（27.38%）|589（89.11%）|
|NK225 11/17昼|353|352|259（73.37%）|347（98.30%）|
|TOPIX 11/16夜|527|527|168（31.88%）|505（95.83%）|
|TOPIX 11/17昼|380|380|306（80.53%）|368（96.84%）|

旧OFI30は、正規化した隣接最良板差分の平均を現値時計上の30秒窓で計算する。隣接価格時計差が15秒を超える等で未知になる。E08は8回の最良価格変化と現値時計差60秒以内を基準に、同価格での補充／減少を平均する。**双方とも独立した実時間窓を確認した値ではない。** 旧条件を維持したときの可用性がこの表であり、未知を零や反対側支持へ変換しない。

NKとTOPIXでは純q0を生む足形成・履歴条件が違うため、件数や既知率の差をそのまま市場流動性の差としない。今回の数量自体の欠測は少なく、旧OFIの未知の主因には時計ギャップや窓の品質条件も含まれる。TOPIXの純特徴`close`は公表済み足終値で、q0原行Lastと異なるものが夜323/527、昼213/380件ある。数量を足終値の時点へ遡って結合せず、公表されたq0原行へ結ぶ。

## 4. 外部研究が裏付ける範囲

Cont・Kukanov・Stoikovは米国株50銘柄について、最良板の注文フロー不均衡と**同じ区間の**価格変化を調査した。基本は10秒、頑健性は10回の気配更新から10分までで、深さが大きいほど同じ不均衡の価格影響が小さい関係を報告している。取消と約定による同じ側の数量減少は、OFIでは同方向の寄与となる。これは同区間の価格影響の説明であり、翌60分の順行率の証明ではない。[著者原稿・2011版](https://arxiv.org/pdf/1011.6402)。旧OFI30の正規化平均は、この論文の未正規化合計と区別する。

Gould・BonartはNasdaq10銘柄で、最良両側の数量不均衡から**次のミッド価格変化1回**の方向を予測し、呼値の相対的に大きい株と小さい株で予測力が異なることを示した。長い時間先や深い板の情報は追加研究の課題としており、本研究の幅広IFDや費用後成績へ直接拡大できない。[著者原稿](https://arxiv.org/pdf/1512.03492)。NK/TOPIXの違いを調べる際も指数の性格だけでなく、呼値・スプレッド・表示深度・更新の仕方を揃える必要がある。

以下は未実装・未評価の候補。旧式を黙って変更せず、原行順を守る新特徴として別名を付ける。

|観測単位|定義案|必要な付帯情報|
|---|---|---|
|直近N回のL1更新|BBOまたは最良数量が変化した原行だけを1更新とし、N=32/128等の正規化差分平均・同方向比率を計算。同値行を回数へ増やさない|開始/終了の物理行、実際の更新数、価格時計の進行幅、時計欠測/後退、正常板連続性。N回はN秒ではない|
|Last時計で区切った完了ブロック|原順上で次の大きい有効Last時計を初めて観測した時、直前の同時計ブロックを完了させる。q0原行以前に完了したブロックだけで数量差と価格応答を集計|Last時計ラベルの開始/終了と、完了を知った原行。窓内の実時間滞在や受信遅延は未知と明記。後退・欠測を含むブロックは別扱い|

|固定水準での応答|過去だけで固定した抵抗/支持の周辺で、数量の増減と通過/不通過、突破後の板の再配置を記録|固定水準の出生原行、量の観測窓、確認原行、実BBO取得位置。固定前のデータへ水準を遡及しない|

共通出力は`symbol/session/contract/q0_line/q0_price_time/feature_start_line/feature_end_line/known/reason/value`を基本とし、金融ラベルを含めない。最後の原行をq0以下に制限する。価格時計でソートして同時刻をまとめ直す処理は禁止する。通常の時間窓、更新回数窓、欠測の扱いを比較できるよう別特徴を残す。

## 6. 継続と吸収を分ける仮説

経済的な説明は、注文の追加・取消・執行が、その価格で取引できる量と価格の進み方を変えるというもの。心理の説明は、追随する参加者が継続している、上値で売りたい参加者が供給を追加している、反対側が注文を撤退させている、といった仮説である。原板だけでは主体や注文目的を確定できない。

|場面|複合確認の案|反例・識別したいもの|
|---|---|---|
|強い方向への継続|5/15/30分の方向・DI/ADX・ERと、複数の更新窓で続く数量支持、固定水準通過後の維持を組み合わせる|1回の大きな表示注文だけ、両側が薄くなった一時的な跳躍、価格と同時に動いただけのOFI|
|強い方向の進行停止|元方向への進行が止まり、固定価格で反対側数量が繰り返し増えることを、元圧力の失速とともに記録する|増加は取消後の再掲や表示位置の移動でも起きる。「吸収確定」と命名しない|
|反転への切替|上記の進行停止に加え、元水準の反対側への構造回復、反対方向の板変化の持続を確認する|厚い壁だけを理由に逆張りしない。実際には壁が消えて順行再開する場合を同じ条件で数える|
|待機|価格方向と板の応答が不整合、時計/量が未知、スプレッド異常|データ品質による待機と、市場局面による待機を別記する|

最初は数量を必須にして全件を削るだけの案ではなく、既存技術条件のみ・数量確認追加・数量による状態分岐を同じ入口母集団で対照にする。売買は符号反転で対称にする。参加率を落とすためのフィルタや、少数の成功例へ都合よく合わせる条件にしない。これらが単純IFDの損失頻度・深さ・連続性を改善するかは、Sourceと条件を固定した別試行で初めて評価する。
