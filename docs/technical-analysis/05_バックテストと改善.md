## 1. 何を確かめるのか

テクニカル指標が将来の値動きと関係すること、取引費用後に利益が残ること、実際に発注できることは、それぞれ別の検証である。まず分析条件に続く値動きを調べ、次に決済・数量・費用を加え、最後に執行制約を加える。各段階の結果を同じ「利益」と呼ばない。

Lo・Mamaysky・Wangはチャート形状を機械的に識別する研究を行い、米国株の日足の一部指標に追加的な情報を見いだした。この結果からNK225・TOPIXの短期売買の費用後収益を導くことはできない。本研究では、目視上の形を再現可能な定義にするという考え方を参考にする。[著者公開論文](https://www.mit.edu/~wangj/pap/LoMamayskyWang00.pdf)

最初に「どの市場状態で、何を観測すると、どの期間の動きが変わると考えるか」を一文にする。反証となる結果も先に書く。例は「平均線が上向きのときの上抜けは、同じ時間帯の単純な買いより費用後平均損益が高い」である。

## 2. データを研究用に理解する

[データと閲覧形式](../データと閲覧形式.md)に実ファイルで確認した事項をまとめている。次の順で確認する。

1. 銘柄・限月・セッション・実際の観測範囲を調べる。ファイル名だけで取引日や限月を決めない。
2. 時刻の意味、同時刻行の順序、時刻後退、価格・気配・出来高の欠損を調べる。
3. Lastが実際に変化した行と、板だけの更新を区別する。同じ最終約定情報を何度も約定として数えない。
4. 既存1分・5分足と原板から作る足を少数セッションで突き合わせる。足の境界、終端、観測価格、出来高定義の差を説明する。
5. 未確認の条件を、仮定・除外・不明として明示する。

現在の標本では `CurrentPriceTime` が板の受信時計とは確認できていない。最終約定時刻が同じ複数行を、精密な受信間隔を持つ板イベントとして使わない。同時計では物理行順を保持しても、本当の経過時間や注文遅延までは復元できない。時刻の精度に合わない高速戦略は評価対象外にするか、観測順だけによる限定的な試算と明記する。

欠損を後の価格で埋めることは先読みになる。気配が不正なら実行可能価格も不明とする。データが悪いセッションを、損失だったという理由で除外しない。品質基準は損益を見る前に定め、除外数と理由を残す。

## 3. 確定足と発注の時間関係

例えば `[09:00,09:05)` の5分足は、09:05以前には最終高値・安値・終値が分からない。この足のシグナルは足確定を確認してから使う。足の開始時刻09:00で売買した扱いにせず、確定後に利用可能な最初の観測と仮定した遅延から発注を判定する。

上位足でも同様で、09:07時点に `[09:00,09:15)` の15分足の確定値を使わない。指標のウォームアップに前セッションを使うことと、建玉を持ち越すことは別である。前セッションを使う場合も未来情報は入れず、休場時間を架空の足で埋めない。

期間不足の値は未定義とし、ゼロ埋めで交差を発生させない。取引対象の最初の足から売買したい場合は、必要な過去の足を明示して準備する。セッションごとに指標を初期化する方式も比較対象になるが、再初期化の影響を売買の優位性と混同しない。

## 4. 約定モデルを段階的に厳しくする

| 段階 | 内容 | この段階で言えること |
| --- | --- | --- |
| 価格だけ | 次の観測価格等で仮想売買、倍率と費用を適用 | シグナルと出口の概算比較。板での約定を証明しない |
| ラージ気配 | 買いはAsk、売りはBid、気配不明は不明。遅延・数量の制約を追加 | ラージ市場による執行近似 |
| 別商品への移用 | ラージの条件でmini/microを想定。商品別刻み・費用と価格差のシナリオを追加 | 実行商品の板がなければ近似のまま |
| 商品別の再生 | 実行商品の板・約定・観測時計を用いる | そのデータの範囲で執行を検討できる |
| 模擬運用 | 実時間の配信と注文受付・約定照会を確認 | 実運用との差と障害時動作を調べられる |

成行相当の買いをBidで、売りをAskで成立させない。複数枚が最良気配の数量を超えるなら、観測できる奥の板まで消費するか、超過分を未約定にする。自分の注文による価格変化は過去板から直接は分からず、規模が増えるほど近似の限界が大きい。

指値は「ローソク足が触れた」だけで約定にしない。同値の待ち行列、取消、部分約定があり、板スナップショットだけでは自分の順位を一意に復元できない。待ち行列を仮定した結果と、価格が不利側へ通過して初めて約定させる保守的な結果などを比較する。どのモデルも観測事実そのものではない。[JPX「取引方法」](https://www.jpx.co.jp/derivatives/rules/trading-methods/index.html)

1本の足の中で利確値と損切り値の両方に届いても、その足のOHLCだけでは先後が分からない。原板順で判定できない場合は保守的な順序を主結果にし、他方も感度分析として残す。利益側だけを常に先にしない。

逆指値も条件価格で必ず成立させず、発動が観測された後の利用可能な気配で評価する。ラージの値動きによる発動と、mini/microの実際の注文監視条件は別設定である。[決済とリスク管理](04_決済とリスク管理.md)

## 5. 損益の単位を統一する

買い新規価格 `e`、返済価格 `x`、枚数 `q`、円価値 `M`、対応する新規・返済の実費合計 `f` とする。

```text
買いの確定純損益 = (x − e) × q × M − f
売りの確定純損益 = (e − x) × q × M − f
```

分割約定・部分返済は建玉IDに結びつける。新規の加重平均価格、各返済数量、各片の費用を管理し、同じ費用を二度控除しない。実約定価格に含まれるスプレッドや不利約定を、費用としてさらに二重控除しない。モデル価格で不利約定を表す方式か、独立した追加費用で表す方式かを明記する。

含み損益は、買い玉をBid、売り玉をAskで評価すると、直ちに反対売買する方向を反映できる。ただしラージ気配でのmini/micro評価は代替評価に留まる。欠測は `null` 相当とし、保有中の損益をゼロにしない。

## 6. 最低限残す評価値

| 指標 | 定義・用途 | 注意点 |
| --- | --- | --- |
| 純損益 | 全返済の値幅損益から費用を控除 | 手数料前・後、ラージ近似・実行商品を分ける |
| 取引数・参加セッション数 | 完結した建玉単位等、集計単位を固定 | 部分約定片数を取引数にしない。無取引場も含める |
| 勝率 | 純利益の取引数 / 完結取引数 | 引分も分母に含むかを固定。勝率だけで採否を決めない |
| 平均損益 | 純損益合計 / 完結取引数 | 取引数ゼロなら未定義 |
| 平均利益・平均損失 | 利益取引と損失取引の平均 | 該当取引がなければ未定義 |
| プロフィットファクター | 正の純損益合計 / 負の純損益の絶対合計 | 損失なしなら有限値を捏造せず、未定義または無限大と件数を併記 |
| 最大ドローダウン | 資産推移の過去最高値からの最大下落額 | 確定だけか含み込みか、評価間隔と欠測範囲を明記 |
| 最大連敗・最悪場 | 損失の連続数と最悪セッション純損益 | 中断・未完了場を消して見栄えを改善しない |
| 保有時間・回転数 | 平均・上位分位・時間帯別の取引頻度 | 高回転ほど費用と時計精度の影響が増える |
| 期限返済・未解消建玉 | 期限決済件数、終了時残数量、判定不能数 | 持ち越しなし要件の直接検証 |

試行全体の開始を0として、累積した確定の値幅損益に現在の費用前含み損益を加え、**未決済建玉の新規費用も含む全支払済費用を一度だけ控除**した値を `X_t` とする。円建てのドローダウンは `max_(u≤t)(X_u) − X_t`、全期間の最大値が試行全体の最大ドローダウンとなる。初期点 `X_0 = 0` も含め、セッション境界で累積値をリセットしない。セッション開始から独立して測るセッション内ドローダウンは別指標として残す。将来の返済費用を差し引く場合は、その引当方法も固定する。既に純額で記帳した費用を再び引かない。

収益率やSharpe比率を使うなら、分母となる資金・期間・無リスク利子・年率化を定義する。証拠金額を恣意的に小さくして収益率を大きく見せない。デイとナイトの長さが違うため、単純にセッション数の平方根を掛けるだけの年率化は根拠を記す。最初の比較では円建て損益とセッション別分布を優先する。

## 7. MFE・MAEで出口を診断する

MFEは保有中の最大順行、MAEは最大逆行を表す。本研究の簡単な定義候補は、買いでは `g_t = (Bid_t − e) × q × M`、売りでは `g_t = (e − Ask_t) × q × M` を観測し、`MFE = max(0, max(g_t))`、`MAE = max(0, −min(g_t))` とする。ここでは費用前、数量固定の単一建玉で説明している。部分返済・増玉がある場合は、初期数量換算と実際の残数量のどちらで測るかを分ける。

MFEに対して実現利益が小さいなら、戻りを待ちすぎた可能性がある。MAEが大きいなら入口が早い、相場状態の判定が弱い可能性がある。ただし、後から全取引の最良地点を選んで返済した損益は実現可能な手法ではない。

改善は例えば「中心線到達で一部返済する」「確定足の安値更新で保護価格を上げる」のように、当時分かる情報だけの規則へ戻す。MFE・MAEの分布から候補を作った標本は開発用となり、別の未使用期間で評価する。

## 8. 時系列の分割と過剰適合

セッションを時間順に並べ、開発・選択用の期間と、最後に一度だけ評価する未使用期間を先に固定する。直後の値動きが重なる足をランダムに分けない。NK225とTOPIX、同じ取引日のデイとナイトにも共通要因があるため、銘柄や場を分けただけで独立した証拠とは言えない。

ウォークフォワードでは過去の区間だけで候補を選び、続く区間を評価し、時点を前へ進める。境界をまたぐ評価対象は排除するか、対象期間が重ならない間隔を設ける。計算窓のための過去データは利用できても、未来の目的変数や将来確定の相場分類を混ぜない。

Baileyらは、複数の設定から最良のバックテストを選ぶ行為と過剰適合を扱っている。候補を多数試すほど、偶然良かったものを選ぶ問題が大きくなるため、本研究では失敗候補・試した期間・探索数も保存する。未使用期間を見て調整した後、その期間を再び未使用と呼ばない。[著者公開論文](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)

現在の保存期間が短ければ、細かく分割するほど各区間のセッション数が不足する。最初はデータ品質・会計・実装の確認を主目的にし、長期の収益性を結論づけない。独立性を仮定する誤差評価を全ティックに適用せず、日付や連続セッションの塊で再標本化する方法などを検討する。信頼区間も相場変化への保証ではない。

## 9. 改善を一つずつ検証する

比較例は次の通り。具体的な値は試行前に決め、後から主結果に都合よく変更しない。

| 比較 | 確かめたいこと |
| --- | --- |
| 無取引と、固定1枚の単純手法 | 複雑化する価値があるか |
| 入口のみ同じ、出口を変更 | 利確・損切りの改善による差か |
| フィルターなし / あり | MA・ADX・時間帯等の追加が機会損失以上に役立つか |
| 元のパラメータ / 近隣値 | ごく一点だけ良い結果になっていないか |
| 通常費用 / 費用増 / 不利約定増 | 薄い利益が費用で消えないか |
| 元の順序モデル / 保守的順序モデル | 同足・同時計の仮定に利益が依存していないか |
| NK225 / TOPIX、デイ / ナイト | どの条件で成立し、どこで崩れるか |

日付、時間帯、買い・売り、トレンド・レンジ、スプレッド、変動幅ごとに分解する。ただし、結果を見てから良かった小区分だけ採用する変更は追加の探索である。探索した全区分を記録する。

GPUを使って試行を増やしても、先読み・費用・データ不足は解決しない。まず少数セッションを逐次再生し、原板行から約定・建玉・損益まで追跡できる基準計算を作る。その後、独立した候補・日付の並列化を行い、同じ入力で基準計算と一致することを確認する。順序に依存する注文状態を無造作に並列計算しない。

## 10. 採否の記録

試行ごとに、仮説、開発期間、未使用期間、実際の探索数、約定モデル、費用、主評価値、品質上の除外、持ち越しの検査結果を残す。「採用」「棄却」「保留」は理由を添える。未確認の実行商品価格や観測時計の問題が主結果を左右するなら、利益の大小だけで採用しない。
