# 研究の進め方と保存方針

作成日 2026-10-30。更新日 2026-11-23。

## 1. 役割と前提

本リポジトリでは、NK225先物・TOPIX先物のラージの価格・板を観測して、チャート分析と自動発注の仮説を検証する。将来の構成は、サーバーからWebSocketを受信し、足と指標を更新し、売買を判断し、注文と建玉を管理するもの。mini・microへの移用は商品別の執行条件を区別する。

保有期間はデイ08:45〜15:45、ナイト17:00〜翌06:00のそれぞれ1セッション内。取引所のザラバと板寄せを区別し、終了後は建玉と未約定注文を残さない設計を研究する。実行済みの検証と進行状況は[試行一覧](../study/README.md)を参照する。

即時約定代用では、NK225のザラバ終了15:40/05:55と、その後の引板寄せ注文受付を分ける。正常な最良気配だけでセッション末尾まで清算可能としない。区間修正で未知となった金額は0円や回避利益へ置換せず、旧固定結果と区別する。[データと執行時刻の限界](データと閲覧形式.md)（2026-11-11追記）。

| 場所 | 保存するもの |
| --- | --- |
| `docs/` | 教科書、複数試行で再利用する知見、データ仕様、出典、目次 |
| `docs/議論/` | 組み合わせの候補、変更理由、結果から生まれた問い。条件・結果の正本は各試行へリンク |
| `docs/研究知見/` | 複数の試行から分かったこと、成り立つ範囲、反例、比較の分母。[テーマ別の目次](研究知見/README.md) |
| `docs/algorithm/` | 固定した手法ごとの入力、特徴、状態遷移、費用、照合手順と結果。[仕様の一覧](algorithm/README.md) |
| `study/` | 5桁番号付きの試行ごとの仮説・結果・再現条件・Viewer互換資料 |
| `inputs/`・`outputs/` | 恒久保存する生成入力の指紋と由来、手法・費用条件別に分けた損益CSV |
| `scripts/` | 用途別の再利用する検証コード。各試行へ版・依存・実行方法を記録 |
| `work/` | AIが自由に使用する一時作業、展開、キャッシュ、生成途中のファイル。Git管理外 |
| `../JP_OSE_Data/` | 共用の過去データ。各試行に複製せず参照する |
| `../SessionTradeViewer/` | 価格・建玉・損益を確認する既存アプリ。形式は実装と仕様を参照する |

`work/` はどれだけ汚してもよい作業領域とする。研究を再現するために必要な唯一のコード・入力条件・結果を、ここにしか置かない状態では試行完了としない。一時物を整理する時期は任意でよい。

## 2. 試行番号

試行フォルダは `study/00001_要約/` の形式とする。番号は既存最大値の次を使用し、同じ番号を再利用しない。要約は何を比較する試行か分かる短い日本語とする。例：`study/00001_MACD交差と方向条件の比較/`。

一つのフォルダに、先に定めた候補比較やパラメータ探索をまとめてよい。その場合、採用候補だけでなく全候補の数・設定・結果を小さな表で残す。結果を見た後に仮説や主な入口・出口を変更する場合は、新しい番号へ送る。元の記録は残し、変更の理由を相互リンクする。

教科書作成は実データの試行に数えない。採番済みの試行は[試行一覧](../study/README.md)で確認する。

## 3. 試行の最小構成

```text
study/
  00001_要約/
    README.md                 仮説、条件、結果、限界、次の問い
    設定と結果.md             汎用表のコピー、使用セル、設定IDと複合評価の明細
    条件.json                 パラメータ、入力参照、版、費用、期間分割
    集計.csv                  セッション別・候補別の小さな集計
    一覧.resources.json       Viewerの資源一覧
    約定.trades.jsonl          原則として約定片だけ
    判断.jsonl                必要な場合だけ、理由・判断時刻・原板行
    再現用コード等             共有実装への参照で足りなければ保存
```

ファイル名のうち、Viewerの形式を識別する `.resources.json` と約定内容は[データと閲覧形式](データと閲覧形式.md)に従う。`条件.json`・`集計.csv`・`判断.jsonl` は本研究用であり、Viewerが直接読み込む仕様とはみなさない。複合条件の共通検証処理は[scripts/複合検証](../scripts/複合検証/README.md)を参照する。

試行の開始時に[現行の汎用表・版8](議論/手法と時間スケールの汎用表_版8.md)を `設定と結果.md` へコピーする。使用セルには `S01（短い閾値）／R01` のように設定と複合評価を参照させ、下段に式・役割・入力・閾値・結果・限界を記す。未使用・未検証・データ不足・対象外を区別し、カタログ版と元の条件・集計へ戻れるようにする。旧試行で固定した版と設定表は保持する。[記録方針](議論/手法と時間スケールの記録方針.md)

原板・逐次と時間足、指標の本数・起算点を分ける。例えば5分ATRで決めた保護を気配ごとに監視する場合、計算は5分、監視は原板・逐次へ記録する。複合評価の成績を、使用した各指標が単独で得た成績とはしない。

原板、既存CSV、全ティック指標、毎ティック会計、大量の画像やHTMLレポートは標準成果物として重複保存しない。約定がなくてもREADMEと集計を残す。約定ファイルは空にできるが、評価したセッション自体を消さない。

注文要求・取消・拒否と、実際の約定は別の事実である。Viewer用の約定JSONLに未約定の要求を混ぜず、運用を研究する段階では必要な注文イベントを別に保存する。要約から原因を追跡できない取引は、理由と必要最小限の指標を記録する。

## 4. 再現に必要な情報

| 分類 | 記録事項 |
| --- | --- |
| 入力 | データルートからの相対パス、セッション、銘柄、限月、サイズ、内容のハッシュ、観測範囲 |
| 版 | 研究コード、データ、Viewerのコミット。未追跡・変更済み入力は内容でも識別 |
| 足と指標 | 価格系列、区間、確定時点、初期化、前セッションの利用、欠損処理、式とライブラリ版 |
| 手法 | 全条件、候補数、比較対象、数量、新規・返済・保護・期限の優先順位、設定ID・複合評価ID・カタログ版 |
| 執行 | 実行商品、倍率、呼値、気配方向、遅延・待ち行列・部分約定・同時計の仮定 |
| 費用 | 手数料の採用日と根拠、価格に含めた滑り、別費用との二重控除防止 |
| 評価 | 開発と未使用の期間、主指標、品質基準、除外、持ち越しの監査、判定不能 |
| 実行 | 実行日時、コマンド、依存関係、乱数種、CPU/GPUと精度差が関係する場合の条件 |

コミットだけで原板を特定できない場合がある。圧縮版と非圧縮版が別工程で更新されるため、採用した方を明示する。同じJSONLの論理内容を識別したい場合は、圧縮ファイル自体と展開後内容のハッシュを区別する。ハッシュ台帳を共用し、全試行で巨大ファイルを毎回複製・再計算しない。

## 5. 実施順序

新候補は複数のテクニカル手法を必ず組み合わせ、方向・持続・急変・変動幅等の役割を分ける。複数時間軸の一致/収束を現在までの値で判別し、順行・反転・待機を切り替える。売買は符号対称の同一閾値とし、利益追尾は手数料・想定滑り控除後の**現在含み益が正**になれば起動する。最低でも新規価格を守る設定を必須とし、起動費用の前提と現在の返済側価格を記録する。設定同値と、遅延・跳躍・費用後の実現同値は別に評価する。[判断の組み立て](議論/複数手法で局面を判別し利益を追尾する.md)

起動定義は2026-11-05のユーザー指定を[00033](../study/00033_CCI突破と足内終値位置/README.md)から反映した。過去の固定A5を現在仕様へ書き換えず、比較用の旧条件と分ける。33の起動参照費用は片道手数料11円・想定追加滑り5pt/倍率10円の往復122円であり、全商品・全試行の費用を固定する一般則ではない。費用感度ごとに起動も再選択する場合は別の運用条件として事前に指定する。

1. [教科書](technical-analysis/README.md)から一つの現象を選び、反証可能な仮説にする。
2. [試行記録テンプレート](試行記録テンプレート.md)へ条件・比較・期間の既使用状況・品質基準を記入し、汎用表を `設定と結果.md` へコピーする。
3. 原板の少数行から足・シグナル・約定・会計を追跡して、基準計算を確認する。
4. 条件を固定して全対象を計算し、セッションごとの純損益と未完了を残す。
5. Viewerで成功・損失・期限返済・欠損の代表例を確認する。必要な図だけ保存する。
6. 追加条件は比較対象を維持して評価する。未使用期間を見た後の修正は追加探索として扱う。
7. 試行結果を記録し、複数試行へ役立つ事実だけを `docs/` へ出典付きで移す。

特定の試行だけの経験則を、すぐ共通知見に昇格させない。「この条件・期間で確認」「反例あり」「未検証」を区別する。共通知見には元試行へのリンク、適用範囲、更新日を付ける。

評価は各方式で成立した取引の実現損益・費用・利益後赤字・DD・回数を中心とする。未参加や決済後の仮想利益を機会損失として評価・最適化しない。方式間の実現収支比較は続け、固定済みの旧試行は書き換えない。[実現損益を中心に評価する方針](議論/実現損益を中心に評価する方針.md)

## 6. 容量と計算資源

研究の標準はMarkdown、小さなJSON/CSV、約定中心のJSONLとする。他形式も必要性に応じて使える。容量の大きい中間生成物は `work/` に置き、再生成方法と必要な条件を残す。既存データを損失圧縮して置き換えない。

2026-11-09以降、損益の閲覧用出力はCSVに統一し、xlsxの新規生成・更新は行わない。文字コードはUTF-8 BOM付きとし、候補・費用条件ごとの全セッション、実現純損益とその累計、参加枠と分母を残す。無取引の場を省略しない。参加率は列名で百分率か比率かを区別する。CSVは保存済み検算結果から生成する閲覧資料であり、固定済み会計や条件を変更しない。

2026-11-04、00005の4,605候補をCSVから全件転記したMarkdown（1,484,208バイト）を削除し、全閾値・支持・学習/選択成績の正本CSVへのリンクに統一した。設定と結果の51×9表、仮説の解説、固定条件、正本数値、監査は保持する。不要な転記を再生成しないよう生成処理も更新する。

繰り返し利用する派生足や特徴量を共通キャッシュに置く場合は、元データ版・変換仕様・コード版から識別し、再生成可能とする。保存量に見合う計算短縮効果を確認してから恒久保存を判断する。

OSSの導入とGPUの利用は可能。導入時は名前・版・用途・必要なライセンス情報を記録する。使用した版とCPU/GPUの選択は各試行から参照できるようにし、将来の高速化でも先読みのない基準計算との一致を先に確かめる。

## 7. Gitからの試行資料の取得

2026-11-23、`study/` をGit管理の対象に含めた。`work/` とPythonの再生成可能なキャッシュは引き続き除外する。大量の資料は用途と容量で分割したコミットとして保存する。

次の2ファイルは、元のファイル名・内容を保ったままGit LFSで保存する。対象はルートの `.gitattributes` で個別指定し、他のZIPへ一律には適用しない。

- `study/00163_履歴を含む複合入口を任意幅と場末まで検証する/再現資料/出生と統計正本.zip`
- `study/00164_IFD最初到達の確定時計で入口と反転を比較する/再現資料/分類と比較正本.zip`

Git LFSを導入した環境でクローンし、リポジトリのルートで次を実行する。今回の保存環境はGit LFS 3.7.0。

```powershell
git lfs install --local
git lfs pull
git lfs fsck
```

Git LFSはGit内の参照情報にファイルのSHA-256とサイズを記録し、実体を別途取得する。GitHubからダウンロードしたソース一式のZIPに実体が入るかはリポジトリ設定によるため、再現時は上記の取得方法を使う。[GitHub公式説明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-git-large-file-storage)（確認日：2026-11-23）。
