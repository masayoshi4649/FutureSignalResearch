# 旧価格足と00017補助値の因果的な結合

作成日2026-11-04。読取による設計メモ。実装・新試行・損益計算は行っていない。

## 足終端と、公開判断時点を分ける

旧価格足は半開区間［start,end）のLastでOHLCを作る。次の異なる枠の**最初の旧価格cacheイベント**で前足にconfirm/confirm_line/publish=Trueを付ける。確認イベントはLast欠測やBBO不正でも、時計が次枠へ進めば確認に使われる。次枠イベントが来ない末尾足はconfirm=finish/confirm_line=0/publish=Falseであり、終了時計だけで発動させない。

| 補助特徴の定義 | 参照上限 | 意味 |
| --- | --- | --- |
| 足終端の観測状態 | now＜frame.end、かつ確認原行以下 | 半開区間末尾で最後に観測した状態。now=endの更新は次足側 |
| 公開判断時点の観測状態 | （now,line）≤（frame.confirm,frame.confirm_line）、かつ確認原行以下 | 足を知った時点の状態。確認行の更新を含み、前足OHLCには入らない次枠更新も含み得る |

例：09:00終了の足を09:00:03/原行120で確認したなら、足終端側は09:00未満、判断側は09:00:03/120まで。09:00:03/121の更新は判断に使わない。両者を同じ「足のVWAP」と呼ばず、使う定義を次試行で固定する。

## 原順の結合

1. 00008価格台帳と00017抽出台帳をsymbol/session/source_path/展開SHAで照合する。両cacheのlineは同じ原板物理行。00017のcontract/exchange番号は場ごとの対応表なので、contract_codes/exchange_valuesの実値へ解決する。番号0同士を同じ限月・市場と扱わない。
2. 補助cacheは保存原順で読み、有限時計の最大既知（now,line）より後退した行を除外する。**時計で先にソートしない。** 同時計は原行順を保つ。旧driverは場内（確認用終端等号を含む）で非後退を選別する一方、00017は接頭/終端を含む原順で最大キーを選別する。両者に採否差があれば補助を欠測とし、差を記録する。
3. 各公開足の確認キーまで補助ポインタを進める。原行の完全一致を要求しない。旧cacheと00017は異なる列で省略するため、確認行の直前から同じ補助状態が続く場合もある。repeatは全状態が物理連続した原行件数で、値を初めて知れるのは先頭line。末尾を待って利用可能にしたり、repeatを売買数量へ足したりしない。
4. 上限までの「最後の状態」を選び、その時点の妥当性を検査する。現在状態が欠測/不整合/未来数量時計なら、黙って古い正常値を検索し直さない。古い採用値を保持する方式なら、出典キー・古さ・現在不可理由を別保存し、別の固定条件とする。
5. 数量時計≤価格時計、内部整合、正値、identity/基準確認を当該行だけから判定する。未来数量時計の値を過去へ配り直さず、後の採用可能行からだけ使う。非公開価格足は補助値があっても発動不可。

価格足と確認キーは既存8列cacheから作る。00017はBBOを持たず、native/代金だけの更新は旧cacheにないこともあるので、00017で価格足・約定モデルを置き換えない。同一原行の補助更新は判断より先へ置き、既存の気配→確定足→要求順と合わせる。新規は要求から1価格時計秒以上後の最初の正常BBOで、VWAP自体を約定価格にしない。

## 起算・履歴・リセット

- **場開始**：補助ポインタ・手法の足履歴・待機設定を初期化。native数値を0へ再基準化しない。前夜起算の配信値と、既知接頭基準を引くDay差分は別名とする。後者は00017で確認できた23Dayだけが候補、他はunknown。
- **累積区間変更**：限月・Exchange/ExchangeName・始値時計/価格・区間番号を保持する。採用量/代金減少、数量時計後退、既知identity不一致で差分基準を永久破棄。同値へ戻っても復活させない。nativeの新起算値を読むことと、旧区間の傾き/交差/待機を橋渡しすることは別。
- **一時identity欠測**：不変の基準候補は内部保持するが当該行の差分参照は不可。同一identityを当時再確認できた以後の行だけ再開し、過去へ補完しない。保守案は補助未確認足で手法の連続履歴/待機を切り、基準候補の保持と分ける。
- **価格欠枠/非公開**：既存の指標・入口リセットを維持し、補助の連続性から価格足を捏造しない。価格EMA等の同限月場間持続と、VWAP手法の同場監視は別管理する。

00017の基準は、閉場後の既知整合接頭または同一identityを確認できる直接零だけ。不明な初期量/代金を0で補わない。末尾から分かる「この場は基準が使えた」というフラグで、過去の一時欠測行を許可しない。

各価格足へ、end/confirm/confirm_line、補助定義、参照元now/line/repeat、native/数量/代金/数量時計、解決済みidentity/区間、内部整合/時計条件/基準/差分可否と不可理由を保存する。両定義を保存するなら双方の出典キーも付ける。

最低限の合成：確認行と同時計次行の区別、native/代金だけ更新、後退時計を並べ替えて救わないこと、repeat中の参照、接頭不整合/先行数量時計/identity欠測と永久破棄、session/限月/欠枠/非公開での手法状態リセット。

価格時計はCurrentPriceTimeで受信時計ではなく、VWAP/代金の固有時計もない。この結合は保存観測モデル内の因果順であり、現実の受信・同時生成・全約定復元を保証しない。

`repeat`は抽出後に分かる連続同一状態の最終的な保存範囲であり、先頭の値を知った時点では将来何行続くか分からない。値そのものを先頭原行から利用することと、repeat全長を当時の予測特徴へ入れることは別である。00018ではrepeatを出典追跡に記録するだけで、位置・傾き・準備・注文・先着には使わない。将来の学習入力へ出典dict全体を渡さず、当時観測できる列を明示的に選ぶ。必要なら判断原行までの既知反復数を別列として定義する。
