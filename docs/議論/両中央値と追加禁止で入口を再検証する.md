# 両中央値と追加禁止で入口を再検証する

2026-11-15。ユーザーの最終条件は、費用控除後の「セッション別収支中央値」と「建玉ごとの収支中央値」の両方が黒字、保有中は追加建玉不可、取引のないセッションを可能な限りなくす（合理的理由は例外）、である。セッション別だけとした途中回答は撤回されている。

[173](../../study/00173_追加建てを禁止し両中央値で入口を再探索する/README.md)で新たに検証する。171/172の固定条件・当時判断・CSVは変更しない。173ではデイも入口の再探索対象とし、旧デイ固定は対照として保持する。

- 保有は買売合計mini1枚まで。反対側の新規や両建ても禁止し、未決予約中の重複要求も防ぐ。既知決済又は注文失効後の次q0から再判断する。
- 建玉中央値にはIFD先着と未到達の期限決済をともに含め、手数料・想定滑りを控除する。
- セッション中央値は全対象DayとNightで別々に算出。0取引場は0円のまま分母へ残す。PRE/POSTは同じNight内の診断区分であり、小帯ごとの取引や中央値黒字を強制しない。
- 観測不足を0円決済として中央値へ混ぜない。既知部分、未知件数、全件中央値の符号の確定可否を分ける。
- 各Day/Nightで最低1取得を目指し、未参加理由を指標未公表・価格品質・条件不成立・未決取消等へ分ける。無条件の定刻発注で件数を作らず、別の複合技術で合理的に補完できるかを調べる。

前提になった固定デイ診断では、既知収支の75.27%が利益上位5日に集中し、主341取得中302件が同側保有中の追加だった。主0の14Dayのうち9場は主順行の必要15分指標が終日未公表で、全てを相場選別の結果とは呼べない。これらは旧実現取引の分解であり、追加を禁止した新口座経路の成績ではない。173で初めから数量・決済時計・後続要求を再生し直す。

純候補の独立一枚screenだけで採否を決めない。三帯それぞれのglobal1再生と、PRE/POSTを接合したNight全体の再生を行い、両中央値・同幅先着・参加・頻度・日集中・未知を同時に確認する。旧73と追加7は既使用であり、新しい未見性能とは称さない。

## 173から174で確認したこと

2026-11-16。[173](../../study/00173_追加建てを禁止し両中央値で入口を再探索する/README.md)の固定参考4案は、買売合計保有＋予約一枠で全80場取得・Day/Night両中央値下限が正。ただしDay/Night双方70%以上は得られなかった。主だけの高率に対し初参加補完が赤字になる例、共同適合Night8案が次段の個別順位で全滅する例が分かった。

[174](../../study/00174_共同条件を残して単一建玉の入口を広げる/README.md)ではDayの候補層を拡張し、共同適合枠を予約、Day補完開始も45/90/120/180分で比較。全期主は全80のDay71.43%・Night68.18%、全80参加・両中央値正になった。両区分70%や追加期の安定性を達成したとはしない。追加Nightは20%・赤字で、前半だけの選択も後半に悪化した。

全場参加は定刻の無条件注文で作らず、主又は複合技術補完の実取得で数える。全場参加・建玉中央値・場中央値・先着率・頻度・期間差を同じ合否へ潰さない。資料は[最新CSV案内](../../outputs/00174_追加禁止と両中央値の比較/README.md)を優先し、173/171/172の固定結果を改変しない。
