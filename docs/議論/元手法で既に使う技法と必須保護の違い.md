# 元手法で既に使う技法と必須保護の違い

確認日：2026-11-10。対象は[FAR166の固定版](https://github.com/masayoshi4649/FutureAlgorithmResearch/tree/cf0717daa1eed78759f78a428bce50129e7f705b/work/research166)から選んだD164_15/P164_06/U165_03と、Source111が再用する純戦略43項目。以下は固定コードの到達経路を調べた事実であり、112の実損益や指標単独の優位性を示すものではない。詳細は[技法対応の調査](../../study/00112_支持否定の確認と通常追尾幅の比較/診断/元三手法の技法/調査.md)・[索引](../../study/00112_支持否定の確認と通常追尾幅の比較/診断/元三手法の技法/索引.json)・[検査](../../study/00112_支持否定の確認と通常追尾幅の比較/診断/元三手法の技法/検査.json)を参照する。

## 順行と反転で使う確認が異なる

元手法は既に方向・勢い・値幅・価格構造・二市場関係・執行条件を組み合わせている。日中coreのEMA15/60は、**確定1分足の15本と60本**であり、15分足と60分足ではない。並びと傾きをATRで尺度化し、NK225とTOPIXの方向支持、押戻し後の反発なども確認する。

一方、夜coreやaddonの突破枝は高安帯突破→順行→押戻し→再反発を使い、往復・日中episodeは帯端反発や帯外突破失敗からの回復を狙う。すべての初回入口へ共通のMA方向一致を要求する実装ではない。夜addonの反転枝にはMA20の位置確認があるが、通常初回の共通gateではない。順行の条件を反転枝へ一律に追加すると、役割そのものを変える。

板数量の利用も限定される。D164は価格支持・短期変化・OFI代理から希望量を決め、別の短期速度で延期する。U165は反対価格帯の維持と表示数量支持が重なった元初回を待機する。OFIや数量補充は実約定出来高と同じものではなく、全枝が独立した出来高確認を持つとは扱わない。

## 元にも保護はあるが、全玉共通ではない

| 元の保護 | 適用範囲・制約 |
| --- | --- |
| ATRや固定帯幅による追尾、部分利確、構造否定時の返済 | core/addon/episodeや時間帯で起動・幅・担当が異なる |
| S01の親利益保護 | episode親の実現＋残玉評価を対象とし、core/addonへ一律適用しない |
| P05の利益追尾 | ピーク40pt以上から10pt戻りを見ても、判断時の `gain>0` が必要。既にgain≤0なら、この利確条件は成立しない |
| P164の20pt追尾・建値床 | 少量初回（元初回20micro以下等）や正grossの部分返済後残玉など、資格のある玉に限定。全初回へ一般化しない |

従って「元には追尾がない」という説明は誤りである。同時に、判断用費用0の源にある担当別保護を、miniの手数料・滑り控除後の全玉共通保護と同一視できない。

111/112で追加した必須保護は、一つの実新規玉について、既返済の費用後額Rと残玉の費用後評価を合算したWが、初期枚数q0×10,000円へ達した時に起動する。別玉や反対側と相殺せず、費用床と全玉床、起動後の峰、通常幅・複合警戒を使い、保護床を不利に緩めない。これは条件を満たした後の返済判断であり、gapや次正常原行までの遅延を経た実約定の黒字保証ではない。

## 心理の仮説と次の問い

突破後の押戻し・再反発は追随の継続、帯外失敗からの回復は突破側の撤退、支持否定と勢い低下の重なりは継続根拠の弱まり、と解釈できる。ただし心理は仮説で、表示数量から注文者の意図や約定を断定できない。同じ価格系列から作る複数指標を、独立した証拠の数として数えない。

現比較は追加保護の実約定をSourceへ返さない。Source自身がまだ保有中なら、追加保護で実玉を閉じても源の再参加・親占有・通知はそのまま続く。固定Sourceによる出口比較と、実約定を源へ返して入口も変える統合戦略を分ける必要がある。

次は入口枝ごとに、長い背景の方向、押戻しの維持、局所的な支持否定と失速をどう区別するかを問う。元からある確認との重複を先に調べ、通常幅だけ、複合警戒式だけ、Sourceへの返送を含む統合変更を別条件で比較する。未参加・決済後の仮想利益を評価へ加えない。

112の実再生ではP100が主条件でW100を12,000円上回ったが、遅延で逆転し、追加滑り込みでは赤字となった。通常幅拡大も全4費用条件で悪化した。[実現差と次の判別](支持否定の必須確認と通常幅を分ける.md)を参照し、コードに複合技法があること自体を費用後優位の証明にしない。
