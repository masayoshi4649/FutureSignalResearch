# 15分ごとの判断と、時刻に依存しない利益・損失の追尾

更新日：2026-11-06。[外部再調査](外部再調査/README.md)を受けた研究条件。ここではユーザー指定、解釈、当初の未固定案を分ける。具体化した[試行49](../../study/00049_15分定時の序盤帯反応/README.md)では、予定枠・公開猶予・追尾幅・強制時計を固定して既使用66場で検証した。旧試行の条件・結果は変更しない。以下の「未固定」はこの共通条件を作成した時点の状態であり、49の実行値は同試行の計画を正本とする。

## ユーザーが指定したこと

- 新規売買を常時判断するのではなく、15分ごとに判断タイミングを設ける。
- 最初の1回を飛ばす。デイの例は09:00を飛ばし、09:15から判断する。
- 利益が出た後の追尾は、定時判断を待たず設定・更新する。利益の起動基準は、手数料・想定滑り控除後の現在含み益が正となった時点を維持する。
- 損失も追尾による離脱を考える。
- 「待ち」は許すが、その割合が半分を超えないようにする。
- **保有中は「待ちではない判断」と数えてよい。** 全定時判断を分母にし、保有継続を待ちへ含めない。

従来の複数手法、売買対称、セッション内完結、最低名目同値の利益保護、125/250の入口目標は維持する。常時の新規判断をやめることと、建玉の常時保護をやめることは別である。

## 判断時刻と参照する情報

|対象|今回の扱い|状態|
|---|---|---|
|デイ|09:00を飛ばし、09:15、09:30、09:45…|開始・間隔はユーザー指定|
|ナイト|17:15を飛ばし、17:30、17:45、18:00…|デイと同じ規則を適用した解釈|
|指標の時間幅|1/3/5/15分、上位足等は別に設計できる。15分判断だから15分足だけに限定しない|設計上の区別|
|分析履歴|判断時点で既知の過去足を使う。建玉の持越し禁止と、過去セッションの分析履歴の利用を分ける|先読み防止が必要|
|新規停止・強制返済|場末の新規停止と全返済を事前に固定。閉場時の新規注文や持越しを作らない|具体的な停止余裕は未固定|
|15分区切りの足|当時利用可能な確定足・板だけを参照する。区切りでまだ未公開の値を後から補わない|公開時計・判断時計の定義は実装前に固定|

ナイト開始時刻、新規停止の余裕、公開遅延時に同枠内で何秒待つかは、ユーザー指定済みと偽らず記録する。旧試行の残り60分、15:35/05:50強制等を、新しいユーザー要件として自動継承しない。新しい時刻規約を固定して比較する。

## 各定時枠に一つの判断を保存する

|時点の状態|判断の候補|主待ち件数に含むか|
|---|---|---|
|建玉なし・新規可能|買い|含まない|
|建玉なし・新規可能|売り|含まない|
|建玉なし・新規可能|待ち|含む|
|建玉あり|保有継続|含まない|
|建玉あり|撤退を要求|含まない|
|新規/返済の受付・約定待ち|処理中として状態を保存|待ちとは別記。状態を隠さない|
|価格/必要情報が使えない|判定不能|待ちと別記。欠損を除いて都合よく待ち率を下げず、評価の成立性を別判定|

実際に注文が約定した件数と、定時に買い/売りを判断した件数は別である。保有の継続は方向と保護状態を記録する。定時外にストップへ到達した場合も、定時まで撤退を遅らせない。

反転発注、即時再新規、同一枠の発注取り直しの有無と、一建玉の具体的な遷移を次の計画で定義する。定時外の保護返済後、次の定時枠まで建玉なしとなる扱いを基本案とする。

## 待ち率の主条件と、併記する量

```text
主待ち率 = 「建玉なしで新規を見送った定時判断」数 / 全ての予定された定時判断数
主待ち率 ≤ 50%
```

分母は保有中も含む。ユーザーの回答を受けた主条件であり、「新規可能枠だけの待ち率≤50%」へ置き換えない。

予定枠の一覧は結果を見る前に固定し、初回除外の09:00等は分母へ含めない。新規停止後も定時判断を残す範囲と、場末の強制返済だけを行う時刻を先に分ける。保有・返済待ち・情報欠測が重なる場合の主分類優先も実装前に固定する。判定不能を非待ち実績として達成の根拠にせず、品質上の適格性を別に判定する。

暫定的に、学習・条件選択等の各検証期間を主な集計単位とし、セッション別も併記する。毎セッション必ず50%以下という意味までは指定されていないため、達成したと一括で断言しない。

次も診断として保存する。

49では、主待ち率を保ったまま、全判定不能を待ちに含めた保守上限 `(待ち+判定不能)/全枠` も50%以下かを活動の判定に使った。判定不能を非待ち成功へ数えないための具体化であり、ユーザーが指定した主分母を変えるものではない。

- 全定時枠数、買い/売り/待ち/保有継続/撤退/処理中/判定不能の件数。
- 新規可能枠だけの待ち率。これは追加の採用制約にはしない。
- 新規判断数、約定数、完結数、保有時間、保有継続が非待ち判断に占める割合。
- 定時外の保護返済数、場末返済数、売買別・日中夜間別の成績。

待ち率だけを満たすため、保護条件に反して保有を延ばしたり、条件に合わない枠へ事後的に注文を足したりしない。追尾幅や保有方針は、ユーザーの活動条件と先着率・費用後損益・品質を同時に満たすよう検証する。

## 損失側と利益側の追尾を一つの保護線で表す案

以下は**実装前の案**であり、初期追尾幅Dや更新方式を検証済みとはしない。

新規価格E、実方向s（買い+1/売り−1）、現在正常返済BBOをm、現在の順行幅r=s(m−E)とする。hは初期0とし、現在の正常BBOを含めてh=max(前h,0,r)へ更新する。Dは新規時に定める有限正の追尾幅。価格更新ごとに保護線を新規価格からの順行幅Lで表す。

```text
初期保護線：L = max(−125, −D)
順行後の更新：L = max(前L, −125, h−D)
現在の費用後含み益が正となった後：L = max(L, 0)
保護返済要求：r ≤ L
```

これなら利益前にも損失側の保護線があり、順行に応じて損失許容を縮める。利益後は最低名目同値を床にする。線は緩めず、現在益の判定には過去の最高含み益を代用しない。DのATR等への対応、呼値への丸め、返済待ち中の凍結、執行遅延・費用を事前に固定する。

この案の損失追尾は、新規直後から損失側の線を有効にし、新規後の最大順行幅から追う方式である。h=0のまま含み損内で反発した幅を新しい追尾起点とする方式とは別にする。また、h−Dが正なら費用後利益の起動前でもL≥0となり得る。名目保護線が同値以上である旗と、現在費用後正を観測して利益保護が起動済みである旗を分けて保存する。

保護線の幅と、実際に約定できた損失幅を区別する。価格飛越や欠測があれば、設定線どおりの損失で約定するとは限らない。現在の[価格時計の限界](価格時計と受信時計を分ける.md)も検証条件へ残す。

125/250は引き続き入口の先着評価に使う。実際の固定250利確も併用するか、追尾・場末返済を主にするかは、新しい実行条件として未固定である。過去の固定250利確を、ユーザーが新たに指定した条件とは扱わない。

## 次の検証で同時に満たすもの

1. 外部根拠と心理仮説から、順行/反転/待機を当時の価格構造と複数手法で区別する。
2. 定時判断と定時外保護を別機械にし、15分の新規判断を待たず保護返済する。
3. 主待ち率50%以下、125/250の支持付き70%目標、費用後の収益、売買対称、場内完結を同時に評価する。
4. 判断枠、発注、約定、保有、先着、実回収の分母を分け、欠測/未解消時の確定額を観測額で埋めない。
5. 旧試行とは新しい時刻・保護規約として分け、条件固定後に新番号で実行する。
