# 保有区間OHLCと損失を検査する方針

2026-11-10の追加依頼。実際の建玉開始から損切り/利確までのOHLCと到達日時を原板から求め、利益後の赤字がどの過程で生じたか調べる。まず固定112の全24条件×70場を対象とする。新113金融条件の市場実行より、この調査を優先する。

全件集計・独立検算・CSV三点を完了した。[確認した原因と次の問い](保有区間OHLCで分けた利益後赤字の原因.md)、[正式な調査と代表例](../../study/00113_起動前の支持否定と利益保護の切替/根拠/112保有区間OHLC/調査.md)へ接続する。以下は実行前に定めた区間・会計・判別の定義を保持する。

## 区間と価格

| 対象 | 定義 |
| --- | --- |
| 建玉全体 | 実新規fillの原行から、全枚数が返済された最終fillの原行まで。両端を含む |
| 返済片 | 各返済allocationの実数量が保有された、同じ実新規から当該返済fillまでの寿命。部分利確後の価格を返済済み数量へ適用しない |
| 原行順序 | 同じ日時でも物理行を区別し、実entry/exit quoteのTime・Index・Lineと原板値を接合する |
| Last OHLC | 有効な価格時計と正の有限Lastを持つ行。正常でないBBOでもLastの採用条件を満たせば含める |
| 返済可能価格OHLC | 正常BBOのみ。買い保有の返済側はBid、売り保有はAsk。Last OHLCと混ぜない |
| 到達日時 | O/Cの端点日時と行、H/Lの最初・最後の到達日時と行。同値の極値を一回へ丸めて順序を失わない |
| 入出力の品質 | 無効時計・非正/非有限Last・無効BBO・境界欠落を件数と状態で残す。境界不整合は完成値で補わない |

O/Cはそれぞれ区間の最初/最後の採用価格で、実際の新規・返済約定価格は別列に保存する。ラージのLastとminiの代理BBO約定の差を「発注ミス」と決め付けない。

## 費用と部分返済

建玉全体の評価は、実際の既返済費用後額Rと残枚数nを原行ごとに合わせる。価格g=side×(返済側BBO−実取得価格)、1枚往復費用K=77+200S円、u=100g−Kとして、W=R+n×uを使う。初期枚数を最終返済まで仮想維持しない。

返済原行では返済前/後のR・nと約定BBO・配賦費用を照合する。同じBBOの返済でWが不自然に飛ばないことを検査し、最終Wを実現純額へ一致させる。記録するのは実際の保有区間内の最大/最小評価、初回費用後正益、各手法の起動水準への初回到達と日時・原行である。

同じ原行を隣り合う数量区間へ重複して扱う場合でも、原板行数・同値到達回数を二重加算しない。返済片OHLCと、R/nを合わせた建玉全体の評価益を別の尺度として保持する。

## 確認する損失

- Lastでだけ利益が見え、スプレッド・費用を含む返済側BBOでは正益にならなかったか。
- 一度費用後正益を観測したが、必須追尾の起動水準には達しなかったか。
- 原板で起動水準へ到達した日時と、実際の保護起動記録が一致するか。不一致はモデル/境界/会計の調査対象とする。
- 保護の起動、返済要求、既存予約、次の正常原行での実約定がどの順で起き、要求後の気配移動と追加待ちがどれだけ影響したか。
- 価格差同値で返済され、手数料等だけが赤字として残ったか。
- 正益/極値を観測した時点で、既に返済要求済みだったか。注文待ちを無条件に「放置」と分類しない。

「保有中の高値で売れたはず」という損益は作らない。OHLCの極値は事後の価格記録であり、その場で分かる売買信号ではない。意味のない損失という結論は、当時の情報・注文状態・費用と照合した具体的な根拠を示してから付ける。未参加や退出後の仮想利益、機会損失、MFE回収率、ROIは評価しない。

## 成果物

予定CSVは、建玉全体OHLC、返済片OHLC、候補別の損失/整合集計の3点。全候補・費用・セッションと0件を残す。赤字行の単なる全件複製は別ファイルにしない。代表例と判断不能の理由をMarkdownへ記録し、Viewerの実約定とつなぐ。

原板は各場一度の走査を基本にし、同じ区間・価格系は再利用する。原板本文や全価格点を新たに複写せず、極値・初回到達・必要な検査根拠を保存する。独立の端点人工と少数区間の別走査で照合する。11/09は引き続き未読とする。
