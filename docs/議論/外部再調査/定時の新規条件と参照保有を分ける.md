# 定時の新規条件と参照保有を分ける

2026-11-08追記：[93の元連続mini比較](../../../study/00093_元三手法のmini連続再現と費用/README.md)で指定手数料後の黒字を確認した。以下の15分向け状態の区別は維持し、最新指定の5分・各開始30分・mini片側10枚へ接続する。

次の型には二案がある。Aは元Portfolioのnew要求を未約定のまま次定時まで置く方式で、元の予約上限・親・取消・実fill後の準備状態まで変わる。Bは元三手法のnativeShadowを連続運転し、新しいnew通知の出生を捕捉して最初の次定時だけ実側へ供給する方式で、元の状態と実の費用・保有・追尾を分ける。どちらも単なる残玉の無期限取得とは区別し、元法と同値とは呼ばない。今回まだ採用・数量・失効・Sourceclose分母を固定していない。

公開Portfolioには個別HoldIDの返済依頼を正規登録するAPIが見当たらず、OnFillは既存Orders/Intentsを必要とする。FlattenOwnerはowner全体を閉じ、ForcedOwnersによる継続抑止も伴うため、個別玉の利益追尾の代用にしない。追尾を追加する際は、元通知の参照層と実の所有・返済契約を明示する。新しい通知の出生、最初の枠、30分見送りでの消費、整数配分、当時の技法確認を固定してから損益を比較する。

## 結論

**現在の参照残玉を選ぶことと、当定時に新しい初回の技法条件を評価することは別のアルゴリズムである。** 前者には「元手法が以前から継続している」という履歴の意味があり、後者を実装するには、現在の価格条件だけでなく、何の待機・親・準備状態を継承し、何をflatと仮定するかを定義する必要がある。

定時ごとにflatなReferenceをNewして現在Observationを1回Stepする方法は、後者の正確な実装にはならない。既知Observationを再用すれば外部Featuresの計算済み指標は失われないが、Portfolio内の準備・親・仮想注文・30秒継続などは復元されない。さらにReference.Frameは発生した新規signalではなく、仮想約定済み残玉を公開するため、空状態への最初のStepでは新規希望があっても当行の残玉poolにはならない。

早い入口が有利とも、残玉の遅い入口が悪いとも、今回の読取からは判断しない。15分新規・売買対称・連続G1と最低建値床を維持する前提で、候補の意味を先に分ける。

## 現在方式の三つの玉

| 層 | 実装上の正本 | 意味 |
| --- | --- | --- |
| 元の仮想源 | `Selected.Shadow` と、その内側のD07等 | 固定mini10枚尺度の元判断・親・注文・仮想取得・返済 |
| 選定三手法の参照玉 | `Reference`内Portfolioの `Selected.Lots` → `Frame/ReadMetadata` | D164/P164/U165の政策まで適用した仮想実玉。現在残量とinitial/delayed_initial/source_addを持つ |
| 本研究の実会計 | 定時採用後の新Book | その時点のBBOから新たに取得し、独立した費用・G1予算を持つ |

現在のpoolは2行目である。元の裸の新規条件一覧や、最内側Shadowの当行新規signalそのものではない。

`Reference.Step`は前の予約の仮想約定→元の全原行Observe→当行通知の受付→残玉更新の順。Quantityは実参照の約定残量で、返済予約を差し引いた量ではなく、予約ありをClosingで別記する。残量減少は元部分返済だけでなく選定政策の保護等も反映する。ReadMetadataは参照初期量・元親初回量・元初回希望量を区別し、残量から親初回量を逆算しない。

したがって、元の初回100相当が利確等で20相当残っているとき、その20を新Bookの初期量にすることは「いま初回条件が20を提案した」という意味ではない。元取得価格・過去のピーク・部分益の資格も、新Bookの新しい取得や確定益ではない。元 `source_add` を実側が初めて取得する場合もあり、元段階と実参加段階を分ける必要がある。

## 比較すべき方式を混同しない

| 方式 | 定時に問うこと | 継承する履歴 | 元法との関係 |
| --- | --- | --- | --- |
| ① 残保有pool | 元手法の参照玉がまだ生きており、現在の複合技法も許すか | 元取得・部分返済・親・追加・待機解除・現在量 | 現行方式。現在の新しい初回成立とは別 |
| 新規通知の定時サンプリング | その定時の原行で元法がnewを実際に発行したか | 元法の全状態 | 元通知の観測。狭い時間標本で、初回条件の常時成立表ではない |
| 新規通知の候補保持 | 原行で発生した準備/解除/新規を、次定時まで候補として残すか | 発生時状態・候補期限・原行での失効 | 新しい保持契約が必要。定時spot再評価と同じでない |
| ② 定時の新しい初回評価 | いまの既知Observationと、明示した状態仮定で、初回として入れるか | 技法の準備状態を継承するか、親/占有/クールダウンをどう扱うかを要定義 | 元法の述語と状態を切り分ける新モデル。単純なflat再生成では代替できない |

定時以外 `allowEntry=false`、定時だけtrueで元PortfolioをObserveする方法も、②そのものではない。内部Shadowは非定時にも進み、元初回イベントを消費する。D164では非許可時の初回を `InitialSeen=true`、`Rejected=新規停止時の源初回` として記録する。夜間も親を先に登録してから外側のallowで発注を止める。後の定時でtrueへ戻しても、過去の同じ親が新しい初回へ戻るわけではない。

## 三手法の状態依存

| 手法 | 初回に関係する現在値 | 当行の数値だけでは代用できない状態 |
| --- | --- | --- |
| D164_15 | 日経/TOPIXの価格進行・短秒5/15速度・OFI等からの支持量、速度失速/再加速 | S01と内側D07の親/占有抑止、初回Seen、当初希望量、延期開始、Source量/ピーク、数量配分Factor、予約/取消。追撃には別の短秒順行確認 |
| P164_06 | 米国前の基底P05/D07の価格条件、数量・値幅条件 | 基底の準備・注文・親、元初回量、初回/追撃の区分、小量初回資格、過去の黒字部分返済で付いた残玉資格。小量資格を現在残量へ付け替えない |
| U165_03 | 現在の反対価格帯と表示数量支持、新しい同方向帯 | 親が初回か、待機開始At/Index、30秒取消、初回Sourceの生存量。同方向帯のIndexが待機開始より新しいこと。独自の追加gateがないことと、元source_addを継承することを分ける |

基底も状態機械である。D164のS01は別のD07仮想口座の旧親占有を見て乗換えを抑止する。P05も独立D07を内部で運転する。D07のResearchActiveには、価格境界・突破/押戻し段階・極値・準備開始・30秒継続確認・NextReady等がある。返済後の再開を扱う状態もあるが、それを本研究91の再参加権と同一視しない。

未知の扱いも元式ごとに異なる。D164の初回失速・U165の反対板待機は、必要値未知ならその追加待機を発動せず元入口を維持する。D164の希望量は支持不明時にも基準10を返す式で、支持のM/Tは校正された勝率ではない。自己価格窓、相手市場、OFIの既知性も別に持つ。一括して未知なら拒否へ変えれば、元の初回条件とは別の品質gateになる。新評価では元のフォールバックと、外側複合技法が必須とする既知条件を別checkに残す。

### 30秒待機と15分時計

D164は初回の短秒失速を最大30秒待ち、再加速で解除する。U165は反対板支持で初回を待ち、30秒以内の新しい自方向帯で解除する。元方式は全原行でこの過程を進める。

- 次の15分にだけ解除を再評価すれば、通常は元の30秒資格が既に切れている。
- 原行で解除した瞬間に実新規を出すと、15分新規の条件が変わる。
- 原行で解除した資格を次の定時まで保持するなら、資格の失効・再検査・元Source消滅・数量を新しく定義する。その保持を元30秒規則そのものと呼ばない。

15分時計を保った比較では、原行で技法状態を更新することと、新規を要求できる時刻を分離する。確認が定時直後に成立する例や、次定時までに消える例も残し、都合のよい時刻へ入口を戻さない。

## 既知Observationをどう使えるか

`strategy.Features.OnBoard`は全原行を追加し、`Observation`へ市場・価格時計/受信時計・源Index・価格/BBO・ATR・E01・Research・Selectedの当時値を返す。日中支持と短秒、夜間の価格イベント/帯もこの段階で作る。既知Observationを不変コピーで読めば、このFeaturesの履歴を定時ごとに再作成する必要はない。

ただし、次のAPIは目的が違う。

| 公開API | 使えること | そのままではできないこと |
| --- | --- | --- |
| `Features.OnBoard/AddCandles` | 因果的な現在観測を生成 | 同じ板を再投入せずに純粋な再評価をするAPIではない。再投入は窓/OFI/Index/帯イベントを二重更新し得る |
| `Portfolio.Observe/ObserveWithFreshness` | 現状態を更新しnew/close Signalを返す | 純粋な初回述語ではない。親/予約/注文/LastIndex等を変更する |
| `Portfolio.Dump/strategy.Restore` | 仮想状態を丸ごと分岐・復元する | 会計だけを安全にflatへ変換するAPIではない。復元は同じ所有/親/準備の整合を検査する |
| `Reference.Step/Frame/ReadMetadata` | 全原行の源を継続し、現在玉と親量を読む | 初回候補の純評価や、隠れたPortfolio全状態を読むgetterではない |

生きているReferenceへ同じcached Observationを再Stepすると、Indexが増えないため拒否される。時刻/Indexだけ増やして再投入する方法も、元物理行と夜間状態の時刻/Index整合を壊すので採らない。新ReferenceのSession.Startを定時へ変更してwarmupを作り直すことも、セッション/米国境界条件を変える別モデルになる。

同一Portfolioを分岐して元判断を診断するなら、当行Observeの**前**にDumpし、復元した別実体へ同じObservationを一度だけ渡す形は公開APIで可能。ただし保有/準備/親も全部同じ分岐なので、答えるのは「その元状態で発行する通知」であり「今flatなら初回として入りたいか」ではない。既存Referenceは内部bookがprivateなので、この分岐を行うには新しい研究adapterがPortfolioを自分で保持する等の設計が必要。今回そのadapterは実装していない。

### 二つの時計を保存する

`decision_at` と `observation.time/received/index/source_line` を別にする。定時直前の原行を使い、定時と同秒でも処理順が後の原行を先取りしない。15分の定時へ合わせるためにObservation.Timeを書き換えない。指標の既知/鮮度、待機の価格時計、セッションの新規許可時計を別々に示す。SourceのIndexと全受理QuoteのIndexも同じと仮定しない。

## ②を作る場合の最小分離案

現在の公開APIに、状態を変更しない `EvaluateInitial` は見当たらない。次の三層を分けた新しい研究用評価型を先に定義する。

1. **技法状態**：公開Observationと、全原行で因果更新した境界・押戻し段階・継続確認等。背景/構造/勢い/量/値幅を分けて既知性を持つ。
2. **元取引状態**：元親の初回Seen・現在保有・pending・元利確・Source量・NextReady等。継承する条件と、実側flatを仮定して外す条件を列挙する。外した条件があれば元法の完全同値と呼ばない。
3. **本研究の執行**：15分・当時BBO・同時一玉・実数量/費用・永久seen又は新しい機会ID・連続G1。元取引の利益を実G1へ足さない。

仮の新型 `InitialCandidate` には、少なくとも次を持たせる。

- `decision_at`、観測の価格/受信時計・源Index・物理行、method/版/元commit。
- `origin=held_reference / current_initial / captured_signal`、方向、元役割と実初参加役割。
- 基底のsetup、trigger、元状態の許可、実側の許可を別checkにし、未知/不成立/適用外を分ける。
- 使った境界/待機/継続の公開出典、親/元Sourceとの関連IDは実在する場合だけ保存する。
- 元初回提案量・当定時希望量・元参照現在量・実要求量を別項目にし、mini10→micro100の尺度と整数丸めを固定する。残量から新しい初回提案量を埋めない。
- 候補ID/出生/失効、同一原行の再評価が新機会を作らない規則。再参加を同時変更しない。

D164では初回時の支持量でOriginalDesiredを固定し、同原行に複数親があると100基準の空きへ比例・最大剰余で配分する。定時の支持量へ毎回置換すれば数量も変わる。全候補を当定時生まれへ揃えると親Started順や元At/ID順位も変わるため、初回条件だけの差と見なさず、希望量・配分・採用順位を別に保存する。

新しいfresh初回を、仮のHoldID・元取得価格・残保有量を捏造して `ReadLot` へ詰めない。現金融のSource入口は保持参照と返済通知の契約を持つため、fresh候補用の入口adapter/APIが必要になる。G1の計算・費用・連続保護を共通にすることと、Source入口の型まで無変更であることは別である。

## Sourcecloseの意味も先に決める

①のSourcecloseは、選定参照玉の既存HoldIDについて、未通知残量Beforeと今回返済量Quantityを示す。これは新Bookの「現在価格で利確できた」や「新規根拠が今否定された」と常に同義ではない。元取得価格や元保護資格に依存した退出もある。実側への比例返済は、その元参照の支援を減らす共通ルールとして機能している。

②には、元参照玉が存在しない候補もあり得る。その場合、元HoldIDを前提としたBefore/Quantityは自動的には定義できない。

- 既存の生存参照に結べる候補だけを対象にし、同じ数量と元通知を残すなら「新規条件×残保有のハイブリッド」であり、純粋な②とは分ける。
- 元親に支援終了を結ぶなら、どの親・いつから・どの分母で実玉を減らすかを決め、過去の部分返済や利益資格を新玉へ遡及しない。
- 新しい候補から専用の仮想参照を開始するなら、その参照の取得・初回量・状態初期化・終了を定義する。未来の仮想fillを見て、過去の定時へ実要求を戻さない。
- Sourcecloseを外し、技法失効とG1だけで返済する案は、入口だけでなく出口も変える。比較を一因子の入口効果と呼ばない。

現方式と②の最初の損益比較を行う前に、数量とSourcecloseをどう共通化できるかを確定する。候補だけmaskした旧損益の合計では、占有・seen・取得価格・後続参加・通知分母の変化を再現できない。

## テクニカルを主軸にする記録

| 役割 | 共通に分けて保存する観測 | 混同しないもの |
| --- | --- | --- |
| 背景 | 既存の方向背景、価格進行/効率/相手市場との関係 | 元参照が残ることを現在方向の保証にしない |
| 構造 | 原手法の境界・突破/押戻し・準備段階、必要なら既存の独立価格状態 | flatを作って境界/待機履歴まで消すことと、保有だけ外すこと |
| 勢い | 当時の価格変化、短秒5/15の失速/再加速、既存のMACD/RSI等の現在資格 | 元初回時の勢いと当定時の勢い |
| 量 | 現在の既知OFI/表示数量・価格帯支持と価格応答 | Source現在保有量、過去の親初回量、出来高 |
| 値幅/位置 | ATR/固定risk、境界からの取得位置、spread・丸め・実要求量 | 過去の元取得距離や元利確額と新玉のリスク |

MACD/RSI等の本研究の外側技法を、元三手法自体が同じ式で使っていると記さない。既存の複合技法と15分時計・連続G1を保ちつつ、元Sourceが担うのは「技法の現在チェック」なのか「履歴付き参照の支援」なのかを記録する。

## 実装前の反証

- 同じObservationの再読で候補/注文/Index/親が増えず、既読snapshotも変わらない。
- 待機前/解除後/30秒等号と超過、既存親/新親、元追加/新実初回、0丸め、元Source消滅を分ける。
- 指標は既知でも元準備状態がない場合を、初回不成立又は状態不足として正しく残す。fresh Newの空poolを指標未知と断定しない。
- 同じ観測値でもArm/継続開始/初回Seen/元残量が違えば判断が違う例を人工で示す。
- Source新規希望が当行に出ても、次正常原行fill前にはFrame.Lotsへ現れないことを確認する。
- 15分直後の解除、次定時前の失効、原行での取消を残す。非定時の実新規を混ぜない。
- 別の初回評価で増えた候補が新しい支援/返済契約を必要とすることを検査し、旧Source全面同値を未計測のまま成功化しない。
