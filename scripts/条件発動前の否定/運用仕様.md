# 発動前の反対端否定だけを追加する運用

作成・人工確認日：2026-11-06。試行68の独自規約であり、実市場の利益や心理を実証した文書ではない。

## 継承する条件

[固定67の運用仕様](../定時候補の価格発動/運用仕様.md)と[運用実装](../定時候補の価格発動/運用.py)をそのまま参照する。新 `Engine` は旧 `Engine` を固有名で読み、`decide` と `observe_watch` だけを上書きする。旧ファイル・大域値・クラスを変更するmonkeypatchは行わない。

公開APIは `replay(events, slots, conditions, session, candidate_id='N0', bounds=None)`。N0/N1を別々に呼び出す。引数・返り値の型は固定67と同じ。

- `events`：`{now,line,last,bid,ask,valid}` の元6列。有限非後退の価格時計、strict昇順原行。元valid数量旗と有限正 `bid<ask` の両方を正常BBOに必要とする。
- `slots`：固定49/67の純判断 `scheduled,time,line,side,role,atr,D,reason,ready,slot_id`。特徴・未来label・条件成否を混ぜない。
- `conditions`：`slot_id -> {high,low,source,expires}`。高安は有限正で `high>=low`、期限は `scheduled+900` で実判断より後・強制より前。sourceはrootが当時最新の公開完全3分SOURCE13と一致検査する。エンジンは不透明な辞書として保存する。
- 出力：固定67の全operationとconditions/condition_traceを保持し、条件終端に **設定否定** と **前提否定** を追加する。他の既超過・観測不足・未発動・発動未約定・約定・未登録の意味は変えない。

定時の方向・役割・ATR/D、発動線、次予定+900の寿命、発動後+1価格秒・後原行正常BBO・TTL30秒、強制・終了半開、連続保護・現在122円strict正起動・最低名目新規床、同約定費用0/5/10、品質・活動算術は全て旧67を継承する。追加指標・方向更新・自動反対注文はない。

## 唯一追加する価格条件

同じ正常観測について、実sideを `s` とし、買いは `Last<=low`、売りは `Last>=high` を反対端否定とする。等号込みであり、売買は上下反射した同じ規則。高安同値でも規則を変えない。

Lastだけで否定しない。必ず正常BBOと有限正Lastを同時に必要とし、非正常valid旗、不正気配、Last未知・非正を否定へ補完しない。

## 設定時の優先と保存

旧67の欠測/BBO不正→pending→保有→既存監視→ready不足→強制以降→side0の優先を維持する。保有中にはLastと特徴readyを新たに課さない。新規候補の役割・有限正ATR・ `5<=D<=125` の検査も維持する。

残った正常な純候補では、次の順で判定する。

1. 設定時に既に買い `Last>high`、売り `Last<low` なら旧 **既超過** のまま待つ。
2. 既超過でなく、反対端否定なら **設定否定** とする。高安同値でLastが同値のときも設定否定。
3. 否定がなければ旧67どおり条件登録する。

設定否定の保存literal：

| 保存欄 | 値 |
| --- | --- |
| decisions.action | 待ち |
| decisions.decision_reason | 設定時に反対端を否定 |
| condition_outcome | 設定否定 |
| condition_reason | 設定時に反対端を否定 |
| registered / watch_started | False / False |
| watch_quality / trigger / entry_filled | False / None / False |
| status / end_time / end_line | 終了 / 元判断time / 元判断line |
| condition_trace.action | 条件未登録 |

これは当時の待ちへ入る。watch未開始のため登録後未約定へ重ねて数えず、品質注意も追加しない。設定時Last不正は旧観測不足・判定不能のままで、設定否定ではない。

## 発動前監視の優先と保存

監視が存在し、設定keyよりstrict後であることが前提。同秒後行を含む。旧timerは原行より前に処理するので、満了と同秒の価格は新しい否定・突破へ利用しない。

1. 最終の正常BBOかつ有限正Lastから300秒をstrict超す最初の原行では、否定や突破より先に旧 **観測不足** で取消す。当行Last/BBOが不正でも間隔超過を検出する。満了timerでも最終観測との差を検査する。
2. 300秒以内かつ正常観測なら `last_observation_time` を当行へ更新する。300秒等号は正常範囲。
3. 反対端否定なら **前提否定** で取消し、watchを消費する。
4. 否定がなければ旧67の買い `Last>high`、売り `Last<low` strict発動へ進む。

前提否定の保存literal：

| 保存欄 | 値 |
| --- | --- |
| 元decisions.action | 条件登録のまま。事後に待ちへ書き換えない |
| condition_outcome | 前提否定 |
| condition_reason | 発動前に反対端を否定 |
| registered / watch_started | True / True |
| last_observation_time | 否定した正常原行のtime |
| watch_quality / trigger / entry_filled | False / None / False |
| status / end_time / end_line | 終了 / 否定原行time / 否定原行line |
| condition_trace.action | 条件取消 |

価格否定は観測品質の問題ではないため、損益注意を立てない。同枠内で価格が再び外へ進んでも復活・再登録・反対新規は行わず、次定時の判断を待つ。次定時ではその時点の別候補を通常どおり判断できる。

## 発動後と活動分母

発動でwatchは消費され、新規pendingになる。それ以後のLast反対端到達へ今回の否定条件は適用しない。新規pendingは旧TTL・次定時満了・強制によってのみ取消し、返済pendingと建玉も新否定で取り消さない。保有後の返済は旧連続追尾・独立強制に従う。新規fillのLast不正も、正常BBO約定を新たに妨げない。

活動分母は全予定枠。設定否定は当時WAIT、監視後の前提否定は登録済だがentryなしの **条件未約定** に入る。保守待ちは `(WAIT+判定不能+登録後未約定)/全予定枠`、主待ちはWAITだけ、保有継続・処理中は非待ち。旧actionと事後被覆を混同しない。

否定を増やせば活動が減り、結果として取引数・取得位置・取り逃がし・損益が変わり得る。否定した集合を未来の良い定時価格へ戻して取得することはできない。価格前提が心理的に破綻したと断言せず、実装した正常Lastの反対端到達という観測に限定する。
