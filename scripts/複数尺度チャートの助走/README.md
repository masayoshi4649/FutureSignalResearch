# 独立チャートの助走案

96の検討用の小型Goライブラリ。固定80の`TechnicalBank`と固定82の`ChartBank`をimportし、指標式を複写しない。金融・Native・Sourceへ値を返す経路や所有台帳は持たない。実原板・95の損益・未読期間は使用していない。

## APIと時計

| API | 引数と役割 | 返り値 |
| --- | --- | --- |
| `New` | `Scene{ID,Contract,Start}`、任意の`*Seed` | 当場の独立`*Bank`と`error` |
| `Step` | 当場NKの`Quote`、今回の観測上限までの判断時計列 | `Batch`と`error` |
| `AdvanceObserved` | 他市場等で明示的に観測された価格時計、判断時計列 | 価格を追加しない`Batch`と`error` |
| `Snapshot` | 引数なし | 参照を共有しない現在の値 |
| `Seal` | 引数なし | 非公開の数値種`Seed`、場末`Snapshot`、`error` |

`Step`の`Quote.Valid`はLastの可用性。BBO正常性とは分ける。Lastが正・有限でBBOだけが異常なら、呼出側が技法用複写で`Valid=true`にする。有限の0価格や`Valid=false`は不良Lastとして未知へ戻す。NaN/Infは入力エラー。原行Index/Lineは当場内でともにstrict増加、価格時計は非減少とする。

1回の操作では次の順で処理する。

1. `Scene.Start + 180*n`の3分timerを、その時点までの各gridと時系列mergeする。15分timerは5回に1回の同時計で同時に閉じる。
2. 同時計のtimerを先に処理し、判断用snapshotをコピーする。
3. 最後に当原行のLastを次の半開区間形成足へ加える。

呼出側は必要な判断時計を**当時計のrawより前の同じ操作**で渡す。既にrawを受けた同時計へgridを追加する呼出しは拒否する。判断時計の間隔をこの器では固定しない。新規・保有判断、Source取得、手数料、損益保護は実装していない。

`available_at`は再生規則上のtimer時計で、当足の`bar_end`と等しい。`observed_clock`は今回timerを進める根拠として与えられた入力価格時計であり、遅れて複数timer/gridをdrainした場合にはgridより後の値になり得る。その価格を過去足へ入れるわけではない。実際の受信可能時刻やネットワーク遅延の証拠とは呼ばない。

`last_source`はその足へ投入された最後の原行の時計・Index・Line・Last・可用性を記す。`rows`は不良Lastを含む投入行数、`data_known`は当足に1行以上あり全行のLastが利用可だったことだけを表す。指標が助走済みであることは`TechnicalView`の各Knownで別に確認する。不良Lastの直後には過去公開済み足の出典が残っても指標Knownは偽になる。`invalidated_at`はこの未知化の一時的な印で、次のtimerで0へ戻る。全履歴の最終不良時計ではない。

## 種の引継ぎ

`Seal`はAdvanceを呼ばず、名目場末時計も受け取らない。観測上限より先の形成足を締めない。未完足の価格は次場へ渡さず、場外や休場中の横ばい足は生成しない。当場内の空足は固定80と同じく数値履歴を未知へ戻す。

同限月なら非公開数値種を値コピーし、新しい`ChartBank`で`BeginSession`を呼ぶ。形成足、公開mask、当場の出典、直前3分の追跡値を初期化する。限月が違えば数値器も新規。新しい開始は前場開始よりstrict後、前場の観測時計以上を要求する。限月変更で時計後退を許すことはしない。

固定80には非公開`error`インターフェースがある。正常状態ではnilであり、コピー前に再帰的な値検査でnil以外の可変参照を拒否する。数値種の固定期間・平均・前終値は引き継ぐため、次場最初のTRには固定80の仕様に従い前場確定終値との差が含まれ得る。これは休場足の生成ではない。

`Seed`は外から改変・組立てできないメモリ内の値で、永続化形式は追加していない。呼出側は`Seal`で同時に得たsnapshotを種の出典として保持する。2つの後継へ同じ種を渡しても数値器・追跡器を共有しない。

## 公開できる範囲

| 項目 | 今回の範囲 |
| --- | --- |
| 3分・15分EMA | 各8/21、現在値と固定80のKnown |
| 3分の勢い | RSI14と前RSI、MACDヒストグラム12/26/9と前値 |
| 3分の値幅・価格 | 確定Close、TR、Wilder ATR14と前ATR |
| 前3分 | 固定82の前Close・前EMA8・前BarEnd・`Previous3Known` |
| 公開・出典 | 3/15分それぞれのbar_end、available_at、観測上限、投入最終行 |
| 未実装・非公開 | OHLC一覧、MACD本線/シグナルの生値、前EMA21・15分前EMA、足内約定量/VWAP、実受信時刻 |

`Snapshot.Chart`は固定82の型そのものを使うので、外側ChartViewのJSONメンバー名は既存型の大文字名、内側TechnicalViewは既存のsnake_caseタグを保持する。勝手な別名・未知値の0補完は加えない。

## 人工検査と限界

`go test -count=1 -v ./...`、`go vet ./...`、`go build ./...`をこのフォルダで実行する。初回人工の停止証拠は試行96へ保存し、正式接続後の全体検査と分ける。作業版からコード4ファイルをbytes一致で移し、このREADMEの保存先の説明だけを更新した。

12トップ試験と9境界サブ試験で、助走不足/110本の助走、固定80/82の全公開値同値、timer→grid→raw、遅れた観測上限と過去grid、同限月・限月交代、未完足Seal、休場・場内欠足、同種2後継、返却値変更、Last不良とBBOの分離、鏡像、未来grid/時計/原行/NaNの拒否を確認する。小さな固定API境界人工であり、既存の実運転への接続・収益性・追加技法の効果は未検証。

別担当のread-onlyレビューでも、timer/grid/raw・Seed/roll・Sealの順序に実害差は見つからなかった。指摘された`observed_clock`と`invalidated_at`の語義は上記へ明記した。既存80/82・金融・95正式物は編集していない。
