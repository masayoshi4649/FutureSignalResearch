# 局所帯の反応を先に分ける学習

作成・ローカルAPI確認：2026-11-06。本担当は人工教師のfitとJSON走査だけを実行する。実市場の教師・学習・評価はroot担当。[固定52の学習仕様](../定時履歴/学習仕様.md)・既存コード・モデル・結果は変更せず、旧モジュールのglobalも書き換えない。

## 比較する方針

| 候補 | 入力 | 構造 | 扱い |
| --- | --- | --- | --- |
| 旧H0 | 固定52の基礎15＋履歴10列 | 固定52の深さ4 | 同46場の保存対照。本学習部では再fitしない |
| B0 | 基礎15＋局所帯幅F16＋実方向の中心距離F17 | 17列の自由木、最大深さ4 | 新しい局所帯準備に揃えた過去教師でfit |
| F0 | B0の17列＋局所反応Z=F18 | 根をF18<=0.5 / >0.5に事前固定、各子木は17列・深さ3 | B0と同じ教師pairでfit |

旧H0→B0は特徴・準備と再fitの方針差を含む。B0→F0は同じ準備・同じ教師に対して、局面Zで先に分ける構造の差である。F0は根も含めて最適化した自由木ではなく、両子の探索が届く行集合と最大深さも変わる。Zの単独の因果効果、心理の実測又は最適分岐の実証とは呼ばない。

W20/W30/F40は従来と同じ。過去20場→次10場、過去30場→次10場、過去40場→条件選択24場と既使用後続2場。新2候補で計6モデル、運用評価は46場、初期20場は学習専用。「学習」期間の結果は後半20場の時系列評価であり、fit40場の一般化性能ではない。全66場は研究に既使用である。

## APIと列数

[学習.py](学習.py)の外部APIは以下のとおり。

```python
fit(rows, feature_meta, policy, model_id, evaluation_start) -> dict
predict(model, vectors) -> dict
walk(model, values) -> (leaf_id, path)
```

政策は`B0/F0`。metadataと各方向のベクトルはB0が厳密に17列、F0が厳密に18列。長い側の切捨てや短い側への0補完はしない。F0の子木へは明示的に先頭17列だけを射影し、F18を子の分岐候補に戻さない。

metadataは`{id,name,method,family,scale}`で順序固定。F01..15は固定51の基礎特徴、familyはF01=`trend`、F02/F03=`osc`、F04=`vol`、F05..15=`price`。新規3列は以下のとおり。

| 列 | 内容 | method | family / scale |
| --- | --- | --- | --- |
| F16 | 局所の参照10本の幅 / 当時ATR | P03 | price / m03 |
| F17 | 実方向s×(終値−局所中心) / 当時ATR | P06 | price / m03 |
| F18 | 局所帯の反応Z、厳密な0又は1 | P10 | price / m03 |

局所帯・反応5本・方向対応・可視性の正本は[特徴仕様](特徴仕様.md)と[特徴.py](特徴.py)。学習側で価格機械やZを再計算しない。両方向がZ=1でも正当な状態であり、Zを売買方向又は排他的役割と同一視しない。B0の17列はF0の先頭17列と完全に対応する。

`vectors={'1':list,'-1':list}`の両空listは未準備WAITで、score/leafは双方None。片空・非有限値・列数不一致・float32桁あふれは拒否する。F18はfloat32化前から数値0又は1のみを認め、bool、0.5、閾値近傍を含む他値は拒否する。未知Zを0へ補完しない。readyなZ=0は未知ではない。

## 教師pairと先後関係

教師は固定49の同時計B+/B−。250=1、125/期限=0。片方でも未約定又は不足ならpair全体を除外し、双方のoutcome/filled・ID・除外分類を残す。未約定行のentry_time/entry_line欠落は許容する。

全入力教師の`end_time < evaluation_start`を要求する。同秒は原行が前でも拒否し、除外予定pairもこの未来境界の検査対象である。両方向は同じslot_id/session/予定時計/実判断時計/原行でなければならない。方向行は各0.5重み、一枠の使用重みは1。片方向だけの追加は認めない。

**この検査とpair除外を全行へ一度行ってから、F0をZ別の方向行へ分ける。** 枝内で再び両方向を揃える条件は課さない。同じ枠の買いはZ=0、売りはZ=1という枝分かれも許容する。各枝のユニーク枠は枝内の方向行から数えるため、Z0/Z1の枠数を加算して全体のユニーク枠へ照合してはならない。

特徴準備でrootが学習候補から外したpair数と、未来の教師が未約定/不足で学習部が外したpair数は別に残す。未来の不足を当時のreadyに戻さない。本教師は価格構造の順行/反転ラベルそのものではない。

## 学習条件と固定root

| 項目 | 共通の設定 |
| --- | --- |
| 学習器 | DecisionTreeClassifier / gini / best |
| 深さ | B0は4、F0の子木は3、F0合成後の根→葉は最大4 |
| 乱数・葉 | random_state=51、min_samples_leaf=60方向行 |
| その他 | min_samples_split=2、min_weight_fraction_leaf=0、max_features=None、max_leaf_nodes=None、min_impurity_decrease=0 |
| 重み・剪定 | 各方向0.5、class_weight=None、ccp_alpha=0、monotonic_cst=None |
| 環境 | Python3.14、scikit-learn1.9.1、NumPy2.5.3、SciPy1.18.1 |
| 数値 | 特徴float32、教師整数、重みfloat64 |

F0のrootは常にnode0、F18/index17、閾値0.5。左がZ0、右がZ1。子木の局所IDを、左は1から、右は左子木のnode数+1からの全体IDへ付け直す。全体pathも新IDで構築する。F0の固定rootが作る枝は、学習器のmin_samples_leafを満たすように選ばれた分割ではない。枝の件数が少なくても仕様を変えず、非空なら子木のfitは可能で、予測時の通常支持条件を適用する。

全nodeの所属・成功数・0.5重み・ユニーク枠/日/場・ID指紋は、合成後の木へ全使用教師を通して再計数する。固定rootのginiは全使用行の成功率pから`2p(1−p)`で算出する。子のginiも同じ算術であり、固定rootが最適gini分割だったという主張ではない。

空枝はfitしない。一つの未知leafとして`data_absent:true / score:null / impurity:null`、方向行・支持は0で保存する。これは失敗確率0%の葉ではない。

## 予測と採用資格

両方向は候補ごとに同じ一つのJSON木へ通す。元の有限特徴を先にfloat32へ写し、左`<=`・右`>`でたどる。epsilon、表示丸め、joblib/pickleは使わない。

どちらか片側でも未知leafに到達したら、`reason='未学習枝WAIT'`、side/winner_side=0。未知側scoreとeligibilityはNone、既知側のraw scoreは保持する。0点補完や低い側への救済はしない。

双方が学習済みなら、scoreがstrictに高い側だけを候補にし、同点はWAIT。勝側score>=1/3、葉ユニーク枠>=60・日>=6・場>=10、root→leafのfamilyが2種類以上かつtrend又はoscを含むことを全て要求する。勝側が不適格ならWAITで、負け側へ逃がさない。F18固定rootはprice familyとして数えるが、それだけでは異種family条件を満たさない。score下限1/3は研究用で、費用分岐点ではない。

## 保存JSON

schema_versionは従来と同じ1。従来の全node/training項目に固定rootと未知の区別を加える。

- トップ：model_id/policy/feature_meta/feature_meta_sha256、parameters、subtree_parameters、structure、rules、versions、source_sha256、training、nodes、interpretation。
- `parameters`：共通設定と合成全体の深さ上限4。F0の実際の子fit引数は`subtree_parameters`の深さ3で明示する。
- `structure`：B0は`kind='free'`、F0は`kind='fixed_root'`とF18/index17/threshold0.5/child_depth3/child_features17/max_depth4/root_gini_optimized=false。
- 全node：id/feature/feature_id/family/threshold/left/right/path、方向行・重み・成功率、unique_slots/days/sessions、methods/families、所属ID指紋、impurity、leaf_support/method_support、data_absent。
- `training.partition`：B0はNone、F0はキー`'0'/'1'`。各枝にdirection_rows/pair_unique/days/sessions/row_ids_sha256/fit_performed/root/node_count/fit_parameters。枝別ID指紋はglobal usedの順序を保つ。
- trainingの従来項目：入力/使用pair、除外方向結果、使用ID、入力/使用行・期間指紋、評価開始より過去の最大終了key。
- predict：scores/leafs/side/winner_side/reason/eligibility。

内部では非空子木の全node所属・方向数・重み・成功率、全使用方向行の葉ID/scoreを元のscikit-learnと照合する。これはJSON投影と合成の接続検査であり、最適分岐を別算法で再学習する独立監査ではない。
