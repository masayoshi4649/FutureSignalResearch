# 内包足の偽突破確認と局面切替の入力

2026-11-06。[74事前計画](../../study/00074_内包足の偽突破確認と局面切替/検証計画.md)に対応する純入力。所有3ファイルは[入力.py](入力.py)・本仕様・[入力の人工検査.py](入力の人工検査.py)。本物の市場入力、教師、モデル、保有・注文、損益を読み込まず、旧固定コードも変更しない。

原典の基本Hikkakeのprice-crossを、公開済みの閉足終値確認、15分定時使用、確認後否定、DI/FastK/ADX/終値位置へ適応した独自規則。modified版や原典の売買成績の再現ではない。心理は偽突破の追随者が撤退し得るという仮説で、OHLCから注文主体を識別したとはしない。

## APIと保存入力

```python
extract(slot: dict, feature73: dict) -> dict
choose(source_Q0_slot: dict, observation: dict, policy: str) -> dict
```

旧73の保存Q0純slotと、その全64列特徴をそのまま受け取る。`extract`は旧ready/DI/FastK/ADX/ATR/Dを再計算しない。`choose`のpolicyはI0/H0/H1のみ。

公開する定数はSOURCE_FIELDS（13項目）、SLOT_FIELDS（10項目）、VALUE_FIELDS（6列のindex）、SIDES、POLICIES、STATUS_REASONS、RULES。旧モジュールのimport・大域値変更、指標銀行構築、ファイル読取は入力本体にはない。

### 15足の正確な場所

73特徴は旧58以降の辞書を深く保持する。価格形状に使うのは次の旧53履歴であり、58の保持機械全prefixやC/E/Jの6足だけではない。

```text
feature73['base']['history']['reference_sources']  可視10本
feature73['base']['history']['reaction_sources']   可視 5本
feature73['base']['base']['sources']['current']    最新足の照合正本
```

根拠は[旧53特徴](../局所帯分岐/特徴.py)のhistory保存、[旧58特徴](../水準を保持する再試験/特徴.py)のbase保持と、[旧73入力](../直近進行の集中と効率/入力.py)の全文複写。現足jに対して参照j−14..j−5と反応j−4..jとなる。

各配列はまず同場と終端を判定し、end>scheduledを除外する。残る足の公開key `(confirm,confirm_line)` が実判断 `(time,line)` より後なら、OHLC等を検査する前に除外する。終端・公開keyが不正で未来と判定できなければ例外。未来suffixの値で過去を変えない。

その後の参照10本・反応5本を厳密に要求する。可視足の不足、過剰、重複、未公開、欠枠、不完全幅、OHLC矛盾は例外とし、新しいready除外又は古い足による補間にしない。全15足で次を検査する。

- SOURCE13：session/index/minutes/start/end/confirm/confirm_line/publish/missing/open/high/low/close。
- 同場、minutes=3、end−start=180、confirm>=end、publish=True、missing=0。
- 価格はboolを除く正の有限数値で、高安に始終値が含まれる。
- index+1、前end=次start、公開key strict増加。
- 最後のSOURCE13が旧currentの13項目と型も含むcanonicalJSONで完全一致。

source_sha256は可視15SOURCE13のlistを、`sort_keys=True, separators=(',',':'), ensure_ascii=False, allow_nan=False` でJSON化したUTF8 bytesのSHA256。未来suffixや余分な診断項目をhashへ混ぜない。

旧ready=Falseは履歴や値を救済せず未知として返し、source_count=0、source_sha256=None、candidates=[]、selected両None、side=0/role=待機。qualificationの数値も全Noneとする。旧未準備placeholderのline=Noneはchooseで保持できる。

## 形状・確認・否定

価格比較は `Fraction(str(保存値))` を使い、epsilon、float32化、追加丸めを行わない。古いBから順に、実side買+1/売−1の順で全形を記録する。

|段階|買い|売り|
|---|---|---|
|内包I|I.high<A.highかつI.low>A.low|同じ|
|隣接する次足B|B.low<I.lowかつB.high<I.high|B.high>I.highかつB.low>I.low|
|B後1〜3足の最初C|close>I.high|close<I.low|
|Cより後の最初denial|close<=B.low|close>=B.high|

A/I/Bは隣接三足、CはBへ兼用しない。高安が確認端を越えても終値が等号ならCではない。B後4足目以降の初突破をCへ救済しない。最初のCを後の価格へ替えず、否定した形を再点火しない。C後の高安順、足中の理想約定、前段階の公開より後に足が形成開始したことまでは推測しない。

使用可能なC終端は `(scheduled−900, scheduled]`。左端は除外し右端を含む。公開が遅れてもC終端がこの範囲を外れた形を持ち越さない。各sideの有効形をC.index降順、同CならB.index降順で一つ選ぶ。新しい形が条件不適格でも、より古い形へ選び直さない。

### 候補schemaと5区分

`candidates`はstrict内包とBが成立した全形のlist。各候補は次の項目を持つ。

```text
id / side / A / I / B / C / denial / status / reason
confirmation_observed / confirmation_complete / confirmation_deadline_end
confirmation_line / denial_line
```

A/I/BはSOURCE13全文、C/denialはSOURCE13全文又はNone。confirmation_lineはIの反対確認端、denial_lineはBの反対端で、保存元の価格型を保持する。IDはCや否定に依存せず、B時点に固定する。

```text
session|H|sideの符号付き整数|B.index|float(B.confirm).hex()|B.confirm_line
```

`confirmation_observed=min(3,B後に存在する可視足数)`、`confirmation_complete=(observed==3)`、`confirmation_deadline_end=B.end+540`。completeは3足観測済みという意味で、Cの存在ではない。

|status|条件|固定reason|
|---|---|---|
|未確認|Cなし、B後の可視足が3本未満|終値確認待ち|
|確認期限切れ|Cなし、B後3本を観測済み|B後3足の終値確認なし|
|確認窓外|Cあり、否定なし、C終端が直近900秒の範囲外|終値確認が直近900秒窓外|
|否定|Cあり、後続の最初の否定あり。窓外より表示優先|確認後に偽突破端を終値で否定|
|有効|Cあり、否定なし、C終端が使用範囲内|直近900秒の終値確認が有効|

## 複数技法の直接条件

保存float64のF01/F02/F03/F15/F48/F52とraw background_directionを両方向へ保存する。値欠落・非有限・F52非二値を0補完しない。F01/F02/F03/F15の売買符号反対、F48/F52の売買同値、非零F01とraw背景の整合を検査する。

qualificationは各sideに `{qualified,role,reason,values}`。valuesは `{F01,F02,F03,F15,F48,F52,raw_background_direction}`。当時の配置roleは、raw背景又はF01が0なら待機、他は実sideとraw背景が同向なら順行・逆なら反転。不適格でも配置と値を残す。

判定優先順は以下で、最初の不成立理由を保存する。

1. 旧未準備：旧73特徴が未準備。
2. selectedなし：有効な終値確認なし。
3. raw背景0：上位DI同値。F01=0：DI優勢差同値。
4. F02<0：FastK中央差が逆向き。F03<=0：FastK進行が非正。
5. F01<0の反転だけ、F52!=1：ADX変化が未知、F48>=0：ADXが非減速、F15<=0：15分終値位置が非正。
6. 他は順行条件適格又は反転条件適格。

順行にADX減速やF15>0を追加しない。raw背景が±1でもF01=0なら新Hを採らない。両方向同時適格は入力不整合として停止する。価格形状自体を必ず反転roleと呼ばず、価格/オシレーター/上位方向と強弱/ATR保護の役割を分ける。量の条件・学習済みscore・回収平均をこの選択へ追加しない。

`extract`の返り値は正確に次の9項目である。

```text
ready / reason / source_count / source_sha256 / candidates
selected / qualifications / side / role
```

selectedは `{'1':候補全文又はNone,'-1':同}`。topsideは唯一の適格side又は0。toproleは採用のrole又は待機。topreasonは、未準備、適格時の「内包偽突破の複合候補」、両selectedなしの「有効な終値確認なし」、それ以外の「内包偽突破の複合条件不適格」。readyは旧readyと同じで、価格形状がないことを未知へ変更しない。

## 純判断への射影

`choose`は元Q0のO49純10項目、すなわちscheduled/time/line/side/role/atr/D/reason/ready/slot_idを深く複写し、session/policy/origin/pattern_idの4項目だけを加える。元feature、prediction、保有、注文、損益を転記しない。

- I0：元Q0の純値をそのまま保持、origin=保存Q0、pattern_id=None。
- H0/H1：新Hのsideがあればそのside/role、reason=内包偽突破の複合候補、origin=内包偽突破、pattern_id=selected.id。なければQ0純値とreasonも保持する。
- H0/H1はpolicy以外の全文が同じ。ATR/Dと時計は元slotから変更しない。新旧の準備矛盾や資格・選択形の不整合は例外。

I0/H1の即時方式とH0の条件方式は主処理の責務。ここでI端を条件発動線へ差し替えず、既存68の最新公開3分高安とその否定を維持する。型の相違による未知やschema不正を、良好な価格候補として救済しない。
