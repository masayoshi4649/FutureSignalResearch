# 206 両指数の固定端点相対変化・純仕様

2026-11-18。金融ラベル・損益・先着・入口採否を使わずに固定する。対象は共通全83場、NK225の181/194 q0 40,314点、TOPIXの旧/直接和集合q0 35,361点。元の判断時刻や原行を維持する。新規の売買条件は本仕様に含めない。

## 入力の再用

`inputs/00201_両指数の板数量純特徴/抽出前固定.json.gz`内の金融未使用q0投影と、その元の純特徴8資源のSHAを参照する。201の板数量値・入口採否・金融結果は読まない。各q0は自己8列入力の同じ原行に対して時計・Last・BBOを照合する。TOPIXの公表足closeをq0 Lastの代用にしない。

価格は旧81場の正式8列と194追加2場の正式8列、計166ファイルのみを読む。原板の再走査・複製はしない。列は`now,line,last,bid,ask,valid,volume,volume_time`であり、今回は価格時計とLastを使う。数量時計を価格時計へ置き換えず、BBOをLast時計で先行した気配と解釈しない。

既存[時計可用性の前提](../../docs/議論/指数間の先行追随を価格時計で参照する前提.md)の原順高水位・同秒初回Lastを継承する。抽出時に旧Sourceの初回Last系列と全166入力で照合する。

## 価格時計と端点

1. 原行順の有限価格時計について既到達最大値を保持し、それ未満の後退時計は利用しない。後から時計順に並べ直して過去へ差し込まない。最大値へ復帰した後は通常の規則を適用する。
2. 場開始以上、終了15分前未満にある各価格秒の最初の正の有限Lastを採る。最初の行が不正Lastなら同秒の最初の有効Lastを採る。後続の同秒価格、同秒最終値、未来最近傍値を主値にしない。
3. q0時計を`t`、仮定遅延を`d∈{1,5,30,60}`秒とし、**自己・相手とも終点`t−d`、始点`t−d−h`**へ過去as-of結合する。窓`h∈{60,300,900,1800}`秒。自己だけ現在へ寄せない。主条件は既存調査と同じ`d=1`、他3値は時計モデルの感度である。
4. 各固定端点を`e`、採用価格時計を`u≤e`とし、追加停滞`e−u≤60`秒を要求する。`d`と追加停滞は別。例えば主終点はq0から最大61秒前までの価格を許す。
5. 固定始点が場開始前、過去有効価格なし、追加停滞超過は未知。前場から補完しない。自己の採用原行はq0原行以下でなければならず、それ以後の値を返さない。
6. 自己q0が自己の既到達価格時計より後退した場合は全特徴を未知にする。q0が開始前又は終了15分前以後の場合も対象外旗で保持し、行を削除しない。
7. 相手の物理原行番号は採用値を追跡する識別子であり、自己商品の原行と比較して先後を決めない。共通受信時計がないため、真の公表・受信の先行性は確定できない。

価格時計が`t−d`以下という規則は、仮定した価格時計の公表遅延モデルである。実際の受信遅延を測った値ではなく、真の受信順のprefixを復元したものでもない。自己原行prefixと、相手価格時計上の未来変更への不変性を人工確認する。

## 値と品質

両端点既知なら各商品について`r=log(P終点/P始点)`を保存する。自然対数の無次元値であり、表示だけをbpにする場合は10,000倍する。自己・相手の両returnが既知なら`return_difference=r自己−r相手`を保存する。売買方向は適用しない。価格単位や指数値の大小を直接比較せず、ATRや全期間標準化は加えない。

内部品質は採用された始点時計から終点時計までの、初回有効Last系列の隣接時計差で測る。300秒**超**の差の件数と最大差を保存する。これは価格時計の間隔であり、受信欠落時間や市場流動性を確定した値ではない。

- `return_known`は両端点既知だけを表す。内部に大ギャップがあっても値を勝手に消さない。
- `quality_known = return_known and gap_count==0`。品質が必要な将来の入口条件はこの旗を別に使う。
- 未知のreturnと内部最大差はNaN、内部件数は−1。端点なしはline=−1・時刻/価格/停滞=NaN。
- 停滞超過でも、過去as-ofで見つかった採用行・時計・価格・停滞は追跡用に残し、`endpoint_known=false`とする。未知を0のreturnへ補完しない。

差の符号からトレンド継続・反転・市場を動かす原因を自動的に推定しない。指標や入口の予測力は本純特徴では検証しない。

## NPZ schema

保存先は`inputs/00206_両指数の固定端点相対変化/{商品}/{場}.npz`。`n`はその商品・場の全q0。配列の軸順は遅延`[1,5,30,60]`、端点`[終点,1分始点,5分始点,15分始点,30分始点]`、窓`[60,300,900,1800]`、商品`[自己,相手]`。

|列|型・shape|意味|
|---|---|---|
|q0_line / q0_time / q0_last|int64 / float64 / float64、`(n,)`|元判断原行・時計・Last|
|q0_target / q0_backward|bool、`(n,)`|対象時刻か／自己価格時計が後退したか|
|q0_band|int8、`(n,)`|0デイ・1米前・2米後。NY09:30の夏冬時間対応|
|q0_member_mask|uint16、`(n,)`|元純母集団への所属。ビット順は抽出前票のmember_order|
|endpoint_line|int64、`(n,4,5,2)`|採用原行。自己/相手の行番号を相互比較しない|
|endpoint_time / endpoint_last / endpoint_stale|float64、同上|採用価格時計・Last・固定端点からの追加停滞|
|endpoint_known / endpoint_reason|bool / uint8、同上|既知旗・理由コード|
|log_return / return_known|float64 / bool、`(n,4,4,2)`|各商品の固定端点returnと既知旗|
|gap_count / max_clock_gap|int32 / float64、同上|内部300秒超価格時計差の件数／最大差|
|quality_known|bool、同上|端点既知かつ内部大ギャップなし|
|return_difference / difference_known|float64 / bool、`(n,4,4)`|自己−相手のreturn差／両商品端点既知|
|difference_quality_known|bool、同上|両商品のquality_known|

理由は0既知、1端点が場開始前、2過去有効価格なし、3追加停滞60秒超、4判断時計が対象時間外、5自己判断時計の後退、6自己q0原行より後の参照。理由6は防御的な未知であり、通常の入力で発生するなら接続を調査する。

`抽出前固定.json.gz`に全Source・仕様・人工票・入力指紋とq0を固定する。`完了.json`には全ファイルSHA、可用性、主1秒からの差値・差符号の変化件数を残す。これらの感度を見て主遅延や停滞閾値を選び直さない。
