# 局所再開の入口機械

市場実行前の仕様。旧49は変更せず、固定49入口を固有名importして数値銀行と出典補助を再用する。価格ファイル、先着、損益、保有はこのモジュールへ渡さない。

## API

- build_bank(sessions)：固定49の契約と数値をそのまま返す。
- SessionSignals(bank,session)：当場だけを深写し、空の監視から始める。
- evaluate(scheduled,time,line,bbo_ok)：全予定枠をstrict昇順で一度だけ呼び、P0/P1を同時に返す。保有・処理中でも必ず呼ぶ。

各featureはside/role/atr/D/reason/ready、current/previous/upper/OR、diagnosticを持つ。rootが予定時計・slot_id・session・policyを補う。新しい注文は定時callback後だけであり、j/kの過去価格・過去時計へ戻して約定しない。

line=Noneはtime=scheduled、可視key=(scheduled,−1)とし、予定と同秒の公開足を見ない。BBO不正でも実keyまで足とイベントを進めて消費する。出力readyはFalse。欠測・不正後に同枠を取り直さない。

## 共通の可視性と数値

価格足は当場の完全・公開・missing0・有効OHLC。足end≤予定T、公開key≤判断key。足ごとの上位DIはその足end以下・その足公開key以下だけから選ぶ。定時でも最新上位を取り直す。古さ3分180秒・15分900秒の等号を許す。最新の見えた不正/未準備足を古い正常値へ代替しない。

数値ATR/Fast/DMI/ADXは49と同一。新方式の定時共通準備はOR、直近3本公開完全隣接、正ATR、Fast現前、当場DI。旧49structureのR10本を新方式の共通ANDへ持ち込まない。ATR/Dは実要求となる定時の最新3分値を使い、発動j/kのATRは別の診断値。

監視と未消費発動は価格不正、公開足の番号/end不連続で取消。非公開足の存在を先読みして取消理由へ使わず、次の公開足で不連続が判明した時点を記録する。場・建玉の数値carryとは別に、監視は場間carryしない。

## P0/P1共通の新T

1. OR高+5超/OR低−5未満で、同方向の上位DIが優勢な背景。sをその方向とする。
2. 公開足bでs×終値現前差<0かつs×FastK現前差<0なら監視を登録。
3. 後の最初の別足jで、買いCj>前足高/売りCj<前足安なら初発動。背景はなおOR±5外・同DI優勢。
4. 背景失効又は起点を含む11本目は、再開判定より先に取消。同足でTを再登録しない。

旧49Tの外3終値・K水準・現K進行への追加ANDではない。Kと価格の調整を先に観測し、価格による再開を後に観測する置換である。

## P1の新R

元外方向をs、反転する実方向をr=−sとする。

1. bの終値がOR±5を外へcrossしたら登録。前終値はその線を超えていない。bではDIを要求しない。
2. 最初の別足fが元端の内側5ptをstrictに越えて戻った時、r×ΔKf>0かつ上位DIが旧外方向優勢でなければ、fの逆端を固定する。
3. f後、最初のkがf逆端をstrict終値更新したら、同じDI条件を確認して初発動。上突破失敗ならCk<Lfで売り、下失敗ならCk>Hfで買い。
4. 元外側5ptの終値再獲得（等号含む）を先に取消。b→kは起点を含む10本、index差≤9。11本目は発動前に取消。
5. 初fのFast/DI不一致・不足、初kのDI不一致・不足はその監視を消費する。後の良いf/kへ取り直さず、新しいoutside close crossが必要。同足で新R登録をしない。

過去fの準備不足はactionsのstatus=invalidで保存する。定時の共通準備が回復した後まで、それだけで無期限にinvalidを引きずらない。最新の定時DIにも旧外方向優勢禁止を要求する。DI同値はRだけ許す。

旧Rの最新半分位置・2終値条件への追加ANDではない。OR中央でも、突破→帰還→逆端確認という履歴があれば新Rになり得る。中央位置だけでは発動しない。

## P0の旧R

各定時で固定49 evaluate_slot(...,S1)のRだけをそのまま候補にする。新イベントへ変換しないため、次枠も条件が残れば再び候補になる。新Tが無く、旧R自体が10本不足等で不明ならP0はinvalidとする。P1はこの旧Rを使わない。

## 初発動の鮮度・否定・消費

- j/kの発動後は、別足の終値が否定線へ戻れば失効する。買いclose≤線、売りclose≥線。T線はjの前足高安、R線はfの逆端。TのOR/DI背景失効も取消。
- 初めて可視となった次のevaluateだけで消費し、発動endから900秒以内だけ採用候補。900秒等号は可。古いもの・否定済みのIDも消費診断へ残す。
- 同枠に複数の有効な初発動があれば、同方向でも競合WAITとし全消費。P0では旧Rとの競合も同じ。最新だけの事後選択をしない。
- 採用・保有・処理中・不正BBO・欠測・未約定にかかわらず初発動は取り直さない。新規再参加は別の調整b又は新しい外側crossから。
- 別足は公開keystrict・index/end隣接で確認。j/k.end>前段階.confirmという追加制限は置かない。発注時には全ての参照足が既知であることを要求する。

## 診断schema

diagnosticはactions、consumed_ids、consumed_events、candidate_events、trigger_age_seconds、T_watch、R_watch、old_Rを持つ。P1のold_RはNone。

eventはevent_id/kind/side/role/original_side、origin_index/trigger_index/trigger_end/trigger_key、origin/trigger/previous/failure、origin_di/failure_di/trigger_di、OR/line_price/trigger_atr/trigger_fast_change、active/cancel_reasonを持つ。出典はsession+SOURCE12、DIはready/source/plus_di/minus_di/direction/adx。消費表示にはage_secondsを加える。

actionsは足出典と監視登録、取消、初回復帰固定、初f/k見送り消費、初発動固定、発動失効を記録する。時刻別の状態被覆と活動不足を後段で集計できるよう、待機を保有と見なさない。

## 人工確認と責任

入口の人工検査.pyは市場ファイルを使わない。新機械の単体検査ではFast/DI状態を明示入力として置き、別に固定49数値経路からの価格→調整→再開を人工で確認する。逆方向反射、未来・遅延公開、取消優先、別足、10本/900秒等号、同枠競合、二回目消費、不正BBO・欠測消費、旧Rの定時再評価を検査する。

新要求は全件について新しい正常BBO先着が必要。連続保護・現在122円strict正の利益起動・全予定枠の活動評価は運用側の責任で、入口の成功や価格の発動を実利益とは呼ばない。
