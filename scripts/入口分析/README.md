# 入口の経路分析

作成日：2026-11-01。NK225について、観測された返済気配が逆行200ptへ達するより先に順行400ptへ達するかを分析する。

- `分析.py`：確定足だけで入口候補を作り、同じイベントの先着ラベルを複数条件群で共用する。区間最小・最大の木を使うが、観測の行順は変えない。
- `検証.py`：素朴な走査との一致、閾値の等号、同時計原順、空白・期限・未約定・確定足等の合成検証。
- `独立照合.py`：分析コードの到達検索を使わず、実イベントの新規・最初の到達・原行・気配を再検算する。
- `集計.py`：事前固定の時間・ATR・RSI・数量等の層別を記述し、成功・失敗・期限・不明・未約定の全内訳を図にする。
- `代表事例.py`：固定規則で成功・失敗の単独事例を選び、Viewer向け2約定・一覧と照合図を作る。閾値到達と返済約定を分ける。
- `経路図.py`：代表事例の順逆行pt、−200/＋400の水準、到達点と待機後返済点を一枚で比較する。

入力は00002の正式台帳を参照し、作業キャッシュを再利用する。作業領域を消去した場合は、[共通のキャッシュ復元](../複合検証/README.md)を先に実行する。既存の数値コード・データ準備は編集せず、依存するコードのSHA256を実行情報へ残す。

```powershell
python -X utf8 "scripts/入口分析/検証.py"
python -X utf8 "scripts/入口分析/分析.py" --study "study/00004_逆行200ptと順行400ptの入口分析"
python -X utf8 "scripts/入口分析/独立照合.py" --study "study/00004_逆行200ptと順行400ptの入口分析"
python -X utf8 "scripts/入口分析/集計.py" --study "study/00004_逆行200ptと順行400ptの入口分析"
```

`判定時計秒/JST`・`所要分`は、先着イベントなら最初の到達時計・所要分、期限未達/観測不足なら最後に採用した正常板の時計・観測追跡分である。実際の評価期限は別の `期限時計秒` に記録する。

全入口イベントは独立した経路比較であり、同じ時間帯の仮想保有が重なる。実際の注文へ同時に流すものではなく、合算損益も作らない。Viewer向けには代表イベントだけを単独シナリオとして保存し、到達判定とその後の返済約定を分ける。

環境はPython 3.14.3、NumPy 2.5.3、図はmatplotlib 3.11.2とWindowsのメイリオ。原板の復元読取はorjson 3.13.0（なければ標準json）。追加パッケージやGPUは使用していない。
