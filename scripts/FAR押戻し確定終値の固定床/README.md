# FAR押戻し確定終値の固定床

[試行90](../../study/00090_押戻し確定終値の固定床と初期損失/README.md)のオフライン検証。固定E1/G1と元FAR後期三手法を維持し、最新押戻し確定終値の逆側10ptを追加撤退線にする。P0は旧89 E1G1、P1は追加線あり。各D0/D1、全264会計。実注文は行わない。

## 実装と観測

- `pullback.go`：公開済みeventと最新pのRecordを結び、要求時の固定価格線を共有sidecarへ保存する。
- `actual.go`・`source_entry.go`：P0の旧経路を維持し、P1にS2専用入口を追加。旧ATR/G1床を私有状態へ保持し、新しい線が旧床よりstrictに厳しい場合だけ新理由とする。
- `types.go`・`replay.go`・`input.go`・`batch.go`：固定88の入口・event公開APIを再用し、15分時計、種、旧Source、連続金融、4会計を接続する。
- `集計.py`：費用、数量、同実入口の出口差と参加差、264のViewer互換資源を生成する。
- `原板監査.py`：独立所有から旧G1床とS2線を別に再構成し、約定・費用・予約・初回利益を一走査で検査する。
- `Source通知監査.py`：Source通知とevent/pの確定足出典を別の統合一走査で結ぶ。指標生成器の独立再実装ではない。
- `基準と保存判断の照合.py`：旧89 E1G1全132Bookの全文同値、共有E1、p候補出典と全金融snapshotを検査する。
- `押戻し価格床の寄与.py`：結果・取引診断・共有判断の3正本から、入口位置、黒赤遷移、同実出口差と参加差を分ける事後診断。
- `表示監査.py`・`図示.py`・`記録反映.py`：Viewer、場別損益、13正本からの帳票を照合する。

外政策P0/P1、金融内部S0G1/S2G1、入口E1、Source政策S、利益配分G1を区別する。追加線は入口の拒否条件にしない。

## 再生

Go 1.24.2 windows/amd64、CGO=0、Python 3.14.3。固定依存・純戦略43・exeの指紋は試行の条件を参照する。

```powershell
Push-Location 'scripts/FAR押戻し確定終値の固定床'
go test -count=1 ./...
go vet ./...
go build -trimpath -o '../../work/再現90.exe' ./cmd/batch
Pop-Location

& 'scripts/FAR押戻し確定終値の固定床/ネイティブ実行.ps1' -OutputRoot 'work/90再現' -ValidateOnly
& 'scripts/FAR押戻し確定終値の固定床/ネイティブ実行.ps1' -OutputRoot 'work/90再現'
```

上のbuildはコンパイル確認であり、続く再生CLIは条件で指定した停止exeを使う。再buildしたexeを再生に用いる場合は、条件と同じSHA256であることを確認し、`-ExecutablePath 'work/再現90.exe'`を両CLIへ追加する。再生先には新しい`work/`子領域を指定する。帳票の13入力と監査範囲は[再現補足](../../study/00090_押戻し確定終値の固定床と初期損失/再現補足.md)に記す。

## 保護と限界

現在単価の費用後含み益がstrict正なら、両政策で最低新規価格の床を即起動する。部分利確・実確定益予算・ATR・125pt・確定3分失敗・Source・場末返済は共通。床到達と次板の約定、費用後黒字を区別する。

押戻しの出典は終値であり、高安ではない。10ptは入力ラージの一呼値を使う固定実験値。ラージBBOによるmicro代理で、実通信・順番・深さを再現しない。全66場は既使用で、未使用11/5・11/6本文は今回も開かない。
