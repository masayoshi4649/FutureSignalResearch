# 複合判断の検証コード

作成日：2026-10-31。候補・入力・結果は各 `study/` に保存し、このフォルダは再利用する検証処理を置く。

- `データ準備.py`：原板を一度走査して入力・数量を監査し、`work/複合検証/` に再生成可能な観測キャッシュを作る。
- `キャッシュ復元.py`：作業領域を消した後、正式台帳にある入力だけから同じキャッシュを復元する。元原板とキャッシュのSHA256も検査する。
- `再生.py`：完全に確定した5・15・30分足と複合条件を逐次計算し、板気配による注文・約定を再生する。
- `検証.py`：先読み・足の集約・数量・出口・注文の合成検証。
- `台帳検証.py`：再生コードを読み込まずDecimalで会計を照合し、任意で全約定の原行・BBO・価格時計も照合する。
- `集計.py`：約定・セッション集計から、因子の対応差や内訳と少数の図を作る。

注文・会計・平滑化の共通部分は[試行00001の再現コード](../../study/00001_MACDと方向条件の比較/再現.py)を変更せず読み込む。再現にはこのファイルも必要で、実行情報へSHA256を記録する。新しい候補は各試行の `条件.json` に固定する。因子の指標定義は計画とコードへ明記し、パラメータの変更は別試行にする。

実行例：

```powershell
python -X utf8 "scripts/複合検証/キャッシュ復元.py" --manifest "study/00002_複数時間足と四系統の要因比較/入力台帳.json"
python -X utf8 "scripts/複合検証/検証.py"
python -X utf8 "scripts/複合検証/再生.py" --study "study/00002_複数時間足と四系統の要因比較" --phase 探索
python -X utf8 "scripts/複合検証/台帳検証.py" --study "study/00002_複数時間足と四系統の要因比較" --cache-check
python -X utf8 "scripts/複合検証/集計.py" --study "study/00002_複数時間足と四系統の要因比較"
```

`--phase 追加確認` は少数候補の最終固定後に使う。未見期間を探索の途中で繰り返し閲覧しない。条件・入力台帳にない場を自動追加しない。

キャッシュは作業領域であり、原板と正式な入力台帳・計算コードから再生成できる。原板の複製・全時点の指標を `study/` へ置かない。CPUで十分な規模のため、GPUの追加導入はしていない。

今回の環境はPython 3.14.3、NumPy 2.5.3、orjson 3.13.0（未導入なら標準json）、図はmatplotlib 3.11.2とWindowsのメイリオ。新しいパッケージは導入していない。入力台帳には作成時の版、各実行情報には数値コードと条件のSHA256がある。原板や依存版が違い、同じキャッシュを復元できない場合は、新しいデータ版として扱う。
