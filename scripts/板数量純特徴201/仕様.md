# 201の純板特徴・版1

2026-11-18。金融計算前の純仕様。出力は入力の数量と過去の価格応答のみ。損益・先着・採否・候補方向・将来行を参照しない。対象はNK225/TOPIX各83場。NK181/194の全1分q0は40,314件、TOPIX183旧形成/184直接形成と194追加2場の和集合q0は35,361件。旧条件と元原板を変更しない。

## 接続と時計

- キーは商品、場、物理原行番号。NKは恒久純特徴のq0のtime/Last/Bid/Askを原板へ照合する。TOPIXは旧/直接のq0のline/timeを恒久8列の同原行へ照合し、そのLast/Bid/Askを原板へ照合する。TOPIX純特徴のcloseは公表足終値であり原行Lastではない。
- 原板は元順に一度ずつ処理し、q0原行までを追加した瞬間に値を保存する。時計で並べ替えず、同時計の後の行を先に見ない。EOFは未完了ブロックの完了理由にしない。
- CurrentPriceTimeは現値時計であり板受信時刻ではない。原行順の更新数とLast時計上の進行幅を別に記録する。実時間N秒の圧力とは呼ばない。時計大ギャップは消さず`max_clock_gap`に残す。
- 時計欠測・場外・後退、Last/最良価格/量の非正値又は不正、Bid>=Ask、限月変更で全連続履歴を破棄する。時計後退では場内で既観測の最大Last時計を保持し、その高水位以上へ復帰した正常行から再助走する。欠測を零支持にしない。
- 全場のLast時計による範囲はデイ08:45〜15:45、ナイト17:00〜翌06:00。これは純原板の品質範囲であり、親の金融終了15分前決済や新規限界を変更しない。

## 7列

|列|定義|既知条件|
|---|---|---|
|QI1/QI3/QI10|上位k段の(買数量合計−売数量合計)/(両側量合計)|現在のL1が正常、対象段の価格・量が正有限、買い価格が段順に厳密降順/売りが厳密昇順|
|OFI16/OFI64|直近N回のL1変化における正規化OFI差分の算術平均|不連続後、N回のL1変化が蓄積済み|
|BLOCK4_OFI|直近4完了ブロックに属する全L1変化の正規化OFI差分合計÷変化数|4完了ブロックと1回以上のL1変化。4つのブロック平均の単純平均ではない|
|BLOCK4_MID_CHANGE|最後の完了ブロック末尾mid−最初の完了ブロックの基準mid|4完了ブロックがある。価格単位はNK/TOPIXそれぞれの指数価格|

L1変化はBuy1/Sell1の価格又は数量が前原行と変わること。同じL1の原行を増挿入してもイベント数は増えない。2段以深だけの変化はNの回数に含めない。符号は市場の買い側が正、売り側が負。入口元方向・実売買側をこの段で掛けない。

最良買価格をb、数量をB、最良売価格をa、数量をAとし、前行をp、現在をqとする。

```text
e = 1[bq>=bp] Bq − 1[bq<=bp] Bp − 1[aq<=ap] Aq + 1[aq>=ap] Ap
D = (Bp + Ap + Bq + Aq) / 2
正規化差分 = e / D
```

価格不変なら各側の数量純増減となり、価格が動いた場合は最良価格交代の寄与を含む。数量を一律に倍加しても値は変わらない。既存OFI30の4数量合計を分母とした窓平均とは尺度を区別する。注文取消と約定を分解した指標ではない。

ブロックは同じ有効Last時計を持つ連続原行。より大きいLast時計を初めて観測した原行で、その直前ブロックだけを完了公表する。新ブロック最初のL1差分は新ブロックへ所属させるため、境界原行をq0とした場合、そこに含まれる現在の板変化は直前完了4ブロックへ含まれない。ブロック基準は、存在すれば直前の正常原行、それがない場初期ではブロック最初の行。この定義でブロック間の差分とmid応答が連続する。

N窓の開始原行は選ばれた最初の変化より前のL1更新（初期は最初の正常原行）。同値行中の時計大ギャップも含めて記録する。`clock_span`はN窓の開始/最後の変化のLast時計差、ブロック列では先頭基準/末尾Last時計差。q0までの実受信経過時間ではない。

## 出力

`inputs/00201_両指数の板数量純特徴/{NK225,TOPIX}/{場}.json.gz`。トップレベルは`schema/symbol/session/financial_labels_used/rows`のdict。各recordは`symbol/session/line/time/last/bid/ask/contract/members/features`。

`features`は上表の7キーを持つdict。それぞれ以下の型を持つ。

```text
value: float|null
known: bool
reason: str             # 既知なら空文字、未知は個別理由
start_line/end_line: int # 実際に使った原行範囲。未知は0
available_line: int     # 値を知れた原行。完了ブロックは境界原行
events: int             # NのL1変化数、又は4ブロック内の全L1変化数。QIは1
clock_span: float|null
max_clock_gap: float|null
```

既知値では`0 < start_line <= end_line <= available_line <= q0.line`を確認する。未知値はnullと理由を残し、元q0を落とさない。候補のsideを掛けるのは後の金融比較側。正逆別の重複ファイルは作らない。

## 固定と検査

`人工確認.py`は鏡像、数量倍率、同値行増挿入、16/64回境界、未来同秒行のprefix不変、4ブロック完了境界と現ブロック除外、後退高水位への復帰、零量/不正常BBOでの窓破棄、同値板中の大時計ギャップを検査する。

`抽出201.py --stage prepare`で全166原板の物理SHA、既存展開SHA、純q0、Source・仕様・人工確認を`抽出前固定.json.gz`へ固定する。その後`--stage extract --scope 追加2 --workers 2`で同一仕様を確認し、`--scope 全83`へ拡張する。全原板の展開SHA・物理SHA・前後stat、全q0の価格/原行を検査する。金融前に独立純値監査も行う。

実行環境はCPython3.14.3、NumPy2.5.4、orjson3.13.0。通常のpip導入環境でも実行できる。参照する恒久入力と原板は複製せず、保存するのは固定q0識別子と75,675件の小さい純値。詳細な依存版・入力指紋は抽出前固定票が正本。
