# 技法分岐学習：浅い共通木の学習とJSON予測

作成・ローカルAPI確認：2026-11-06。実相場のfit・市場再生はこの担当では行わない。特徴の定義・符号・尺度は[特徴仕様](特徴仕様.md)と[特徴.py](特徴.py)を正本とし、学習部が独自に列を変換しない。

この木の教師は両方向の仮125/250先着であり、価格構造のT/R分類や心理状態ではない。学習した葉の成功率は学習標本の加重比率で、将来の成功確率・因果・一般化性能を保証しない。技法familyの条件も独立した複数の心理的証拠を意味しない。

## APIと担当境界

- `fit(rows, feature_meta, policy, model_id, evaluation_start) -> dict`：[学習.py](学習.py)。rootが本物の学習を呼び、返り値をJSONとして保存する。学習器やjoblibファイルは保存しない。
- `predict(model, vectors) -> dict`：標準ライブラリだけで保存JSON木をたどる。scikit-learnの予測器を再読込しない。
- `walk(model, values) -> (leaf_id, path)`：float32化と左`<=`・右`>`の純粋なJSON木走査。監査側の独立実装へ置き換えることができる。
- 特徴は15列の固定順F01..F15。metadataは各`{id,name,method,family,scale}`。familyはF01=`trend`、F02/F03=`osc`、F04=`vol`、F05..F15=`price`。欠測の0補完、標準化、列並べ替え、追加の符号反転はしない。
- `extract.ready=True`の両方向pairだけをrootが学習候補へ渡す。特徴未準備の除外数はrootが別記する。未来の先着不足を、当時の特徴readyへ戻してはならない。

## 教師・ペア・時間

各方向行の必須項目は`slot_id,session,scheduled,time,line,side,features,outcome,filled,end_time,end_line`。使用する約定済み教師には`entry_time,entry_line`も必要。未約定行はその二項目の欠落を許す。その他のラベル列を受け取っても新たな特徴へ加えない。

同じ`session,slot_id`には`side=+1,-1`が一行ずつ必要で、両側の予定時計・判定時計・原行が一致することを厳密に検査する。方向重複・片方向だけの入力・非有限特徴は拒否する。学習候補は保存入力順を保ち、損益や方向ごとに並び替えない。

| 保存outcome | 教師値 | 扱い |
| --- | --- | --- |
| 250 | 1 | 両側とも使用可能な場合だけ採用 |
| 125 | 0 | 同上 |
| 期限 | 0 | 同上。強制期限までの非250であり、未約定とは別 |
| 未約定 | 使用しない | 相手方向を含むpair全体を除外 |
| 不足 | 使用しない | 相手方向を含むpair全体を除外 |

一方向行の重みは常に0.5で、一枠の合計重みは1。`min_samples_leaf=60`はscikit-learnの方向行数の条件であり、後述する葉のユニーク枠60とは別である。両方向が同じ葉に入れば二方向行でもユニーク枠は1と数える。

`evaluation_start`は評価開始秒。すべての入力ラベルの`end_time < evaluation_start`を要求し、同秒は原行が前でも拒否する。除外pairを含めて入力の未来ラベルを拒否する保守的な契約である。使用行と全入力の最大終了keyを別々に保存する。仮約定・終了keyの逆順も拒否する。

本物の学習は各政策につき次の3木、合計6木をrootが順に作る。

| 学習範囲 | その木で評価する範囲 |
| --- | --- |
| 初期20場 | 次の10場 |
| 初期30場 | 次の10場 |
| 初期40場 | 条件選択24場と既使用後続2場 |

初期20場は学習専用で、運用評価は46場。初期40場に対するfit成績をそのまま40場の一般化成績とはしない。後続2場も既使用であり未見の外部実証ではない。期間の選択や実行順はrootの[検証.py](検証.py)が管理する。

## 固定学習条件

| 項目 | 固定値 |
| --- | --- |
| 政策 | Q0：深さ2、Q1：深さ4を全比較 |
| 木 | `DecisionTreeClassifier`、`gini`、`best` |
| 乱数 | `random_state=51` |
| 葉方向行数 | `min_samples_leaf=60` |
| その他 | `min_samples_split=2`、`min_weight_fraction_leaf=0`、`max_features=None`、`max_leaf_nodes=None`、`min_impurity_decrease=0` |
| 重み/剪定 | 各方向0.5、`class_weight=None`、`ccp_alpha=0`、`monotonic_cst=None` |
| 欠測 | 学習候補の特徴欠測はrootがpairごと除外。学習部は補完しない |
| 数値 | scikit-learnへの特徴はfloat32。ラベルと0.5重みはそれぞれ整数とfloat64 |

確認済み環境はPython 3.14、scikit-learn **1.9.1**、NumPy **2.5.3**、SciPy **1.18.1**。学習時はscikit-learnの版を検査し、モデルへ全ライブラリ版と学習コードSHA256を保存する。ローカル確認元はインストール済み`sklearn/tree/_classes.py`の`DecisionTreeClassifier.fit/predict_proba`で、特徴が内部でfloat32化されることも確認した。

## JSON正本

トップは`schema_version=1,model_id,policy,feature_meta,feature_meta_sha256,parameters,rules,versions,source_sha256,training,nodes,interpretation`。

`training`に使用方向行ID、入力pair数、使用pair数、除外pair数・各側のoutcome/filled・除外分類を保存する。入力行、使用行、使用ID、期間のSHA256はキー整列JSONで作り、行配列順は保持する。学習期間には全使用場、最初/最後の予定時計、使用教師と全入力それぞれの最大終了key、評価開始秒を含める。市場の全教師行や全特徴をモデルへ全件転記しない。

`nodes`はID順の配列で全nodeを保存する。

- `id,feature,feature_id,family,threshold,left,right`：scikit-learnの分岐をそのまま保存。葉は`feature=-2,threshold=-2,left=right=-1`。
- `path`：根から当nodeまでの`node,feature,feature_id,method,family,threshold,comparison,branch`。
- `direction_rows,weighted_rows,success_weight,total_weight,score`：教師所属から数えた方向行数・0.5重み・加重成功比率。
- `unique_slots,days,sessions`：ユニークな場/枠、日、場の数。direction_rowsと混同しない。
- `methods,families,leaf_support,method_support`：pathで実際に使った技法と別々の資格。
- `training_ids_sha256,impurity`：所属教師IDの指紋と学習木のgini。

fit内で教師所属の成功率・方向行数・重みをscikit-learnと照合し、使用全方向行のJSON葉ID・成功率も`apply/predict_proba`と完全一致で確認する。これは自分のJSON展開の接続確認であり、別算法による最適分岐の独立実証ではない。

## 予測と採用

入力は`vectors={'1':[15特徴],'-1':[15特徴]}`。両空listは未準備として`scores/leafs=None,side=0`。片側だけの欠測、非有限値、float32桁あふれは入力不整合として拒否する。

予測は各特徴をまずfloat32へ写し、JSON閾値と比較する。二重精度の元特徴と先に比較しない。等号は左へ進む。生floatでは右だがfloat32丸めで等号左になる境界も人工で確認する。

両方向のraw`score`を保持する。strictに高い側だけを勝者とし、同点はWAIT。勝者が次のいずれかを満たさなければWAITとし、次点へ救済しない。

1. `score >= 1/3`。等号可。これは今回の探索閾値で、費用分岐点や収益保証ではない。
2. 到達葉のユニーク枠が60以上、日が6以上、場が10以上。
3. 根から葉までの異なるfamilyが2種類以上、かつ`trend`又は`osc`を最低1種類含む。

返り値は`{scores,leafs,side,winner_side,reason,eligibility}`。`scores/leafs/eligibility`は両方向キーを保つ。`eligibility`はscore/leaf_support/method_supportを分け、pathのfamilyも残す。低い側のscoreを0に偽装しない。`side=0`は待機で、`winner_side`には資格判定前の最高側を残す。同点と未準備ではwinnerも0。

この採否は入口の候補であり、保有/pending抑止、正常BBO、新規TTL、連続損益追尾、全予定枠の待ち率、費用後の実績は固定運用と主検証が別に扱う。モデルscoreを実取引の利益率や実資金流入の計測とは呼ばない。
