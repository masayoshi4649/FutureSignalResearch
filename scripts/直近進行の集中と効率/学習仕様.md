## API

- `feature_metadata(meta, policy)`：B0は61、Q0は64。prefix61は[固定72学習](../支持を満たす技法分割/学習.py)の旧71規約で確認し、追加3項目はID/name/method/family/scaleと順を固定する。
- `float32(values, feature_count=64)`：61又は64を厳密検査する。Bは61を明示する。旧61の値域・共同maskを保ち、追加C/E/Jの未知・bool・非有限・域外を拒否する。
- `prepare_rows(rows, evaluation_start, feature_count=64)`：同commonready後の全pairを受ける。旧61射影を固定72のpair/可知/strict過去境界検査へ渡し、同順で全列canonicalを作る。追加のpair除外はしない。
- `fit(rows, feature_meta, evaluation_start, policy, model_id)`：B0又はQ0の元学習木を純JSON辞書として返す。policyから61/64を選び、引数の省略値に依存しない。
- `walk(model, values)`：政策別の全61/64値をfloat32へ写し、保存閾値をepsilonなしに走査し、葉IDとpathを返す。
- `predict(model, vectors)`：両方向のscores/leafs/eligibilityを保持した従来型prior。両空は特徴未準備WAIT、片側の先着標本未知は両側WAIT、同点WAIT。回帰値で方向を順位付けしない。
- `prune(model, model_id, source_sha256)`：元木の約定支持だけで両側を親へ統合し、派生JSONと元来歴を返す。
- `self_test()`：架空教師だけの検査結果を返す。正式学習・市場再生・proof生成は行わない。

返り値はjoblib等でなくJSON純辞書。schema_versionは1、元木はB0/Q0の各W20/W30/F40で計6本、同支持剪定後6本、calは運用側で派生6本から作る。

## 教師と指紋

旧69Cの即時/条件共通可知pairへ、当時だけで決まる新commonreadyをANDする処理は主・入力側で先に行う。両方向一組で同じ集合をB/Qへ渡す。教師を見てcommonreadyを作らず、片方向だけを増やさない。未来不足を現在readyへ戻さない。

`prepare_rows`のcanonical11項目は旧72と同型で、featuresだけが61/64になる。filledとoutcome、確定無取引0、障壁と回収の終了時刻が評価開始よりstrict前である検査を保つ。学習側で未知を0補完したり、返却行を黙って減らしたりしない。無取引0は回帰対象だが125敗北や障壁分母ではない。

`training.base61_fingerprints`は同commonready教師を旧61へ射影した六指紋。B/Q両方に保存する。旧`base60_fingerprints`も保持する。新full64のinput/used/barrier指紋は全64値を含み、full61と同じ値であるとは要求しない。共通のrow ID・期間・target指紋は、特徴値を含む指紋と役割が異なる。旧72の全準備集合と新commonready後が違う場合、元の旧72指紋と同値でないこと自体は異常ではない。

`feature_missing_handling`は「73の共通readyで先に両方向pairを限定。B61/Q64に同じ可知教師。学習内の追加除外・0補完なし」と保存する。準備落ちの件数・理由・IDと期間の比較は主結果を正本とする。

## 同じ固定構造と候補探索

固定node0はF01<=0、node1はD0のF26<=0.5、node2はD1のF20<=0.5。四群D0_V0/D0_V1/D1_V0/D1_V1を保持し、空群も未知葉として残す。D0は0/25、D1は0/19だけを子候補から除くため、子はBで59列、Qで62列。子深さ2・全体最大4、全行minleaf60、全方向行重み0.5である。float32根の微小値の零化と、運用側のraw DI0 WAIT・実役割を区別する。R有効はb出生段階からで、反転完成の意味ではない。

候補核は固定72の`choose_split`を、**内部policy引数S0**・政策別projection・metadataで純再用する。保存木のB0/Q0を書き換えたり旧moduleのglobalを変更したりしない。全float32隣接異値のfloat64中点を候補にし、両子の全行60とfilled unique60枠・6日・10場を両方に要求する。確定金額の整数化と厳密有理数MSE改善、正改善のみ、feature index→閾値順の同点規約も固定72と同じ。乱数は使わず、random_state=None、legacy_random_state=51は来歴のみ。

全nodeの`split_search`は72と同型で、固定3nodeはNone。非固定はcandidate_count/row_eligible_count/support_eligible_count/selectable_count/support_required/stop_reason/selectedを保存する。B/Qともsupport_required=True、selectable_countは支持適格候補数。早期停止の順と全候補数0も72同じ。選択したfeatureは全体indexであり、QのF62..64を子内の圧縮indexへ置き換えない。

統計は全回帰行のpnl5平均/MSEと、filled限定の障壁score・支持・filled回収を別保存する。空回帰葉、確定無取引だけの葉、回収正の葉を区別する。tech gateは従来どおり少なくとも2familyかつtrend又はosc、最高側score1/3等は運用選択側の固定規約で、集中度を手で採否条件へ追加しない。

## 支持剪定と来歴

旧71/72のprune入口は61列に固定されるため、64木をpolicy名だけ変更してその入口へ渡さない。新側で61/64構造を確認し、旧と同じsupport/descendants/paths純関数と同じ下からの支持DP・残存旧ID昇順再付番を用いる。固定0/1/2は残し、score・回収・評価到達で剪定しない。

各nodeのsource_node_id、source_to_new/new_to_source、全剪定決定、親統計、元training/partitionを保持し、新配置はpruning.partitionsへ別保存する。派生葉に残るsplit_searchは元学習時の来歴であり、現在の分割でない。剪定時の学習0。

依存の直接指紋は固定72学習一件へ絞る。そのコード自身が固定71以下のSHAを検査しており、主の固定/旧完了台帳が推移依存を保全する。旧依存を省略して未照合にする意味ではなく、新modelのshared_source_sha256へ同じ旧一覧を累積転記しない方式である。
