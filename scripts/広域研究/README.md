# 外部手法の調査に基づく検証

確認日2026-11-04。[00006](../../study/00006_外部手法を1分3分5分で比較/README.md)は1/3/5分の六入口×補助条件を比較し、[00007](../../study/00007_固定入口の単一建玉と費用感度/README.md)は固定一候補を単一建玉へ適用した。

Python3.14.3、NumPy2.5.3を使用。原板からキャッシュを作り直す場合は既存のorjson3.13.0も必要。CPUで処理し、新しい学習ライブラリ・GPUは利用していない。

## 実装と保存先

| ファイル | 用途 |
| --- | --- |
| 入力監査.py | 旧NK60の固定入力を維持し新NK4のみ追加。新4の成績を計算せず品質を監査 |
| 検証.py | 1/3/5/15分の足・EMA/RSI/ATR/DMI/ADX/BB・六仮説・147候補・一候補固定と後続検査 |
| 合成検証.py | 足・式・境界・時点・未来値不使用の34検証 |
| 独立監査.py | engine/評価.pyを呼ばない選択・集計・固定候補経路の別計算 |
| レポート.py | 数値正本から汎用表コピー、全閾値と結果、READMEを生成 |
| 運用検証.py | 00007の単一建玉・注文待機・固定幅の返済・費用・Viewer資料 |
| 運用の合成検証.py | 注文順・時刻・未完・空白・会計などの検証 |
| 運用独立監査.py | 運用エンジンを呼ばず全64場の会計・注文・最初の正常板・Viewer互換資料を別計算 |
| 運用レポート.py | 00007の固定済み数値からREADME・汎用表付き設定と結果を生成 |

原板は `../JP_OSE_Data/future/`。キャッシュは既存の `work/複合検証/キャッシュ/NK225/` を共用。大きな特徴付き入口は `work/広域研究/00006_探索事例.jsonl.gz`・`00006_後続事例.jsonl.gz` へ保存。正式試行は小型の全候補集計・固定一候補の事例・台帳・SHA・Markdownを保持する。

## 再現の順序

正式00006は後続確認済み。同じ出力先への探索/後続上書きを拒否する。再現する場合は `work/広域研究/再現00006/` 等へ計画・条件・入力台帳をコピーし、次の順に `--study` で指定する。新たな条件を研究する場合は新試行番号を取る。

```powershell
C:/Python314/python.exe -X utf8 scripts/複合検証/キャッシュ復元.py --manifest study/00006_外部手法を1分3分5分で比較/入力台帳.json
C:/Python314/python.exe -X utf8 scripts/広域研究/合成検証.py
C:/Python314/python.exe -X utf8 scripts/広域研究/検証.py --study work/広域研究/再現00006 --phase 探索
C:/Python314/python.exe -X utf8 scripts/広域研究/検証.py --study work/広域研究/再現00006 --phase 後続
```

探索は64件の台帳のうち旧60場だけを読み、新4場を入力読取前に除外する。後続は固定SHAを照合し、旧60の指標履歴を復元後、新4場に固定一候補だけを当てる。後続を再順位付けしない。作業中間ファイルの保存名は共通なので、異なる再現を同時に実行しない。

既存 `キャッシュ復元.py` は欠落分だけを固定sourceから再生成し、元stat・前処理版・展開SHA・キャッシュSHAを確認する。後から追加されたgzipへ勝手に入力を切り替えない。

00007は正式な固定ファイルを参照し、別の作業先へ再現する。入口中間物の圧縮SHAはgzip生成時刻等で変わるため参考値とし、展開内容SHAの一致を要求する。

```powershell
C:/Python314/python.exe -X utf8 scripts/広域研究/運用の合成検証.py
C:/Python314/python.exe -X utf8 scripts/広域研究/運用検証.py --phase 探索 --output work/広域研究/再現00007/探索
C:/Python314/python.exe -X utf8 scripts/広域研究/運用検証.py --phase 後続 --allow-future --output work/広域研究/再現00007/後続
```

Markdownの転記だけを更新する場合は `レポート.py` と `運用レポート.py` をそれぞれ実行する。固定された解析コード・条件・数値正本を文書修正のために変えない。

完成済みの監査は各試行の `合成検証.json` / `合成検証結果.json`・`独立監査.json` を参照する。00007の[Viewer照合記録](../../study/00007_固定入口の単一建玉と費用感度/Viewer照合.json)にローカルAPIの設定・起動記録・代表4場の照合を保存した。同じAPIが起動中なら `C:/Python314/python.exe -X utf8 scripts/広域研究/運用独立監査.py --include-future --api-base http://127.0.0.1:8092` で照合できる。APIを使わない会計監査は `--api-base` を省く。

## 判定の意味

00006は先着観測。主確認率は順行250先着/全約定で、逆行125先着・期限未達・観測不足を残す。運用損益へ読み替えない。各試行には元の表と同じ51×9の設定表を残す。

00007は観測気配を用いた売買再生。固定利確/逆指値線を越えた瞬間にその価格で約定したとせず、要求+1価格時計秒以降に返済する。空白や未解消を別記し、滑り感度は価格を動かす再実行でなく同じ約定への追加費用として定義する。
