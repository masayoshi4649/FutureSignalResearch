# 約定支持だけで技法群を剪定する仕様

作成日：2026-11-06。対象は[試行70の検証計画](../../study/00070_約定支持を保つ粒度で技法を組み合わせる/検証計画.md)。本仕様の実装・人工確認は、本物の三木を剪定したことや評価成績を示さない。正式実行の状態は試行の条件・固定・実行・監査JSONを正本とする。

## 目的と変えないもの

[固定69の条件教師C0木](../条件入口の教師/学習仕様.md)の学習済み分割を、訓練期間の約定支持だけで粗くする。新しい教師・特徴・分割閾値・分類器・回帰器を学習しない。全60特徴と、同じ親nodeに属していた全回帰例・約定例の統計を保持する。

新保存モデルのpolicyはP0で、P0/P1が同じ木を使う。P0は従来の技法資格・先着score・約定支持・回収支持を要求し、P1だけ同じ過去主回収総額のstrict正を加える。候補選択は固定66の両方向適格先行選択、入口は固定68、出口・費用・連続保護はO49を維持する。支持が残ったことを、先着70%・費用後利益・全予定待ち50%以下の達成としない。

## 支持と両側統合

支持は元nodeの`unique_slots >= 60`かつ`days >= 6`かつ`sessions >= 10`。いずれも固定69で約定した方向行から計算した件数であり、回帰に含めた確定無取引0は支持を増やさない。型は非負intとし、boolを件数として認めない。`leaf_support`とこの三条件の一致も元木の整合として検査する。

1. 元node 0のDI符号、1のR経路有効旗、2のT経路有効旗は分割のまま保持する。空群や支持不足群でも四つの固定群をまたいで統合しない。
2. 学習済みの各分割を下から処理する。両子を先に処理した後の、両側すべての終端nodeを列挙する。
3. 全終端が支持を満たせば、その分割を保持する。一つでも不足なら両側をその親へ統合する。一側だけを残さない。
4. 統合した親自身が支持不足なら、上の学習済み分割の判定にも不足として伝わる。固定三nodeを越えては統合しない。

剪定決定は支持三件数と木の構造だけを読む。先着score、回収額・平均、MSE、技法資格、評価到達や評価成績を良い枝の選別に使わない。下位の統合後に支持が残った親を終端として使うため、元の末端に一つでも不足があれば必ず固定群全体へ統合する、という規則ではない。

## APIと入力の責任

実装は[剪定.py](剪定.py)。公開APIは次のとおり。

| API | 引数 | 返り値 |
| --- | --- | --- |
| `prune(model, model_id, source_sha256)` | 固定69のC0/schema1辞書、新しい保存ID、呼出側が照合した元JSONのbyte SHA256 | schema1/P0の派生モデルdict |
| `walk(model, values)` | P0モデル、同60列 | 新IDの葉と根からのpathのtuple |
| `predict(model, vectors)` | P0モデル、両方向の同60列又は両空list | 固定69同型のprior辞書 |
| `support(node)` | 元nodeの約定支持件数 | 三件数とsupportedのdict |

`prune`はファイルを書かず、元モデルを変更しない。元C0、全60metadata、固定段、深さ4・子深さ2・枝別58列、到達可能な一意木、元path、元学習群root/countを検査する。元JSONのbyte SHAは呼出側が実ファイルと照合する責任で、純関数は64桁小文字16進文字列として受け取る。辞書内容の指紋も別に保存する。元統計の全再集計は既存69成功監査と入力指紋への結合を使い、本変換で教師を再生成しない。

`walk/predict`は辞書のpolicyだけを局所的にC0へ写して固定69の純関数へ委譲する。旧moduleのglobal、旧規約、元辞書を変更しない。float32、先着score下限1/3、約定60枠・6日・10場、複数familyとtrend又はosc、未知葉・同点WAITを保持する。根のtrendとpriceが資格へ算入される構造も従来どおりで、独立な二つの実証を意味しない。

## nodeと統計の継承

到達可能な旧IDを昇順で並べ、0から新連番を割り当てる。固定0/1/2は新0/1/2のまま。残存nodeには`source_node_id`を付ける。通常分割のleft/right、path内のnode参照だけを新IDへ移す。統合先は葉のsentinel `feature=-2, feature_id=None, family=None, threshold=-2.0, left=right=-1`へ変更する。

件数、全回帰平均/MSE、約定平均、先着score、支持、methods/families/method_support等は、その残存node自身の旧統計をそのまま複写する。子葉平均の平均は使わない。親のpathはその親自身の分割を含まないため、親を葉にしても親の元methods/familiesと整合する。確定無取引だけの既知回帰0と、全データなしのnullは引き続き区別する。先着データなしのscoreを0へ補わない。

元の`training`、`parameters`、`subtree_parameters`、`structure`、元学習コードの`source_sha256`等は学習証拠として保持する。特に`training.partition`のroot/countは**元木の配置**であり、剪定後の配置ではない。予測は新nodes/pathを使い、表示と監査は新配置を以下の`pruning.partitions`から読む。

## 保存する来歴と判断履歴

モデルtopへ新`model_id`、`policy=P0`、`source_model_id`、`source_model_sha256`を設定する。`pruning`には次を保存する。

| 項目 | 内容 |
| --- | --- |
| `rules` | この支持剪定の機械規約 |
| `source_model_id/source_model_sha256` | 元モデルIDと元JSON byte SHA |
| `source_model_content_sha256` | 解析済み元辞書の固定69 canonical指紋 |
| `source_node_count/new_node_count` | 旧node数と残存node数 |
| `source_to_new/new_to_source` | 文字列IDキーの対応。削除した旧IDの新IDはNone |
| `decisions` | 全学習分割の局所判断。上位統合で後から消えた判断も含む |
| `partitions` | 固定四群ごとのsource_root/source_node_count/new_root/new_node_count |
| `fit_count` | 0 |
| `code_sha256/shared_source_sha256` | 新変換コードと固定69学習コードの指紋 |

`decisions`は旧分割ID昇順。各項目は`source_node_id/action/terminal_source_ids/terminal_support/result_terminal_source_ids/reason/retained_in_final/split_retained_in_final`。`terminal_source_ids`は子の剪定後・自身の判定前の終端集合で、各支持件数とsupportedを記す。統合なら結果終端は自身の旧ID一つ。`retained_in_final`は最終到達に残るか、`split_retained_in_final`は最終的にも分割として残るかであり、局所の保持判断と最終残存を混同しない。

## 校正と主への接続

剪定後の同nodeを固定69の`calibration_for`へ渡す。先着scoreと回収は分母が異なり、校正の`mean_yen`は約定例だけ、`mean_all_yen`は確定無取引0を含む全例、主総額の符号はDecimal正本に基づく。総額は無取引0を加えても変わらない。固定66選択へ同prior/calを渡し、主のP0/P1 slotのpolicy/model_idへ結合する。

元教師は過去のままであり、評価期間の約定数や良い結果を使って再剪定しない。これまでの全66場は既使用である。支持による粒度変更は結果後に提案した新仮説で、未見実績や将来の校正を保証しない。

## 人工確認と範囲

[剪定の人工検査.py](剪定の人工検査.py)の`self_test()`又は`run()`が結果dictを返す。CLIはPythonで同ファイルを実行する。11群は、60/6/10等号と不足、両側統合・祖先再統合、下位統合後の終端支持、固定四群、全支持保持、利益/score変更の構造不変、元全文・統計保持、旧新IDと全path、不正木拒否、無取引と空群、剪定→69cal→66selector→新主P0/P1 slotsの純接続を検査する。

人工は手作り13node木であり、fitは0。公開fixtureは`source_factory(case='nested', overrides=None)`と`vector(direction=1, valid=0)`。caseはnested/keep/local_merge/fixed_insufficient/all_no_trade/empty_group、overridesは葉IDごとのfilled/days/sessionsを指定する。固定60metadataを読むが、市場配列・本物モデル・教師を読まない。正式三木の変換や新運用は主担当の固定後実行に限定する。別保存物監査は、この剪定関数を期待値として呼ばず、元支持と旧nodeから独立に残存構造・統計・予測を確認する。
