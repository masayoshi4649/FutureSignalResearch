# 条件入口の独立一枠測定

作成・人工確認日：2026-11-06。試行69の教師候補を測る補助であり、全方向を同時に実行する売買戦略ではない。市場・教師・モデルを読むコードを持たず、本物計測とfitはrootが別に管理する。

## 公開API

`MeasurementBank(events, session, bounds=None).measure(slot, condition, candidate_id='独立条件測定', background_direction=None)`。

- `events: list[dict]` は固定C49の `events_for` が返す場内・有限非後退価格時計の元6列 `now,line,last,bid,ask,valid`。原行はstrict昇順。元valid数量旗を正常BBOの判定から外さない。不正時計・後退時計・場外行・未来label等の追加フィールドは銀行構築時に拒否する。
- `session: str` は場、`bounds: dict|None` は人工用start/force/end。実際は固定68の場時計を使う。
- `slot: dict` は元定時。`session,policy,feature` 等の追加を許すが、Engineには固定68の `SLOT_FIELDS` だけを深く複製して射影する。追加特徴・予測・ラベルを新しい判断に使わない。sessionを指定した場合は銀行と一致が必要。
- `condition: dict` は固定68と同じ `{high,low,source,expires}`。SOURCE13・当時可視性・高安の整合・寿命は固定68独立先着も検査する。元条件やsourceを変更しない。
- `candidate_id: str` は独立実行の識別子。完全単独再生と比較するときも同じIDを使う。`background_direction: int|None` は±1/0/Noneの説明用。DI0を測るときはroleを順行へ仮置きするが、後段のDI0WAITを変更しない。
- 返り値は **固定68の標準operation全文＋measurement**。直接の全期間singletonは固定68 `replay(events,[pure],{slot_id:condition},session,candidate_id,bounds)`。`comparison_view(result)` で経済・保有品質・条件の共通射影へ写せる。

実際の対象は旧特徴readyな全枠×両方向。旧採用488方向や特定の価格パターン完成群へ限定しない。未準備を測定対象へ救済しない。非準備・side0・placeholderの人工でもoperation形は保つが、その場合の独立先着はNoneとし、通常の教師対象にはしない。

## 固定再利用とprefix

[旧55計測](../独立追尾回収/計測.py)の `MeasurementBank.__init__/_prefix` を継承し、入力検査・元6列の不変な記録・原行/時計索引・strict前のflat状態を再用する。[固定68運用](../条件発動前の否定/運用.py)と[固定68独立先着](../条件発動前の否定/先着.py)を固有名で読み、旧ファイル・大域値を変更しない。明示参照3コードのSHA256をimport前に検査する。

銀行を一度だけ作り、各原行の直前について次を利用する。

- 前の有限非後退価格時計 `last_time` と原行 `last_line/raw_line`。
- 前の正常BBO時計 `last_quote_time`。Lastの正常性とは別であり、68の条件監視時計を代用しない。
- 当該原行よりstrict前の非正常BBO数と、flat時の正常BBO gap>300秒数。

各測定は新しい68Engine一枠をflatから構築し、元判断原行より前の状態だけをseedする。同じ銀行の前の測定が持ったwatch・pending・建玉・損益を引き継がない。開始原行は予定以後最初の価格時計であり、正常BBOを待って後行へ結び直すことを拒否する。placeholderは予定時計の独立timerを使う。

元入力を構築後に変更しても、銀行は内部の元6列と独立先着索引を保持する。新しい単体エンジンの時計・原行・前正常BBOを消さないので、切出時のgapと強制要求出典を全期間singletonと同じにできる。

## 短縮してよい終点

旧55の「doneかつposition/pendingなし」だけでは不十分。68では定時に条件登録すると、doneかつflatのままwatchが続くため、そこで止めると将来発動を消してしまう。

新しい供給generatorは、直前にEngineが処理した結果について次の全条件が成立した後だけ止める。

1. 元定時の判断がdone。
2. watchがNone。
3. positionとpendingがともにNone。
4. 条件記録のstatusが全て「終了」。

これにより初回完結、設定否定・既超過等の無登録終了、監視取消、正常未発動満了、新規pending取消を終点とする。条件監視中や新規/返済pending中、保有中は供給を続ける。打切判断に将来の価格結果や独立labelを使わない。

原行がなくても68の `run` 最終処理が満了・TTL・強制timerを実行する。期限越えの最初の原行によってtimerが進んだ場合は、その原行がflatとして一行処理されることがある。条件終了keyはtimerより前の既知原行のままで、未来行を終了出典へ補わない。条件満了・次定時等号の取消優先、TTL30等号、force+1秒、終了半開は固定68へ委ねる。

## 完全単独再生と一致させる射影

`comparison_view` は次を深く複製する。

| 範囲 | 保存内容 |
| --- | --- |
| 経済 | closed、trades、fills、ordersの全属性 |
| 当時判断 | decisions全文。原定時time/lineと発動要求を区別 |
| 条件 | conditions全文、condition_trace全文 |
| 活動中の逐次追尾 | watch・position・pendingがあるログ、定時判断、返済約定、新規取消 |
| 品質 | 保有中長gap、条件監視観測不足取消数、判定不能、損益注意、確定可否、未解消建玉/注文、活動適格、全枠判定可能 |
| 集計・最終状態 | metrics全文とfinal_state全文 |

条件と建玉が終結した後のflat品質件数、flat強制ログ、最終の価格時計原行は全期間singletonと同一を要求しない。これらを保有品質の差や回収の差にしない。prefix時点のflatカウンタは保存するが、打切後のflatカウンタを未来から補ってはならない。

## 独立先着との接続

固定68 `prepare_events` を銀行ごとに一回だけ呼び、同じ銀行内で全ready方向の独立labelを作る。rootは返り値を利用し、同じ先着の二重計測をしない。

`measurement['独立先着']` に元枠・条件4項目・trigger・新規key/価格・未発動/否定/観測不足/発動未約定・125/250/期限/不足の全文を保存する。独立先着は同時一建玉の占有を使わない。

`verify_entry` は条件4項目、origin_slot、trigger、request key、condition_outcome、watch_started/quality、新規有無、fill時刻・原行・価格を独立先着と照合する。非約定なら条件終了keyも照合する。成功は `measurement['独立先着約定一致']=True`、先着対象外ならNone。不一致を救済せず例外にする。

次は意味が違うため同値を要求しない。

- 約定したlabelのendは125/250/期限/不足の障壁終点、条件記録のendはentry fill。実追尾の出口はclosedのexit。
- TTL等の非約定reasonは、独立labelの総称とEngineの具体的取消理由が異なり得る。時点・結果・注文は別に保存する。

## 無取引0と未知の区別

計測は教師のpair選別・回帰・支持を実行しない。教師の三分類は主が事前計画に従って行う。

正常な設定否定・前提否定・既超過・未発動・発動未約定でも、条件/注文の終結と品質を確認した上でのみ確定無取引0にできる。片側未知を0へ補完しない。**設定時のLast/BBO不正は、Engine損益品質がTrueで台帳0でも、独立先着が観測不足なので未知**である。

約定して追尾が完結しても、独立先着の障壁が不足なら先着教師は未知。逆に250先着でも、追尾退出がその前なら実回収が赤字になることがある。独立先着の既知性・回収品質・それぞれの終了時計を別に読み、評価開始よりstrict過去の可知性は主の教師準備で検査する。

未解消は新規片道費用11/61/111円の台帳観測を残し、全体確定対象はnull。保有中gap又はwatch開始後の観測不足もnullを維持する。全ready方向の独立回収を合計して実行可能戦略の利益と呼ばず、一枠分母の活動率を全定時枠の待ち率へ置き換えない。

## measurementの追加欄

独立一枠であること、全体売買でないこと、一枠分母、入力/prefix/供給イベント数、開始/最終走査key、打切理由、strict前prefix、説明用DI方向と仮役割、独立先着全文と照合結果、一致/非一致範囲、教師確定の注意、固定参照SHA256を保存する。元特徴全文を再転記しない。
