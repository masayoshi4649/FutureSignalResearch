## 独立計算

- `E3の純判定.py`：固定96のPython入力検査/check計算をSHA再用し、必要8/9checkからE3/E3S本名の採否を作る。保存Go採否を期待値にしない。
- `E3と金融の照合.py`：Source・現在採否・予約・次気配約定・費用・全経路MTMを再構成する。`inspect_tape(tape, new99)` と `compare_empty_gate98(new99, old98)` を公開する。
- `市場Tapeを照合する.py`：固定台帳/条件/完成/指紋を検査し、上の独立器へ同じ2/54場を配送する。`--index --run99 --condition --out --stage first2|full54 --workers 1..8`。新Source/指標/Rawを実行しない。

固定98完了は `2ee9417d0cd1f8bef107712789d26e3f72c0f95a933e60b31bb3f11784ca0dfe`。G0四帳簿だけを旧98の空risk/G0/H0へ除外なく全JSON比較する。旧AB・旧P0・初期riskありを新対照に代用しない。旧出典にある成功値を新99の成功として転記しない。

## 保存・表示・報告

`集計.py` は `--run --audit --condition --proof98 --index --out --limit 2|54` を受ける。成功した金融・独立の各stage指紋を要求し、圧縮Native、結果、一覧resources、全約定tradesを新規出力する。金額はDecimalで半円を保持し、純式へ渡す元JSONの数値だけGoのfloat64表現へ対応させる。Source/H注文分類、全現在採否、数量・所有・費用を検算する。

`表示監査.py --run --catalog <一覧> --result <結果> --out <新規証拠> --workers 8` は、保存会計を確認してから既存 `http://127.0.0.1:8092` の全648資源へ照合する。固定98/96の表示比較部品をSHA再用する。`--self-test` は通信代替の人工であり実APIの証拠ではない。Viewerを起動・停止・再設定しない。

`報告.py` は `--run` 又は `--check` と7入力 `--result --audit --viewer --condition --plan --readme --settings`、`--out` を使う。REPORT99 markerから原計画のbytesを復元し、汎用表版5・55×9/38設定/12評価を保持する。全648会計/独立/Viewerの成功が揃うまで正式報告を生成しない。

入口間の12比較は、実Source出生を先に対応させ、要求/取得時刻・Index・物理行・価格・初期量が同じものだけを同実入口の退出差にする。それ以外の取得変更・双方の実参加額を別記する。未参加や退出後の仮想利益・回収率は算出しない。
