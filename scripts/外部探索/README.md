## 入力と実行

正式な[入力台帳](../../study/00008_外部研究を共通尺度へ移して探索/入力台帳.json)を使って、欠落キャッシュだけを復元する。

```powershell
C:/Python314/python.exe -X utf8 scripts/複合検証/キャッシュ復元.py --manifest study/00008_外部研究を共通尺度へ移して探索/入力台帳.json
```

新しく再現する場合は `work/外部研究/再現00008/` 等へ計画・条件・入力台帳・外部参照台帳をコピーし、`--study` で指定する。正式結果の上書きは拒否する。

```powershell
C:/Python314/python.exe -X utf8 scripts/外部探索/探索.py --study work/外部研究/再現00008 --phase 探索
C:/Python314/python.exe -X utf8 scripts/外部探索/探索.py --study work/外部研究/再現00008 --phase 後続
```

探索は新11/4デイの原板・キャッシュを読む前に除外する。後続は旧64場から指標履歴だけを復元し、固定した新規最大2IDと旧対照に限って新1場を採点する。固定SHA・探索結果・選定の一致を要求する。

作業中間物の保存名は共通のため、異なる再現を同時実行しない。別の条件やデータで探索する場合は新しい試行へ分ける。外部の100/50先着・mini10枚・手数料0・次物理行執行を、こちらの125/250・micro1枚代理・片道11円・1秒待機と同一視しない。

外部入口の再採点は正式試行の `資料/外部約定取得.json` と固定キャッシュを読み、外部ファイルのGit blob SHAを照合する。新11/4デイを扱わない。台帳・原板の前処理・外部小資料の取得証拠は[入力監査](../../study/00008_外部研究を共通尺度へ移して探索/入力監査.json)を参照する。

正式結果を使う読取監査とMarkdown生成は、売買条件を変更しない。計算・固定条件に触れる再探索とは区別する。Viewerは各一覧JSONの親から約定を、設定の `data_root`（`../JP_OSE_Data/future`）から市場原板を解決する。3分足の条件は設定表で確認し、表示は原板・1分・5分等を使う。
