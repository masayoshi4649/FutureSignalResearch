# 定時判断と連続保護の運用契約

作成日：2026-11-06。新49用の実装契約。[運用.py](運用.py) / [運用人工テスト.py](運用人工テスト.py) / [研究条件](../../docs/議論/15分判断と連続追尾の研究条件.md)。標準ライブラリだけで動き、旧売買エンジン・原板ファイル・指標・未来ラベルを読み込まない。ここでの人工成功は実相場の収益確認ではない。

## 公開APIと入力

```python
replay(events, slots, session, candidate_id="S0", bounds=None) -> dict
scheduled_times(session) -> list[float]
session_bounds(session) -> dict
activity_metrics(decisions) -> dict
```

`session`は`YYYY-MM-DD_Day`又は`YYYY-MM-DD_Night`。時計はJSTに対応するepoch秒、原行は1始まり。通常の開始/強制/終了はデイ08:45/15:35/15:40、ナイト17:00/翌05:50/翌05:55。終了は**半開区間 `now < end`**で、終了等号の気配から約定を作らない。人工用に`bounds={start,force,end}`を指定できる。

`scheduled_times`はデイ09:15〜15:15の25枠、ナイト17:30〜翌05:30の49枠。初回09:00/17:15は含めない。エンジンは渡された全枠を分母にし、実相場の呼出し側は予定表との完全一致を検査する。人工では一部の枠だけを渡せる。

|入力|字段・扱い|
|---|---|
|`events`|各行は正確に`{now,line,last,bid,ask,valid}`。原行番号は重複なし昇順。`now`の欠測/後退は件数を残して飛ばし、同時計の原行順は保つ|
|`valid`|元資料のBBO/数量正常旗。時計有効旗ではない。正常BBOは`valid is True`かつ有限正`bid < ask`。良い価格でも数量旗Falseなら売買・追尾に使わない|
|`last`|入力の出典値。約定・含み益には使わず、新規買いask/売りbid、返済買建bid/売建askを使う|
|`slots`|必須`{scheduled,time,line,side,role,atr,D,reason,ready}`、任意`slot_id`。予定時計は重複なし昇順。理由は文字列又は文字列リスト。追加context/label字段を拒否する|
|通常slot|予定T以後の最初の有限・非後退時計のイベントを`time,line`へ結合する。BBO不正常でもその原行を飛ばさない。遅延は0〜30秒等号可。エンジンも最初の原行との一致を検査する|
|欠測slot|Tから30秒以内に対象時計がなければ、呼出し側は`time=T,line=None,ready=False,reason="判断時計欠測"`を渡す。後日の気配でなくTのタイマーとして分類する|
|新規条件|`side`は買い+1/売り−1/待ち0、`ready`はbool。新規時に実`role`順行/反転、有限正ATR、有限`5 <= D <= 125`が必要。Dはslot値を固定し、価格や追尾線のtick丸めはしない|

全入力は複製して扱う。通常のD/価格の呼値整合は主側で検査し、人工では非整数も認める。ここへ未来の125/250ラベルを渡さない。

## タイマーと同原行の処理

1. 原行前に到来した欠測枠・新規期限・独立強制タイマーを処理する。強制タイマーと欠測枠は同時計の原行より前、TTL等号は同時計の正常BBO約定を許す。
2. 正常BBOなら長気配間隔を検査し、既存建玉の実MFE/MAEを更新する。
3. 既存pendingが要求+1価格秒以後かつ要求原行より後なら約定する。
4. 新規fill当行も含め連続保護を行う。既存返済pending中は保護を更新しない。
5. その原行に結合されたslotを分類する。返済fill後の空きなら新規判断を許すが、その新規の同原行fillはない。

slotの分類優先は、**無効BBO/時計欠測で判定不能 → pendingで処理中 → 建玉があれば保有継続 → 空きのready不足で判定不能 → 空きのside0で待ち → 買い/売り要求**。保有中はfeature-readyを要求せず、無効BBOなら判定不能の行にも`holding=True`を残す。定時外に保護返済しても、次の予定枠まで新規判断を作らない。

新規要求は正常BBOの判断原行で発生し、+1秒/後原行から最初の正常BBO、TTL30秒等号までで約定する。期限超過・強制時刻で新規を取消し、同じ枠を取り直さない。返済にはTTLによる架空の約定を作らない。

強制要求は気配到来を待たず、固定15:35/05:50の独立タイマーで出す。出典行はその時点の最後の既知原行、fillは強制+1秒以後かつ後原行の正常BBO。既に返済pendingなら先の要求を維持する。終了前に返済できなければ未解消で、最終値を使って埋めない。

## 連続保護・現在正味益・費用

新規価格E、実方向s、現在正常返済BBOをm、`r=s*(m-E)`pt。初期`h=0`、`L=max(-125,-D)`。正常気配ごとに`h=max(0,h,r)`、`L=max(前L,-125,h-D)`とし、線を緩めない。

現在正味益`r*10−122 > 0`strictなら`arm=True`、以後`L=max(L,0)`。現在正味益の境界だけは`Decimal(str(mark))`と`Decimal(str(entry))`から比較し、12.2pt等号の浮動誤差で起動しない。r/h/Lは浮動値を保存し、任意epsilon・tick丸めを加えない。

`r <= L`で返済要求し、その後の**h/L/armを凍結**する。pending後の有利気配でarmを補完しない。一方、実保有の`mfe/mae`は返済fillのBBOを含めて別に測る。このためpending後に`mfe > h`となり得る。h−Dが正ならarm前でもL≥0になり得るため、保護線の位置と費用後正起動の旗を分ける。

固定250TPはない。125/250の新規後先着は主の別ラベルであり、運用は損失側の初期線・連続追尾・場末返済を使う。名目entry床は費用後同値や遅延後同値約定を保証しない。

micro1枚、10円/pt、手数料11円/片道。`pnl0 = s*(exit-entry)*10−22`、`pnl5=pnl0−100`、`pnl10=pnl0−200`。追加滑りは同じ約定への費用負荷で価格を変更せず、起動参照は常に5pt込み122円。Viewer約定の`fee_yen=61`は11+5pt×10の片道参照値で、別途価格へ滑りを足さない。

## 返り値と品質

|返り値|意味|
|---|---|
|`decisions`|予定枠ごと一件。元slotに`action/decision_reason/holding/pending_kind/position_id/wait/activity_valid`を追加。actionは買い新規要求/売り新規要求/待ち/保有継続/処理中/判定不能|
|`trades`、`fills`|Viewer標準の同じ約定片。`id/timestamp/type/position_id/price/qty/fee_yen/method_id/source_line`。時刻はJST ISO8601、typeはLongN/LongR/ShortN/ShortR|
|`closed`|完結一件ごと`slot_id/side/role`、`entry_time/line/price`、`entry_request_time/line`、`entry_atr/D/h/L/arm`、初起動`arm_time/line/r/net`、実`mfe/mae`、`exit_time/line/price`、`exit_request_time/line/reason`、`pnl0/5/10`。実際のキーは`exit_reason`|
|`orders`|entry/exit要求、要求時計/行、eligible_time、entryだけexpires、statusと約定/取消出典。one pendingを上書きしない|
|`trail`|定時判断・保護の変化・要求・約定・取消・強制の順序と現在state。変化しない全tickを重複保存しない|
|`final_state`|残position/pending/forced。残建玉を消去しない|
|`quality`|時計不正/後退・非正常BBO・空き/新規待機/保有中の長気配間隔、判定不能枠、損益注意理由、活動/全枠判定/損益確定の別旗|

正常気配の間隔が300秒を超え、**実建玉又は返済pending**をまたいだ場合だけ損益品質注意とする。空き時間・新規pendingを含む間隔は別診断。未解消建玉/返済pendingも損益確定不可。非正常行が存在するだけで全期間を不適格にはしない。

`metrics`は次を分ける。

- `主待ち率 = 待ち / 全予定枠`。保有継続・処理中を待ちにしない。
- `保守待ち率上限 = (待ち+判定不能) / 全予定枠`。この上限≤50%を活動適格とし、`全枠判定可能 = 判定不能0`は別旗。欠測を非待ちとして達成を増やさない。枠0は率None/適格False。
- `完結取引観測純額円`はclosedだけの0/5/10合計。
- `約定台帳観測確定円`は上記から未解消建玉の新規片道費用11/61/111円を引く。返済pendingもopen扱い。これは台帳上の費用計上で、全体結果の確定とは別。
- `全体確定対象円`は損益品質注意又は未解消があれば0/5/10すべてNone。観測額で空欄を埋めない。
