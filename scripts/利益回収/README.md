00010の再生は `比較.py --study work/利益回収/再現00010` を使う。先に同作業先へ正式計画をコピーする。条件は固定定義から生成され、入力は00008台帳のSHAを参照。正式結果の上書きと固定後の条件変更は拒否する。作業gzip保存名は共通なので再現を並列実行しない。新しい条件は新しい試行へ分ける。

上の診断・帳票の再生成は保存済みの取引・数値を使い、過去の未見性を復活させない。00009の未来峰を回収可能益とは呼ばず、00010の早期返済による新規集合の変化も同一取引の出口差と分ける。観測空白のある全体は確定収益にしない。
