# 定時履歴の学習：同一準備の15列対25列

作成・ローカルAPI確認：2026-11-06。実市場の学習・教師読取・運用はroot担当。この担当は固定51の学習処理を新規ファイルへ複写し、政策別の列数を明示した部分と人工検査だけを変更する。[固定51の学習仕様](../技法分岐学習/学習仕様.md)・コード・モデル・出力は変更しない。旧モジュールのglobalを書き換えて25列を通すこともしない。

## 比較範囲

| 候補 | 特徴 | 木 | 扱い |
| --- | --- | --- | --- |
| 旧Q1 | 51の15特徴 | 固定51の深さ4 | 同46場の保存対照。本学習部で再fitしない |
| C0 | 履歴共通準備に揃えた基礎15列 | 深さ4 | 新しく過去教師だけでfit |
| H0 | C0と同じ準備・教師pairの基礎15＋履歴10列 | 深さ4 | 同上 |

Q1→C0は履歴準備による訓練母集団の条件付け・評価の可用性・再fitを含む比較であり、単に旧Q1の結果をマスクした効果ではない。C0→H0は同じ準備・同じ両方向教師へ履歴情報を加える学習方針差。追加列は分割候補数も変えるので、特定の履歴列だけの因果効果や、独立した心理の票を実証したとしない。

原51と同じW20/W30/F40を維持する。過去20場→次10場、過去30場→次10場、過去40場→条件選択24場と既使用後続2場。両新候補で計6木、運用評価は46場で初期20場は学習専用。「学習」期間の表示は後半20場の時系列評価で、fit40場の一般化性能ではない。全66場は研究に既使用である。

## API

[学習.py](学習.py)の外部APIは51と同じ。

```python
fit(rows, feature_meta, policy, model_id, evaluation_start) -> dict
predict(model, vectors) -> dict
walk(model, values) -> (leaf_id, path)
```

政策は`C0/H0`。`C0`はmetadata・各特徴ベクトルが厳密に15列、`H0`は厳密に25列である。モデルの政策から列数を確定し、長い側を切り捨てたり短い側へ0を加えたりしない。

内部の`feature_metadata(meta, policy)`、`vector(values, count)`、`float32(values, count)`、`prepare_rows(rows, evaluation_start, count)`には政策又は列数を明示する。全nodeのfeature参照範囲もモデル政策に対応する。scikit-learn自体はfit時だけimportし、predict/walkは標準ライブラリのfloat32変換とJSON木走査で実行する。

## 特徴metadataと欠測

metadataは各`{id,name,method,family,scale}`で順序固定。F01..15は旧51の値・順・符号をそのまま保持する。familyはF01=`trend`、F02/F03=`osc`、F04=`vol`、F05..15=`price`。

追加10列は以下の契約。厳密な履歴抽出・窓・出典・当時可視性は履歴担当コードを正本とし、学習部で価格機械を再実装しない。

| 列 | 内容 | method | family/scale |
| --- | --- | --- | --- |
| F16/F21 | 自方向端/反対方向端の最終state | P06 | price / m03+m30 |
| F17/F22 | 同、外切替数 | P03 | 同上 |
| F18/F23 | 同、内切替数 | P09 | 同上 |
| F19/F24 | 同、最終切替符号 | P10 | 同上 |
| F20/F25 | 同、最終切替後足数/10 | P10 | 同上 |

買いは上端→下端、売りは下端→上端の順で後10列を配置する。既に方向に対応している履歴列へ学習部で追加のside乗算をしない。履歴の未発生0や最終切替なしage−1.0は、抽出側が準備済みと定義した正当な値であり欠測補完ではない。未知は別のready理由とし、rootがC0/H0共通で特徴pairから除外する。

予測の`vectors`は`{'1':list,'-1':list}`。両空listは未準備WAITで`scores/leafs=None`。片側だけ空、非有限値、政策と違う列数、float32桁あふれは拒否する。未発生を未知へ、未来の先着不足を当時の準備不可へ変換しない。

同一枠のC0/H0は基礎15列と教師・予定/実判断時計・原行が同一であることをroot/独立監査が結ぶ。H0の全特徴行指紋とC0の全特徴行指紋は列数が違うので一致を要求しない。教師ID・期間と、H0の先頭15列を射影した基礎値が対応することを確認する。

## 教師と固定条件

教師は固定49の同時計B+/B−。250=1、125/期限=0。未約定又は不足が一方でもあればpair全体を除外し、各側のoutcome/filled・ID・分類を保存する。未約定行のentry_time/entry_line欠落は許容する。片方向だけの追加は禁止し、使用方向行は各0.5重みで一枠の重みは1。

全入力教師は`end_time < evaluation_start`。同秒は前原行でも拒否し、除外pairも未来ラベルなら入力を拒否する。入力・使用方向行・ID・期間の指紋を保存する。特徴readyの除外と教師不明のpair除外は別件数である。

| 項目 | C0/H0共通 |
| --- | --- |
| classifier | DecisionTreeClassifier、gini、best |
| 最大深さ/乱数 | 4 / random_state=51 |
| 葉方向行数 | min_samples_leaf=60 |
| その他 | min_samples_split=2、min_weight_fraction_leaf=0、max_features=None、max_leaf_nodes=None、min_impurity_decrease=0 |
| 重み/剪定 | 各方向0.5、class_weight=None、ccp_alpha=0、monotonic_cst=None |
| 環境 | Python3.14、scikit-learn1.9.1、NumPy2.5.3、SciPy1.18.1 |
| 数値 | 特徴float32、教師整数、重みfloat64 |

scoreがstrictに高い側だけを候補にする。同点はWAIT。勝側score>=1/3、葉ユニーク枠60/日6/場10以上、pathのfamilyが2種類以上かつtrend又はoscを含むことを要求する。勝側不適格なら次点へ逃がさず、低い側のraw scoreも0に置き換えない。追加履歴10列はすべてprice familyであり、履歴専用familyを新設してこの条件を緩めない。score下限は探索用で、費用分岐点ではない。

15列C0を同じ行順・同じ教師・同じmetadataでfitした場合は、固定51Q1と全node・葉・scoreが一致する。履歴準備で実際の行集合が変わる場合まで、保存51Q1との全木同値を要求する意味ではない。

## JSONと予測

JSON schemaは51の全node・training構造を保持する。`policy`と`rules`の政策深さ/政策特徴数、モデルID・出典SHA等は新52を示す。

- トップ：schema_version/model_id/policy/feature_meta/feature_meta_sha256/parameters/rules/versions/source_sha256/training/nodes/interpretation。
- 全node：feature/threshold/children、根からのpath、方向行・0.5重み・成功率、ユニーク枠/日/場、method/family、支持旗、所属ID指紋、gini。
- training：入力/使用pair、除外方向結果、使用ID、入力/使用行と期間指紋、評価開始より過去の最大終了key。
- predict返り値：scores/leafs/side/winner_side/reason/eligibility。両方向のraw値と各gateを残す。

予測時は元floatを先にfloat32へ写してから左`<=`・右`>`をたどる。閾値へepsilonや表示丸めを足さない。fit内部で全使用方向行のJSON葉と確率をscikit-learnのapply/predict_probaと照合する。joblib/pickleを保存しない。これはJSON展開の接続検査であり、最適分岐の別算法による独立再学習ではない。

新規/保有/pending、説明上の順行/反転、全予定枠活動、固定O49の損失/利益追尾・122円strict起動・費用0/5/10はroot主と既存運用の責任で、学習部へ新しい価格ゲートや出口を加えない。

[学習の人工検査.py](学習の人工検査.py)は固定51の人工factoryを読み、返り値の新規辞書だけを使う。旧モジュールの大域値やファイルを変更しない。実相場や本物教師は開かない。


この人工の方向交換は同一JSON木に対する予測対称性の確認である。実OHLCの反射・上端下端交換から履歴10列が同値になることは履歴側人工が別に担当する。人工fitだけで本物の学習・運用・採用判定を代用しない。
