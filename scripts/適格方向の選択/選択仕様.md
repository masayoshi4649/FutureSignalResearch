# 全資格を満たす方向から障壁scoreで選ぶ

作成日：2026-11-06。66の純選択仕様。固定65 U0の3保存木／3回収calと同じ60特徴を使う。新fit0、新特徴0、新しい教師・回収再集計0。実装担当の確認は手作り人工のみで、本物66の採否や損益を見て条件を変更しない。

## 一つだけ変える順序

[65学習](../現在状態と量価格/学習.py)は、両方向の障壁scoreの元最高側を先に決め、その側だけへscore下限・葉支持・複数技法を要求する。[旧R55予測](../独立追尾回収/回収集計.py)は、同じ側へ回収支持と、正回収候補だけに過去主回収strict正も加える。元最高側が不適格でも、下位側へ救済しない。

66は、この**資格と順位の順序**を変える。同点・片側未知・両空は旧WAITを保った上で、既知の両側に全資格を判定し、その適格側のうち障壁scoreが高い側を選ぶ。回収平均そのものによる順位、次点への閾値緩和、支持の軽減を加えない。

|新候補|旧予測reference|各側へ要求する資格|
|---|---|---|
|E0|R55.predictのC0（65 U0に対応）|score・葉支持・複数技法・回収支持|
|E1|R55.predictのR0（65 U1に対応）|E0の資格＋過去主回収strict正|

旧U0／U1は保存対照。対応する旧Uで採用した純方向は新Eでも同方向のまま残る。一方、**E1はE0の同方向部分集合である必要はない**。E0の選択側が過去回収非正なら、E1はもう一方の全資格適格側を選び得る。このためE1をE0の単純間引きとは呼ばない。

## APIと責任分界

```python
predict(model, calibration, vectors, learner, policy) -> dict
```

- modelは該当phaseの固定65 U0木、calibrationは同じmodel_idの固定回収集計。
- vectorsは当時の両方向60特徴、又は両空。learnerは固定65の純predictを持つmodule等。policyはE0／E1。
- 新選択は固定R55.predictを最初に一度呼ぶ。旧globalや入力を変更しない。
- model／calの保存SHA、対応phase、過去教師の終了境界、当時の特徴準備は主・保存監査の責務。選択.pyは実データや保存モデルを自分で取得しない。
- DIraw0の最終WAIT、実role、予定枠の時計、O49の一建玉と約定・連続保護・費用・活動条件は呼出し側の従来規約。新選択ではDI同値を救済しない。

依存はstdlibと固定R55の予測純関数だけ。sklearn・joblib・学習APIを呼ばない。公開定数はPOLICIES、REFERENCE_POLICIES、RULES、REFERENCE_PATHである。

## 両方向の資格

各側のscore／葉ID／従来eligibilityは、旧learnerが作ったreference.priorをそのまま読む。葉支持・複数技法の基準を作り直さず、回収支持と正額は保存calのboolを使う。

|資格|維持する定義|
|---|---|
|score|250先着score>=1/3、等号可。旧boolと下限の一致を検査|
|葉支持|unique枠>=60、日>=6、場>=10。旧eligibilityのleaf_support|
|複数技法|異種family2以上、trend又はoscを含む。旧method_support|
|回収支持|固定calのsupport。旧60枠／6日／10場の集計を再用|
|E1の正回収|固定calのpositive。主費用pnl5のDecimal合計strict正|

回収positiveは表示float平均を `>0` で再判定しない。保存boolはDecimal正額に由来し、丸め零・小さい正負へ新epsilonを置かない。E0では回収平均が負でも、他の全資格が適格なら選び得る。E1では同じ方向を正回収で除き、他側の資格が揃えば方向を変え得る。

学習葉のscore未知と、学習葉は既知だがcal回収支持が不足することを区別する。前者は片側でも全体WAIT。後者は、その方向の不適格理由となり他側を検討できる。

## 先行WAITと選択

1. 両vectors空は特徴未準備WAIT。
2. 片側でもscore=Noneは未学習枝WAIT。既知側が適格でも解除しない。
3. raw両側scoreが同点なら同点WAIT。片側だけ適格でも同点を解消しない。
4. 上記以外で両側の全資格適格を確認し、適格側をscore降順へ並べる。
5. 適格側なしなら両方向不適格WAIT。元最高側が適格なら従来側、元最高側が不適格で他側だけ適格なら他方向を採用する。

資格判定を一つの最終理由だけで省略しない。score／葉／技法／回収支持／正額の不足を両側とも保存する。高いscore側が1/3未満なら、より低い側も同じ下限未満なので、score下限だけを理由とする下位救済は成立しない。技法・葉支持・回収支持・正額の差は、下位救済の理由になり得る。

同じscoreでも高い回収平均で順序を付ける処理、適格側がない場合の下限引下げ、未知をscore0へ置く処理はない。

## 返却辞書

互換欄は次を保持する。

```text
side / reason / prior
recovery_leaf / recovery_support / recovery_mean5
```

priorは旧reference.priorの深い写しであり、元最高側や旧採否を書き換えない。新選択側は外側sideとselected_sideに記す。採用時のrecovery欄は新たに選択した葉の値、WAIT時はreferenceの値をそのまま残す。したがってWAITでも、旧最高側の回収欄がNoneとは限らない。両側の詳細はdirection_eligibilityを読む。

追加欄は次のとおり。

```text
policy                      E0 / E1
reference_policy            C0 / R0
reference                   旧R55.predictの全返却dictの深い写し
original_winner_side        元raw最高側（先行WAITでは0）
selected_side               新選択側（WAITは0）
rescued                     新side!=0 かつ元raw最高側と異なる
rescue_reasons              元最高側の全不適格理由（救済なしは空list）
direction_eligibility       '1' / '-1' の資格辞書
eligible_sides              全資格適格側のscore降順list
ranking_block_reason        先行WAIT理由又はNone
```

eligible_sidesは先行WAIT時にも説明用に残す。同点の表示順は1／−1だが、採用は必ずWAITであり、この表示順を売買の優先にしない。rescuedはこの予測段階の旗で、後段DIraw0によるWAIT後の純採用救済や、保有占有後の実新規救済と同じ件数ではない。

各direction_eligibilityのフィールドは次のとおり。

```text
known / leaf / score_value
score / leaf_support / method_support / families
recovery_support / recovery_positive / recovery_mean5
eligible / reasons
```

score_valueはraw率、scoreは下限資格bool。未知側はknown=False、eligible=False、その他の未知値はNone。reasonsは次の順序で重複を隠さず保存する。

```text
score下限未達 / 葉支持不足 / 複数技法不足 / 回収支持不足
E1のみ：過去回収平均非正（表示平均Noneの場合は過去回収平均未知）
未知葉：未学習葉 / 両空：特徴未準備
```

外側reasonは次のliteral。

```text
通常採用                採用
他側救済                適格な他方向を採用
両側不適格              両方向不適格WAIT
先行WAIT                特徴未準備WAIT / 未学習枝WAIT / 同点WAIT
```

model／calのmodel_id不一致、既知葉の回収集計欠落、scoreや資格bool・回収平均の不正は拒否する。不正な保存値を未知や0へ補完しない。
