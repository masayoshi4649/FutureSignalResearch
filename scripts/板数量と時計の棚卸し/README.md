# 板数量と時計の棚卸し

確認日：2026-11-18。金融候補の選択・変更を行わない、原板と純特徴の品質調査。

[棚卸し.py](棚卸し.py)は、[194の恒久入力](../../inputs/00194_20261116夜と1117昼の固定適用入力/README.md)が参照する2026-11-16ナイト・11-17デイのNK225/TOPIX原板、計4ファイルを全行読み、数量フィールド・時計・保存済み判断原行との対応を調べる。[観測結果.json](観測結果.json)に入力とSourceのSHA、全件集計、少数の照合例を残す。原板は複製しない。判断時点をq0と表記する。

金融台帳、先着判定、IFD結果、損益、次の価格方向は読まない。計算する値は当時までの板不均衡と旧数量式の可用性のみ。新しい売買条件や試行番号は作らない。

## 何を再利用するか

[旧数量の独立照合](../FAR5分枠の技法判定の監査/数量の独立照合.py)の`OFI30`、`E08`、`parse_clock`を使用する。旧Native、Actor、保存済み損益は読まない。旧式の集計単位や不足判定は変更しない。NK/TOPIXとも原行順に、場内・非後退の現値時計かつLast正値の行を投入する。

- 旧OFI30は、隣接板の正規化OFIを現値時計上の窓で平均する。論文の未正規化OFI合計とも、実受信時刻30秒のOFIとも異なる。
- E08は、現値時計差60秒以内の8回の最良価格遷移を基準に、同価格での補充・減少を集計する。数量変化8回という意味ではない。
- q0はNKの純特徴1,014件、TOPIXの直接形成した純特徴907件を別々に使用する。両商品で等間隔・同一母集団の時計を揃えた比較ではない。
- NKではq0の現値・時計・物理原行を照合する。TOPIXの`close`は公表済み足終値なので、原行の`CurrentPrice`との一致を強制しない。原行と時計を照合し、終値との差を件数で記録する。
- q0原行を超える行を過去窓へ取り込まない。同じ現値時計でも後の原行を逆流させない。

## 再実行

既存のローカル環境では、リポジトリ直下から以下を実行する。結果JSONは再生成される。

```powershell
& 'work/複合テクニカル学習環境/Scripts/python.exe' -X utf8 'scripts/板数量と時計の棚卸し/棚卸し.py'
```

実行時はCPython 3.14.3、`orjson==3.13.0`。別環境は同版を`python -m pip install orjson==3.13.0`で用意して実行する。コードは既存の`work/pythonlibs`も探索するが、そのフォルダは必須ではなく、通常のPython環境に導入したorjsonでもよい。旧監査Sourceは恒久保存された`scripts/`内を参照する。

原板パスは194入力票の絶対パスを読む。配置を変更した場合は入力票の参照先を保つ必要がある。入力票・純特徴の再生成や過去全期間の板量品質を検証したという意味ではない。一般化する前に旧期間でも同じ棚卸しを行う。

設計への含意は[板数量を価格時計と分けて入口へ使う](../../docs/technical-analysis/市場心理/板数量を価格時計と分けて入口へ使う.md)を参照。
