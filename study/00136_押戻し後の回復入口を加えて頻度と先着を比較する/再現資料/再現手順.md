# 136の再現手順

136は非金融同体試行である。F0固定→全73場Source一走査→旧79/全方向同体確認→保存lifecycle原因診断まで実施し、新金融F1・正逆Raw再走査・金融集計・CSVは作成しなかった。Source engineは133へE1を追加した版1、正式番号は136。[結果と限界](../結果と限界.md)。

## 原文と共有源

[F0原本](../検査/F0.json)はSHA`3fe3ceae426787b689145fd7aa7730b4bc27ea1dfbb918c93f3d66eb463211ba`、直接63源を記録する。[全12MDの原文](../検査/実行前文書_F0.json.gz)は正式4MDを含み、結果編集前にF0へ照合して退避した。条件・E1状態定義・全504設定セルは不変。

[保管索引](../保管索引.json)の追加F0資料ZIPは47源。旧Sourceの13Goは133の[共有ZIP](../../00133_全場参加を維持して強い入口の探索期限を延ばす/再現資料/133固定コード.zip)から復元先だけを写像して使う。118/121の共有依存10源は、F0内の独立確認JSONが持つ間接指紋を同じZIPへ照合した。F0直接63源に後から追加したとは扱わない。

177,709,174 bytesの共用122入力と3,993,600 bytesの元実行体は恒久複製しない。F0記載のexe SHAは`824303bc64124931b026ec03ef25cea01730bfa620b7e20156b0bfa833fd6fd1`。旧133Sourceも既存gzipを参照し、二重保存しない。

[新Source](../../../inputs/00136_E1のSource接続/README.md)だけ一度gzip保存した。解凍SHA`f777aa32ab145bf5b9ba570b06244ec071fb40356eff67efce55137ba197b6c2`、4,836,317 bytes。保存gzip408,361 bytes。[非金融確認](../検査/Source非金融の確認.json)は`006e38a423d2bdb68167e1f5803f1ba46fed7a9ad23b0911f23ed48699dd23e3`、[全方向同体](../検査/全方向同体の確認.json)は`f6d9a5c43202d625b1e88facb298df28dcd17c5e2582d9e3bb4952ff824d1b0e`。

## 保存Sourceだけで確認する

Python標準ライブラリで、リポジトリルートから未作成のworkへ復元する。

```powershell
python -X utf8 "study/00136_押戻し後の回復入口を加えて頻度と先着を比較する/再現資料/F0資料を復元する.py" --destination work/136再現 --with-source
python -X utf8 "study/00136_押戻し後の回復入口を加えて頻度と先着を比較する/再現資料/保管を確認する.py" --restored work/136再現 --output work/136保管の確認.json
```

F0直接61/63源と共有依存10源を元SHAへ戻し、MD12原文と全504セルを照合する。未複製の2源は上記177MB入力と元exe。元F0はbytes同体で保持し、新しい事前F0/F1や写像した監査記録を作ったことにしない。

確認コードは保存Sourceから旧73sceneの全値、C0/S0/A0の全参照、79取得/73場、1取得68場/2取得4場/3取得1場を照合する。先着や損益を再計算しない。旧C0の成績は既報の継承参照であり、新しい136集計JSONやCSVを作らない。[元の閲覧CSV](../../../outputs/01a1889f-f2af-7943-a047-543275ee9ed2/135公表差CSV/README.md)はC0列を使う。

実復元では保存コードだけからGo1.24.2でビルドできた。[復元/ビルド確認](../検査/F0保存資料の復元確認.json)。ビルドした実行体は作業用であり、元F0のexeと同体と主張せず、Sourceの再起動や自然走査には用いていない。

## 原因診断の再現

[原因資料](../根拠/原因資料.md)はSourceのlifecycle/statsだけを使用した。[後発ZIP](確認と保管の追補.zip)から復元される診断コードを、保存Sourceのある新workで実行する。

```powershell
python -X utf8 "work/136再現/work/136順次確認が出生しない原因/診断する.py"
```

同名出力がまだない作業先を使う。原診断のSource前後SHAはf777aa…、コードSHAは`3f6aee02d455dd5bea31c252de2ca9f17d897a148e0b7e1807cb57fe123514c4`。[診断確認](../根拠/原因診断の確認.json)に3出力のSHAを残し、全34改善・回復3例・集約を照合できる。自然Raw/CSV/既存取得列/金融は読まない。時計上可能な4件を新入口数として計算しない。

## Source一走査から再現する場合

これは保存結果の確認とは別の、原板を読む手順である。現在の保管確認では実行していない。共用122入力はSHA`6a6cd13dfd00c9669b522e3c3c8e06a4066766f6075786f64d8c0feeb45513ec`、[122の生成手順](../../00122_E0固定条件を全セッションで検証する/再現資料/再現手順.md)を参照し、同体の既存入力を共用する。原板・177MB派生入力を136用に恒久複製しない。

復元した`work/押戻し回復をSourceへ接続する/Source再生器`で`go build -o E1再現用.exe ./cmd/e1source`。未作成の出力先へ次を指定する。

```powershell
E1再現用.exe --input <共用122入力> --expected-sha 6a6cd13dfd00c9669b522e3c3c8e06a4066766f6075786f64d8c0feeb45513ec --output <新Source出力> --workers 8 --execute-after-f0
```

元の段階scriptとF0は当時の絶対パス/MD/実行体を検査する履歴で、別作業先へそのまま実行するものではない。再実行する際の実際のコード・入力・新規出力を別に記録し、歴史上のF0を上書き・再発行しない。今回の再現保管ではSourceを再起動していない。

新Sourceのlegacyを旧133の全73scene・全79取得と照合し、差があれば旧正本を置き換えず止める。A0は旧全取得＋全適格E1、S0は最初1補完であることを維持する。同原行は旧C0優先、E1の方向はpatternで、T8値を捏造しない。逆注文の適格性・実mini板・10枚口座・追尾・新期間の性能は本非金融試行の証明範囲外である。

保存Sourceからの実再現では、診断確認票と3出力が全SHA同体となった。[原因再現の確認](../検査/保存Sourceからの原因再現.json)。Source/Raw再走査や新しい先着・損益の計算は行っていない。
