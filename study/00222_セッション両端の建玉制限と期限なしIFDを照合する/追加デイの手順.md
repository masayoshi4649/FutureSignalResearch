# 新しい日経デイへ開始20分・30分の4候補を適用する

追加日の入口は日経199_02、予約・建玉の上限は買売共用1枚。08:45から20分または30分はノーポジションとし、その間の要求は予約に入れない。開始前の市場データは指標計算に使う。全ての建玉で幅±1Rの両注文を維持し、15:29に場末返済を要求して15:30までに全決済する。**取得後の経過時間による強制返済は設けない。** I20・I30は固定両注文、T20・T30は同じ設定に終盤の可変追尾を加えたもの。[全閾値](設定と結果.md)・[固定候補と照合用指紋](追加デイの固定条件.json)

## 実行

新しいデイの[固定199_02入力を準備](../00216_十一月二十日の固定入口と寄り前の反例を検証する/日経/README.md)する。母集団フォルダは「固定取得入力.json.gz」「当時特徴.json.gz」を含み、純入口NPZ・板索引はそのデイと同じ入力を参照するものを指定する。依存する研究部品の復元は[219の再現手順](../00219_日経199デイの利益保護と出口条件を比較する/再現手順.md)を参照。

以下は既使用の11月18〜20日での照合例。追加日を計算する場合は、母集団・純入口・板索引と場名を新しいデイに替え、`--既使用照合` を外す。複数のデイをまとめて指定できる。出力先には新しいフォルダ名を指定する。

```powershell
$py = 'work/複合テクニカル学習環境/Scripts/python.exe'
$worker = (Get-Item 'study/00222*/追加デイへ適用する.py').FullName
$dest = Join-Path work ('222日経デイ_' + (Get-Date -Format 'yyyyMMdd_HHmmss_fff'))
& $py -X utf8 $worker --母集団 'work/216日経/母集団' --純入口 'work/216日経/純入口.npz' --板索引 'work/216日経/前史十場と追加二場の索引参照.json' --場 '2026-11-18_Day' '2026-11-19_Day' '2026-11-20_Day' --既使用照合 --出力 $dest
```

出力フォルダの `I20_デイ.csv`、`I30_デイ.csv`、`T20_デイ.csv`、`T30_デイ.csv` は1候補1表。取引のなかった日も1行残し、利益・損失・収支、建玉回数、不明件数、対象時間と保有率を記録する。累計は今回指定した期間の初日を起点とする。返済不明を含む日の確定収支と、それ以降の確定累計は空欄とする。`再生元帳.json` は入力指紋と各候補の新規・決済原行、待機中に除いた予約件数を収録する。

## 照合結果

2026年11月22日に既使用3日を追加日用の経路で再生した。各候補の建玉11件、4候補合計44件で、45日版の同日元帳と取引順・取得／決済日時・価格・費用・追尾履歴を含む全項目が一致した。12日次行の利益・損失・収支・回数・対象／保有秒・保有率も照合した。

|対象日|各候補の建玉|各候補の費用後収支|
|---|---:|---:|
|2026-11-18|4|−33,308円|
|2026-11-19|4|＋1,692円|
|2026-11-20|3|＋31,769円|
|3日計|11|＋153円|

上の3日では4条件の収支が同じになり、総利益134,615円・総損失134,462円、決済不明0件だった。また、45日版の8候補すべてを場ごとの共通関数で再生し、変更前後の建玉元帳・日別期間集計・予約照合の各JSONがバイト単位で一致した。
