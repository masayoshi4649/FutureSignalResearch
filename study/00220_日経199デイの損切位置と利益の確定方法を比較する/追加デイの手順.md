# 次の日経デイへの固定適用

2026-11-22。元IFD、B400P3（W31の損幅に400pt上限・午後利確指値＋可変追尾）、B400P4（同じ損切と追尾、利確指値なし）、S3P3（B400P3の損切上限を外す）を固定した。元の利確幅はR、費用はmini換算1枚につき往復1,077円。全出口定義と使用する219・217・213等の再生部品に対し、改行をLFに揃えたSHA256を保存した。[固定条件・基準元帳の指紋](追加デイの固定条件.json)

1. [元入口の入力生成](../00216_十一月二十日の固定入口と寄り前の反例を検証する/日経/README.md)と同じ要領で、対象日の日経の母集団（固定取得入力・当時特徴）、199_02の純入口NPZ、その日を含む原板索引manifestを用意する。旧部品の復元元は[219の再現資料](../00219_日経199デイの利益保護と出口条件を比較する/再現手順.md)に記載した。
2. リポジトリ直下から、下記の `--母集団`、`--純入口`、`--板索引`、`--場` を追加日に合わせ、`--既使用照合` を外して実行する。場名は `YYYY-MM-DD_Day`。複数日をまとめて指定できる。新規の出力先を使う。
3. JSONの「口座再生」は元の全要求から、候補ごとに予約と保有が一度に1枚以下となるよう再生した成績。「入口固定」は元IFDがその日に得た取得を全ての出口で独立に評価している。不明は空欄相当のnull。以後の追加日は、費用後利益・損失・収支、保有枠と取引の入れ替わり、赤字日・未知を同じ窓で比較する。

## 既使用日の照合

以下は独立の追加データではなく、既使用の11月18〜20日の再現コマンド。45日の全元帳からこの3日を取り出した基準に、**4候補×2モード×3日が取引順・全項目で一致**した。手法別の新規・返済原行と時刻・費用・各建玉の保護起動・極値を含む。

```powershell
$taskFile = (Get-ChildItem 'study/00220*/追加デイへ適用.py').FullName
$destFile = Join-Path 'work' ('220照合_' + (Get-Date -Format 'yyyyMMdd_HHmmss_fff') + '.json')
python -X utf8 $taskFile --母集団 'work/216日経/母集団' --純入口 'work/216日経/純入口.npz' --板索引 'work/216日経/前史十場と追加二場の索引参照.json' --場 '2026-11-18_Day' '2026-11-19_Day' '2026-11-20_Day' --既使用照合 --出力 $destFile
```
