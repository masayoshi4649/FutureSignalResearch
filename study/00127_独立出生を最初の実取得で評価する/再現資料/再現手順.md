# 127の再現手順

2026-11-11。最短の金融再現は保存した650出生入力からRawを再生する。公表出生を作り直す段階とは分ける。正式保管では金融を再実行せず、原板・177.7MBの共用公表Inputを複製していない。

## 固定と実行コード

[F1](../検査/F1.json) SHA256は`5f4b809e22745072da22d6429bb95290d94c398c2a44fcd4ce8ea40e4f0bc061`。コード17点・入力2点・原文4点・当時実行物を固定し、[再生完了](../検査/再生完了.json)と[段階完了](../検査/段階実行完了.json)が前後同体を記録する。

[127コードZIP](127コード.zip)と[復元索引](コード復元索引.json)にF1の新規16コード、CSV出力/再読、保存器を保管した。ZIPのサイズ/SHAと全entryの復元先・サイズ・SHA・CRCは索引を正本とする。共通124集計1点は[124コードZIP](../../00124_逆行の原因と売買反転を同じ入口で検証する/再現資料/124コード.zip)から`work/124入口の原因分析/集計する.py`へ戻す。SHA256 `8479ca348231ffd77a637360797750833c9e6617c7fc4a6502e015c7a1d9f04a`。旧共通コードを変更しない。

実行前のREADME/設定/集計条件/v4条件は[原文gzip](../検査/実行前文書.json.gz)へ結果更新前に保存した。12,659B、SHA256 `5a56700a34e9e43cf3ca46768a9d5cc05758b07b28aa5766b8d6a9fbdf9e6bd2`、解凍43,544B・SHA256 `f7e22732d7c27b7cc84d0893b6bbd59310b2b6dd920c52e852d75a4e97b52e8e`。4 entryの`utf8_text.encode('utf-8')`で全bytesと指紋を復元する。現文書を上書きしない新規再現ツリーで扱う。

F1の絶対pathと当時実行物SHAは新環境へ自動変換されない。移設やRawpath変更は別の入力・固定記録にし、旧F1を改変しない。下記の直接CLIを実行したことだけで、当時の全F1検査まで自動的に再現したとはしない。

## 最短のRaw再生

[共用入力一覧](../../../inputs/00127_独立出生/README.md)から`入力.json.gz`を`work/127独立出生の評価/入力.json`へ解凍する。4,461,240B、SHA256 `b8f382b90f345c4e2c7085ad743c95bbfd887e0cb36ec1f704f848b148bc4e85`。全73場・650events・minimum_risk10・期待Raw品質を含む。RawはこのInputの指紋付き既存参照を使い、勝手に別データへ置換しない。gzip/plainはmagicで判定される。

Go1.24.2で、新規の再現作業ツリーを使う。自然再生前に人工を実行する。元のF1実行物を上書きしない。

```powershell
Push-Location work/独立出生の再生器
go test -count=1 ./...
go vet ./...
go build -o 独立出生の再生.exe ./cmd/run
Pop-Location
& work/独立出生の再生器/独立出生の再生.exe --input work/127独立出生の評価/入力.json --sha256 b8f382b90f345c4e2c7085ad743c95bbfd887e0cb36ec1f704f848b148bc4e85 --output work/127独立出生の評価/全73場の独立出生結果.json --workers 8
```

当時exe SHA256は`fb8370534f4d9c6f5a829aac4b4cfa81e97431f88bb076c2f840fa47b40feaaf`。異なるビルド環境で実行物が同一になるとは仮定せず、コード・環境と出力値を照合する。[最小risk追加後の人工9主/vet/build](../検査/再生器の人工検査.json)も保存した。

Rawを再読せず集計だけを再現する場合、[保存した再生結果gzip](../成果物/全73場の独立出生結果.json.gz)を同じ結果pathへ戻す。圧縮823,969B・SHA256 `5997f4d9e33344b1d362fd14ffc63f16a3ff45123ccf0a4cac0c03099ca5838f`、解凍10,545,201B・SHA256 `ca45bd682152963c6f1e0fca72161e5cb77fc51e096d61fb2854e00e1ba58ecb`。

## F0選択と集計

[集計条件](../根拠/集計条件.md)のF0を変更しない。最初の取得Raw→同Raw R/T/S/Q→最小保存risk→両side同riskは当Raw見送り→同sideはID順。損益や未来の候補で先着を交換しない。FRは同じF0の実逆側を選ぶ反実仮想、A0と各mode先頭は診断である。

```powershell
python -X utf8 work/127独立出生の集計/人工検査.py
python -X utf8 work/127独立出生の集計/集計する.py --result work/127独立出生の評価/全73場の独立出生結果.json --sha256 ca45bd682152963c6f1e0fca72161e5cb77fc51e096d61fb2854e00e1ba58ecb --input-sha256 b8f382b90f345c4e2c7085ad743c95bbfd887e0cb36ec1f704f848b148bc4e85
```

Python3.14.3の標準ライブラリを使う。新規先へ`集計.json`、全650出生と選択経過の台帳、CSV用表を生成する。台帳はSourceEvent全文とRequest/Evaluation/Entryを残すが、元正本の金融outcomesを全転記しない。

集計SHA256は`5e080bcfd6b20f6175aeec7c1a141a0e2ce445493674125a33b92050ce8bf9d7`、表SHA256は`1496cb1a1528c449d54baa07a892c4a5e3529800442603e0f09ddafc6353f939`。集計は[圧縮正本](../成果物/集計.json.gz)（13,750B・圧縮SHA256 `ec06442d3f56e76c95f8c010cf47b2a4304fe30cb0e7709a4ea5af76bc078ba9`）と照合する。台帳・巨大表JSONは再生成可能なので重複保存しない。

## 出生由来を再生成する場合

[公表出生v4コードZIP](公表出生v4コード.zip)はF1のRaw再生コードとは別の出自。[出生コード索引](公表出生コード復元索引.json)に最終Go6点、schema転記、固定検証用の準備/診断コードとSHAを残した。v1〜v3のGo一式を重複保存していない。

旧118Bankは[118コードZIP](../../00118_指値待機と複数技法の取得確認で入口を比較する/再現資料/118コード.zip)から`work/118複数技法の入口条件/`へ戻し、索引の固定4ファイルSHAを確認する。177,709,174Bの共用Input（SHA256 `6a6cd13dfd00c9669b522e3c3c8e06a4066766f6075786f64d8c0feeb45513ec`）は[122再現手順](../../00122_E0固定条件を全セッションで検証する/再現資料/再現手順.md)から旧118入力と新3公表を結合し、`work/122全場入力/入力.json`へ戻す。

## 独立数値検算と事後診断

コードZIPには`work/127独立検算と未取得診断/独立集計する.py`、`当時特徴を診断する.py`、短報原文も追補した。F1外の検算コードであり、金融条件を変更するものではない。自作Fraction算術の補助は[124追補ZIP](../../00124_逆行の原因と売買反転を同じ入口で検証する/再現資料/検算と保存の追補コード.zip)から`work/124正逆の独立検算/検算する.py`へ復元する。SHA256は索引の`external_independent124`と照合する。

独立集計には保存結果・650入力・集計を元work名へ戻す。追加の当時特徴診断には、さらに旧122の177MB公表Inputを共用して参照する。金融再生又はRaw再走査はしない。新規proof先で実行する。

```powershell
python -X utf8 work/127独立検算と未取得診断/独立集計する.py
python -X utf8 work/127独立検算と未取得診断/当時特徴を診断する.py
```

[独立proof](../検査/独立検算.json) SHA256は`38ad9679907a4813387374ae1ad8129d1a187c98ee64b975e0dec09612542c4b`。650票/164取得・140組3,360値・政策ID/coverageを確認した。診断JSONは[圧縮正本](../成果物/未取得と当時特徴の診断.json.gz)に86,283Bで保存し、解凍SHA256 `c5cb6c5622f2a54f0147bc682149a5bf078e7579a74f59486aeddb21a97d0930`へ照合する。Raw先着最初性の再走査・bootstrap区間の再実装・実IFD約定確認は、この独立検算にも含めない。

Rootの結果後依頼によるQの[EMA側切替](../成果物/QのEMA側切替の追補.json.gz)・[レンジ余地](../成果物/Qのレンジ余地の追補.json.gz)の2追補は小型gzipで保管し、同じコードZIPへ追補器2点を入れた。[追補完了](../検査/Q事後追補の完了.json)に元SHAを残す。診断JSONを元work名へ解凍して実行する派生診断で、旧127の出生/取得/集計を変更せず、逆注文のcap/risk又は128の金融を再生しない。
