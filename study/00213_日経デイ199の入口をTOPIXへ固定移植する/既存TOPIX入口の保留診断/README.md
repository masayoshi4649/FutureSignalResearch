# TOPIX既存デイ入口で日経の保留条件が発生するか

日経199_02の保留は、注文方向と逆の5分DI差が正であることを必要とする。TOPIX旧D4は、主入口の押し戻しと量不明時の補完がともに、注文方向への5分DI支持を要求する。210主3はこの旧D4の一部を見送る。両判定にTOPIX184直接形成の同じ5分足を使うと、この必要符号は両立しない。

旧83場のうち42デイ、14,674判断を照合した。D4は2,450判断、210主3は2,383判断で注文方向が生じた。その全件に対応する公表時点の5分DI差があり、売買方向を掛けた値の最小はどちらも+0.01512825。保留の必要符号を満たす判断は両案とも0件。直接特徴がないデイ7判断では、いずれの案も注文方向が生じなかった。

日経の保留だけをTOPIX既存入口に付けても、この共通の5分足を用いる限り、保留機構の開始や保留中補完の抑制は生じない。日経の入口全体をTOPIX上で再構築した場合や、両判定で別々の足を使った場合は別の比較になる。

## 正本と再現

- TOPIXの照合入力と指紋は試行210の[入力台帳](../../../inputs/00210_TOPIXデイの背景矛盾と成熟待ちの純入口/入力台帳.json)。使用した3資源の指紋は[照合結果](照合結果.json)にも記録した。
- TOPIX既存入口の根拠は試行210の[Source](../../00210_TOPIXデイの長期矛盾と押戻し成熟を比較する/Source.zip)に含まれる「入口186.py」の `pressure` / `p0`、「入口189.py」の量不明補完、「入口210.py」の役割A見送り。
- 日経側は試行195の[Source](../../00195_保留中の補完入口を技術根拠で判別する/Source.zip)の「rules195.py」で `arrays[1-side]` を「rules193.py」の `_risk` に渡す。R1の5分DI差はこの反対側で厳密に正である必要がある。
- リポジトリ直下で `python study/00213_日経デイ199の入口をTOPIXへ固定移植する/既存TOPIX入口の保留診断/同じ五分足で必要符号を照合する.py` を実行する。標準ライブラリのみ。注文要求数は保有・予約の制約を適用する前の値。
