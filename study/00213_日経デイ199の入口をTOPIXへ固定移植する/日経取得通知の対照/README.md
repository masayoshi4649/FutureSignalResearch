# 日経199_02の建玉取得を通知としてTOPIXで売買する

2026-11-19。日経199_02が実際に建てた時刻と方向に、TOPIXでも売買機会が残っていたかを調べた。両指数の同じデイ42場を使用した。TOPIXのチャートから独立に入口を決める成績は[試行213の主比較](../README.md)に記した。

## 結果

日経からの162通知のうち、TOPIXで127件を取得し40/42場に参加した。33件はTOPIX側が既に保有、1件は事前の板が60秒以内になく、1件は30秒以内の取得が成立しなかった。取得なしは9月21日と23日。対象全時間に対する実保有時間の下限は51.85%。10月12日の1件は決済不明。

日経とTOPIXの両方で損益が判明した126件のうち107件で、費用後損益の符号が一致した。日経と同じ売買方向がTOPIXでも機能する場面があった。通常立会日の現物寄付前に発生した日経10通知はTOPIXでもすべて取得し、8勝2敗・＋137,664円だった。日経側の同じ10件は10勝・＋377,230円。個別の価格経路、双方の出口の約定仮定、倍率・幅が異なるため、収支差の全額を指数の違いへ帰属できない。[寄付前10件の出所](../../../docs/データ監査/現物制度属性と入口の分布/README.md)

## 通知から決済まで

日経の実取得を知った時点で、日経の新規価格・売買方向・予定幅・予定期限を受け取る。TOPIXの当場で通知より厳密に前の正常板仲値を参照する。参照値の遅れは60秒以内。日経のIFD幅を日経取得価格で割って仲値に掛け、0.25pt単位で切り上げて幅を固定した。実取得の幅は9〜26.5pt。利確・損切は対称で、日経で既に実現した将来損益を通知判断へ入れない。[計算前に保存した条件](条件.json)

TOPIXラージの原順板の買売価格・両側数量・価格時計が正常な行を対象とし、通知の翌秒以後30秒以内に買Ask／売Bidで取得する。取得までの実測遅れは中央値2秒、範囲1〜28秒。利確は指値に到達した時の目標価格、損切・期限は要求翌秒以後30秒以内の最初の返済可能板で計算する。期限は元のH60またはセッション末。デイ15:29に全決済を要求し15:30未満で打ち切る。保有または予約は合計1枚、未知決済は場末まで占有する。約定はラージ板による代用。日経とTOPIXの受信時刻が独立に保存されていないため、時計の同時性は価格時計に対する仮定になる。[試行211のTOPIX約定規則](../../00211_固定TOPIX入口に対するIFD期限の寄与を調べる/README.md)

ミニTOPIXを1pt＝1,000円、片道手数料41.8円、想定滑り片道0.25ptとした。往復583.6円を各既知取引へ計上した。Bid/Ask差は費用前の価格差に既に入っている。日経とTOPIXの枠は各商品で独立に再生し、日経の通知を取得できなかった後もその後の日経通知を評価した。

## 再現

プロジェクトの恒久保存入力のうち、試行199の旧81場＋追加2場の台帳、TOPIXの元81場と試行194の追加2場の原順8列から、デイを抽出する。対象の指紋、全通知、全建玉の価格と原行、全42日、期間別集計は[結果](結果.json)に収録した。試行211の2個の恒久保存Source ZIPのSHAを確認し、一時フォルダへ展開する。直接走査と211の区間木を独立に計算し、128要求について失効または取得・決済・先着・保有終点を照合した。

Python 3.14.3、NumPy 2.5.4、tzdata 2026.6 を使用した。次のコマンドは研究ルートで実行する。

```powershell
$env:PYTHONUTF8='1'
$section = 'study/00213_日経デイ199の入口をTOPIXへ固定移植する/日経取得通知の対照'
$pythonExe = 'work/複合テクニカル学習環境/Scripts/python.exe'
& $pythonExe "$section/追随を診断する.py" --verify --output work/通知対照の再現.json
& $pythonExe "$section/閲覧入力を作る.py" --result work/通知対照の再現.json --output work/通知対照の閲覧入力.json
```

正式保存したSourceから別の出力先へ再計算した結果のSHA256は `7bd40b1b12ed74c4c79b5dd7a066f2f7020615223598b0fcf7fdcd573ec6297d`、[型付き入力](型付き入力.json)は `338365faa9099f1a2a3c66f2ebe22c37f50c1ac800d9c9b769445a8d73c1a144`。日時・金額の取得元と再計算手順は[通知再生プログラム](追随を診断する.py)と[閲覧入力の生成](閲覧入力を作る.py)にある。
