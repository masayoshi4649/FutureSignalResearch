# 201 の独立検査と再現

純判断は新金融へ進む前に照合し、金融は root の GO 後に参照した。生産側の条件・純出生・金融・順位は変更していない。

| 確認対象 | 結果 | 正本 |
|---|---:|---|
| 元の固定純出生と全 25 板条件 | 6,039,954 属性一致、138,645 板判断要求 | [純判定独立確認](監査/純判定独立確認.json) |
| 予約・保有の人工時計 | 5 合成場面一致 | [独立枠の人工確認](監査/独立枠の人工確認.json) |
| 親金融 5 BASE | 全台帳・保有区間・場順が同体 | [金融独立確認](監査/金融独立確認.json.gz) |
| 全 25 口座の別算術集計 | 108,350 属性一致 | 同上 |
| 独立の一件状態による取得再生 | 86,544 属性一致 | 同上 |
| 共通・旧のみ・新のみの実現取引 | 各帯・各期間で総損益差と整合 | [実取得差分](監査/元新の実取得差分.json.gz) |

純条件は `decide` / `filter_bundle` を呼ばず、元の 199 固定 NPZ と 200 恒久純 JSON から素直な条件式で計算した。未知、同じ q0 で core を落とした後の T 迂回禁止、幅・期限の保持も照合した。板の数量式そのものは別担当の原板→純特徴監査の範囲である。

枠は計 958,320 q0・40,187 要求を再生した。NK は生産側の heap エンジンを使わず、一件の予約又は保有状態で処理した。対象は終了前新規締切より前の全 q0 で、初参加 T は開始 45 分後から・初取得まで、同秒の決済は秒末解放、未知は場末占有、別名の同 case 取得は抑止する。締切以後の新規はなく、全セッションと対象時間の分母は保持した。TOPIX も全 q0 から TTL 30 秒の予約と未知保有を再生した。

**IFD の価格表と TOPIX Route セルは不変の既存計算を共用した。今回あらためて原 BBO を独立走査したとはしない。** 新たに独立確認した範囲は板条件、変更後の全後続要求と枠、取得選択、金融集計である。集計には旧 183 の別算術を使い、損失率・連敗・DD・5/10 場窓・中央値・保有区間を照合した。

## Source と入力の復元

[独立Source.zip](独立Source.zip) と [索引](独立Source索引.json) は検査コードと既存 183 の別算術 2 本を保存する。ZIP 内の相対パスを保って、研究リポジトリと同じ構成の再現領域へ展開する。既存ファイルは内容指紋が一致することを確認し、異なる内容を上書きしない。

前提は主試行の [金融Source.zip](金融Source.zip) と共通入力が復元された環境。金融Source には生産側 Source、201 純入口、TOPIX200 の N00/N10 全 83 場の固定母体台帳が入っている。独立 Source には金融母体や原板を重複保存しない。

- 199 の親純 NPZ 4 本は、[旧81の正式純入口ZIP](../00199_保留中の旧幹を確認済みの根拠で切り替える/純入口.zip) と [追加2の正式純入口ZIP](../00199_保留中の旧幹を確認済みの根拠で切り替える/追加二場/純入口.zip) から必要分だけ復元する。下記の補助コードは既存時には内容一致だけを確認する。
- TOPIX の親純入力は `inputs/00200_TOPIXの観測被覆と時間順入口/`。板純入力は `inputs/00201_両指数の板数量純特徴/`。入力自体と指紋は主条件を参照する。
- 主試行の `純封印.json`、`純成立診断.json`、`全25口座安定性.json.gz` と `金融正本/` を、内容を変えず対応する `work/201板数量比較/` へ復元する。
- 181 の純基準 cache は主試行の純再生で作成・照合されるもの。金融監査は既存 cache の存在と同体を確認してから接続し、監査中に新しい基準を選ばない。

既存の共通環境が残る本リポジトリでは、次の順で実行できる。

```powershell
& 'work/複合テクニカル学習環境/Scripts/python.exe' -X utf8 'work/201独立検査/固定母体を確認復元する.py'
& 'work/複合テクニカル学習環境/Scripts/python.exe' -X utf8 'work/201独立検査/独立確認201.py' --pure
& 'work/複合テクニカル学習環境/Scripts/python.exe' -X utf8 'work/201独立検査/独立枠を人工確認する.py'
& 'work/複合テクニカル学習環境/Scripts/python.exe' -X utf8 'work/201独立検査/独立確認201.py' --finance
```

Python 3.14.3・NumPy 2.5.4、ニューヨークの夏冬時間を解決できるタイムゾーンデータを使った。正本は書き換えず、再現した検査票の数値を比較する。

## 接続修正と事前封印の限界

[検査履歴](監査/独立検査履歴.json) のとおり、最初の金融監査は監査側の `sealed` 接続不足で assert 停止した。存在する既存 181 純基準を同体確認してから接続する修正だけを加えた。売買・板式・枠式・生産側の金融は不変。純検査時の Source を `金融検査接続修正前.py` に内容指紋一致で保存しているため、再実行した票の Source 指紋と当初票の指紋は区別する。

また、[動的依存の確認](監査/動的依存の同体確認.json) にある `scripts/入口分析/分析.py` は Route の初期化時に動的 import され、201 の直接事前 Source 列挙から漏れていた。現 SHA256 `88c4e940475dedec99ffc6e9fc435053d5b5096738486a7e769feb3963051253` は、旧48の固定条件、200の正式 Source 索引と ZIP 内実バイトに一致する。依存は[主金融再現追加Source](主金融再現追加Source.zip)へ保存した。**過去の固定と同体であることを、201 自身で直接事前封印済みだったという主張に置き換えない。** 201 の条件や金融正本は遡及修正していない。
