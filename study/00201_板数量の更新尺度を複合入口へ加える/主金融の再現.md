## 保存したもの

[主金融再現追加Source.zip](主金融再現追加Source.zip)は43,415バイト、7ファイル。[索引](主金融再現追加Source索引.json)に各memberと既存ZIP11本のSHAを記録した。ZIPのSHA256は`92de3e39ec7920b4c0fcf6d0319a715b3f51a4c4f8d99092c88e51c80fa3e11b`。

- 元の金融Sourceを変更せず、復元、再実行、入力書込監視、同体検査の補助コードを追加保存した。
- ZIP内`work/201主金融再現/復元参照表.json`が、154資源の復元先と、既存の恒久ZIP内member又は正式ファイルを対応付ける。194・200・201等のSource、174〜181の固定出生・接続キャッシュは既存保存を参照し、二重収録しない。
- 201の純出生5ファイルとTOPIX200のBASE期待台帳2本は、既存[金融Source.zip](金融Source.zip)から復元する。NK199のBASE期待台帳と201比較正本は、それぞれの正式保存を参照する。
- 大きい原板、旧金融配列、151の約20MBの純特徴キャッシュは追加ZIPへ入れていない。共用`inputs/`はfile hardlinkで参照する。既存固定生成入力を用いて主金融を再現する経路である。
- NumPyとorjsonのバイナリは保存しない。Python 3.14.3、NumPy 2.5.4、orjson 3.13.0、tzdata 2026.6を使用した。Windowsの夏冬時間変換には`America/New_York`を解決できるタイムゾーンデータも必要。

旧179はNumPyの設置位置も指紋検査する。このため復元補助は、NumPyを展開先の`work/複合テクニカル学習環境/Lib/site-packages`へ、orjsonを`work/pythonlibs`へ指定版でpip導入する。実行するPythonにも同じNumPy版とタイムゾーンデータを用意する。ライブラリ本体の手作業コピーはしていない。

## 151キャッシュの扱い

主金融の旧73場接続は、151の純特徴NPZとmetadataの固定SHAを要求する。その値は恒久148の`当時特徴.json.gz`と`固定取得入力.json.gz`を、既存151の`data151.py`で射影して再構成できた。数値・q0・場情報は生成し直す。

旧metadataには当時の絶対pathとstatが含まれるため、その小さい断片だけを`151特徴の旧由来.json`へ履歴として保存した。再生成時は現在の入力物理SHA・解凍SHA・容量を検査した後、履歴断片を付け戻し、旧metadataの物理SHAを再構成する。**当時のstatを今回の読取証拠とは称さない。** 今回の読取証拠は準備票の`151再生成/今回の読取証拠`へ別記した。

## 実行手順

本リポジトリの正式`study/`と`inputs/`を残して実行する。元の`work/`にある研究コード・キャッシュは再計算の入力に使わない。比較する201の金融正本も必要である。展開先は同じファイルシステム上の**未作成フォルダ**を指定する。失敗済みフォルダを再利用せず、新しい名前を使う。

まず追加ZIPを元の相対構造へ展開する。下の処理は既存ファイルがある場合に内容一致を要求し、異なるファイルを上書きしない。

```powershell
$研究ルート = (Get-Location).Path
$python = Join-Path $研究ルート 'work/複合テクニカル学習環境/Scripts/python.exe'
@'
from pathlib import Path
import zipfile
root=Path.cwd().resolve()
archive=root/'study/00201_板数量の更新尺度を複合入口へ加える/主金融再現追加Source.zip'
with zipfile.ZipFile(archive) as z:
    for item in z.infolist():
        target=(root/item.filename).resolve()
        assert target.is_relative_to(root)
        body=z.read(item.filename)
        if target.exists():
            assert target.read_bytes()==body, target
        else:
            target.parent.mkdir(parents=True,exist_ok=True)
            target.write_bytes(body)
'@ | & $python -X utf8 -

$展開先 = Join-Path $研究ルート 'work/201主金融再現/再実行_001'
& $python -X utf8 'work/201主金融再現/復元する.py' $展開先
& $python -X utf8 (Join-Path $展開先 'work/201主金融再現/復元先を実行する.py') $研究ルート
```

既存のPython環境がない場合はPython 3.14.3の別環境を作り、`pip install numpy==2.5.4 tzdata==2026.6`を実行して`$python`へ指定する。固定研究Sourceのパスは復元補助が構築する。上記で確認した展開先は`work/201主金融再現/repo_hardlink2`だが、次回は別名にする。

復元した`work/201板数量比較/実行201.py`の`finance()`をそのまま呼ぶ。元実装の金融開始markerは新しい展開先に生成し、既存markerを消さない。比較用の全統計・金融正本は出力先へ事前に置かず、再生成後に正式正本と比較する。書込先は展開先の通常ファイルだけであり、入力hardlinkは書込を拒否する。

## 封印と移転の限界

`scripts/入口分析/分析.py`はTOPIX Routeの初期化で動的に読まれ、201の事前Source直接列挙から漏れていた。現SHAは`88c4e940475dedec99ffc6e9fc435053d5b5096738486a7e769feb3963051253`で、200の正式ZIP内実バイトと一致した。旧48も含む照合は[動的依存の確認](監査/動的依存の同体確認.json)を参照する。追加ZIPへ保存したが、**201自身が直接事前封印済みだったことにはしない。** 201の条件・Source・結果を遡って変更していない。

今回の確認は同じPC上での別root復元であり、元の恒久`inputs/`と正式正本を共有する。入力台帳には`S:\GitHub\masayoshi4649\FutureSignalResearch\inputs\...`などの絶対pathが残る。入力の前後照合にも元配置を読むため、完全に別PC・別ドライブへ自由に移せることまでは確認していない。移転時には元の絶対位置へ同一入力を提供するか、別試行としてパス解決だけの変更を監査する必要がある。固定条件を黙って書き換えない。

また、この再現は既存のq0母集団・固定純出生・IFD共用数値表からの主金融が対象である。元166原板から全旧履歴・各旧試行の探索を再生成したとはしない。板純特徴の原板からの抽出は[純特徴の再現](純特徴の再現.md)、価格・枠・集計の独立確認範囲は[独立検査の再現](独立検査の再現.md)に分けた。
