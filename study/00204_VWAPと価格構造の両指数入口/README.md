## 目的と現状

MA・RSIの確認条件を増やすだけでなく、配信VWAPと、先に固定した支持抵抗の回復・拒否、数量の時間順を使う余地を調べる。旧17〜19の失敗を踏まえ、入口と出口、入力の可用性と取引条件の効果を分ける。

TOPIXは83場・35,361判断原行の全てでnative値の内部比率が整合し、数量時計も価格時計と同秒だった。ただしDayのnativeは前夜からの累積に対応する観測であり、厳密なDay差分を計算できたのは26/42場。Nightの厳密な当場差分は0/41場。nativeをそのまま「各セッションのVWAP」と同一視しない。

純入力は201の原板指紋とq0を再使用し、原板の複製なし、q0のgzip合計2,133,746 bytes。20項目の人工確認、全35,361 q0・728,535属性の独立原行照合が成功した。区間変更状態全体の別実装監査は未実施で、その範囲は[監査](../../inputs/00204_両指数の配信VWAP純入力/TOPIX独立原行照合.json)に記録する。

## 次へ進むための区別

- nativeの位置・傾き、任意の既知時点からの累積差分、厳密な当場差分を別列・別仮説にする。
- 価格とnativeの同時条件だけで二つの独立な需給確認を得たとしない。
- 支持抵抗をsetup時点までで固定し、その後の受容・拒否と量を時間順に確認する。
- 新売買条件をレビューしてからSource・純入口を固定する。出口・幅・期限・費用を同じにし、単一建玉の口座を再計算する。
- 同じ可用性を課す価格対照、native確認、量を含む確認を分ける。未知・保有・予約・未参加を場分母から除かない。

損失の頻度・深さ・連続性と参加・両中央値を優先する現行方針を維持する。現段階に優位・採用の結論はない。
