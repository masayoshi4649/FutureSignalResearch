# NK225の検証と再現

固定単純IFDに対し、旧4案＋6種の複合構造×4統合方式を比較した。幅・期限は基準入口の設定を継承し、新しい出口最適化をしていない。mini1枚、1pt=100円、片道税込手数料38.5円、追加滑り片道5pt（往復費用1,077円）。全81場は既使用であり、全80発見・前48選択・後25/追加7/本日1の診断を区別する。

全80Dayの事前順位先頭は04（押戻し回復を追加）、前48Dayの先頭は06（同回復＋既存危険局面の反転）。Nightは両方とも00（旧IFD）が先頭。順位は適合→赤字場率上限→最悪5場既知寄与損失→最大場損失→連続赤字→赤字取引→損失/取得→DD→参加の順。前半と全期を交換しない。未知場/窓の既知寄与順位は確定した安定優位の証明ではない。

04はDay全41場取得・両中央値黒字・保有55.44%を保持し、赤字場10→9、場末DD93,539→70,771円。一方で損失総額1,163,159→1,284,621円、追加7内Day収支8,768→−17,386円へ悪化した。全面的な損失安定化として採用しない。

[取得差の診断](取得差の診断.md)に新枝の実取得と旧口座との差を記した。詳細は `NK183取得差の診断.json.gz`。これは実取得した取引の差であり、未参加の仮想利益を機会損失として最適化したものではない。

## 再現

まず [182再現資料](../../00182_反転の危険局面と値幅に応じた保護を組み合わせる/再現資料/README.md) に従い、親Source・正本を古い順に新しい作業コピーのリポジトリルートへ復元する。182索引が参照する181以前の依存も必要。原板・148/163/167/179/180共用inputsを同じSHAで参照し、183へ重複させない。続いて183新規Source.zipを同ルートへ展開する。

```powershell
python -X utf8 work/183単純IFD検証/当時価格183.py
python -X utf8 work/183入口候補/人工検査.py
python -X utf8 work/183単純IFD検証/実行183.py --resume
python -X utf8 work/183単純IFD検証/比較を集計する.py --baseline E183_00__C0_IFD
python -X utf8 work/183損失安定性/新候補の集計を独立検査する.py --input work/183単純IFD検証 --output work/183損失安定性/NK183独立確認.json
python -X utf8 work/183損失安定性/NK183の差を診断する.py
```

`--resume` は固定Source・純配列の一致を検査後、存在する期間packを再利用する。中間packがない新しい作業コピーでは全84packを生成する。独立検査には全28集約packが必要なので、4保存候補だけを渡さない。再生成した期間pack・純NPZは保存索引の指紋へ照合できる。ZIPの保存時刻や圧縮実装が変わる場合は内容配列と条件を先に照合する。

独立検査は金融台帳からの別算術集計・旧金融共通項照合であり、原JSONL全件の再取得や実約定保証ではない。TOPIXの全件BBO直接走査監査とは検査範囲を分ける。

## workを使わない保存4案の検算

正式保存の4金融packとSource ZIPだけから、全安定性項目・小表・独立算術16,848属性を再計算して照合できる。全28の保存済み集計から4種類の順位も再計算する。旧Sourceやworkの復元は不要で、金融・条件・順位を変更しない。

```powershell
python -X utf8 study/00183_単純IFDで両指数の入口と損失安定性を検証する/Source/NK225/保存4案を検算.py
```

これは保存後に追加した閲覧検算Sourceであり、新金融前の凍結Source.zipを変更していない。CLI補足では `比較を集計する.py` の必須 `--baseline` を明示した。他の掲載CLIもargparse定義へ照合済み。
