# 134の再現手順

F0→Raw即時/遅延の非金融Source出生→三取得集合と方向を固定→F1→正逆別観測→集計→CSVと独立検算の順で実施した。正式研究は134、Sourceと後段は凍結133実行物をそのまま再用した。出力headerのengine試行133を134に偽装しない。[結果と限界](../結果と限界.md)、[設定表](../設定と結果.md)。

## 保存資源と履歴

- [保管索引](../保管索引.json)に各源のサイズ・SHA・復元先を記録した。133の[固定コードZIP](../../00133_全場参加を維持して強い入口の探索期限を延ばす/再現資料/133固定コード.zip)から63源を共用し、[追加固定コードZIP](134追加固定コード.zip)に134固有の15源を保存した。
- [共用入力](../../../inputs/00134_Raw公表時計の共用入力/README.md)は即時/遅延のSource出生、三model固定入力、方向metadataの4gzip、計600,734 bytes。CSV対照のSourceは133から参照し、重複保存しない。
- [正逆観測](../成果物/固定取得の正逆観測.json.gz)の解凍SHAは`cd1e1df3cd8147ca06a1447947d3f800003ec62d3ffb54b15a3b829de13b112f`。[集計](../成果物/集計.json)は`ac497334c10b7fc5ab3c90bcc82bfb5bc488a5c9e75bfc2cd6ee32d686d2d0f0`。
- [F0原本](../検査/F0.json)は`b4729dc22249fe7b8b54937c7b1ff0ce784d546c7e55d3ccf1fe84455628bc40`、[F1原本](../検査/F1.json)は`d76eb2017da90f160b1b6c78485a26c28fa63f03954ec7748bc6b49802396eb6`。[実行前文書](../検査/実行前文書.json.gz)はF0の6MD/F1の7MD、重複を除き7原文。結果編集前に退避・SHA照合した。
- [後発コードZIP](検算と保管の追補コード.zip)は独立検算、CSV、保管/再現、事後の足定義監査。原F0/F1に含まれる源と区別する。

設定生成コードにはDMI・ADXをSAR行へ置く誤記があった。金融完了後にI08/I10とRSI・ATRの足幅を訂正した。[9セルの文書訂正](../検査/設定表の文書訂正.json)を別記し、残495セルを照合した。元コード・実行前MD・F0/F1は原文のまま残し、実行条件や結果を変更していない。復元される固定MDは訂正前の当時原文である。

## 保存観測だけから再集計する

Python標準ライブラリで実行できる。リポジトリルートから未作成の作業先を指定する。

```powershell
python -X utf8 "study/00134_Raw公表時計で複合入口を再生成する/再現資料/保存資料を復元する.py" --destination work/134再現
```

ZIP CRC/源SHA・gzip解凍SHAを確認し、F1の102源中98源を復元する。83,614,403 bytes/84,670,954 bytesの巨大Source入力と2実行体は複製しない。原板も不要。履歴F0/F1はbytes同体で保持する。

元のF1は当時の絶対パスを含む。別名の`再現用パス台帳.json`に、元源SHAを保持したままrepo内相対位置だけを復元先へ写す。作成UTCと元F1 SHAを明示し、金融前固定ではないと記す。実行体・巨大入力が存在する新F1を作ったものではなく、保存観測の再集計CLI用の照合台帳である。

```powershell
$replayRoot = (Resolve-Path -LiteralPath 'work/134再現').Path
$replayLedger = Join-Path $replayRoot 'work/134公表時計の評価/再現用パス台帳.json'
$replayLedgerSha = (Get-FileHash -LiteralPath $replayLedger -Algorithm SHA256).Hash.ToLowerInvariant()
python -X utf8 "$replayRoot/work/134公表時計別の集計/集計する.py" --f1 $replayLedger --f1-sha256 $replayLedgerSha --fixed-input "$replayRoot/work/134公表時計の評価/固定入力/固定取得入力.json" --fixed-input-sha256 5dafeceae9fe87c98e7d487f924f96c56d817cf00bc5a4a96379cb7377d2c526 --metadata "$replayRoot/work/134公表時計の評価/固定入力/方向と出生.json" --metadata-sha256 5f3442a81ce06916a94bb433f48befe5ec4cca6bec7154db18aa17cf1b2e1eb4 --result "$replayRoot/work/134公表時計の評価/固定取得の正逆観測.json" --result-sha256 cd1e1df3cd8147ca06a1447947d3f800003ec62d3ffb54b15a3b829de13b112f --output-dir "$replayRoot/work/134再集計"
```

停止済み正本と異なる新規先へ出力する。実再現では集計の差は`F1_SHA256`の台帳参照だけで、他の全フィールドは元の集計と同体。三表JSONは`71b4384f73a66325831ff52de3bdeff50dc595dc3a08d9d5f5a68af7671c5208`へbytes同体だった。[再現確認](../検査/保存観測からの再現確認.json)。Source/Raw再走査、巨大派生入力本文読取、新条件の金融実行やCSV生成はしていない。

## Sourceの出生から再現する場合

[128の再現手順](../../00128_Raw価格時計で構造回復の出生を比較する/再現資料/再現手順.md)から公表を再生成するか、既存同体の128公表gzipを共用する。即時`gap300.json.gz`はSHA`e382858a62865b321449279d9653f5b1c644c97f6c4254cbae8dd9d3ea065e62`、遅延`gap300_delay60.json.gz`は`ce2add7e0a01fd1ab31c0510194b4647144c01034701f548253c307f6334c830`。6.9/7.1MB公表や巨大派生入力を134用に恒久複製しない。

復元先の`work/P3をRaw公表時計で再生成する準備/入力を変換する.py`は、共有124metadataと128公表を使い、非金融Source入力を未作成先へ生成する。即時83,614,403 bytes・SHA`905cab946d67e368633585219fc9f4fa04efab639104dcecdc6a3d01d18eeb01`、遅延84,670,954 bytes・SHA`8cc73c58fcf90968d177913bfdf66bdcacb3a98aa6ca1a787a35ad9301349139`。原177MBのCSV派生入力を再複製する必要はない。

Go1.24.2と相対go.modを保持し、[133のSource/後段ビルド手順](../../00133_全場参加を維持して強い入口の探索期限を延ばす/再現資料/再現手順.md)を使う。元Source exeのSHAは`e6d216ffbbc9ec8d640d5d482d163de3ac289c1f46392469abb9d66eb47a905e`、後段は`033cf22a052e985bc61aa020a04fa6d499119051aaa39bb2adb715a4af1e7736`。新しい場所での再ビルドが元exeとbytes同体とは保証しない。履歴SHAを新しいビルドへ流用しない。

1. 凍結Source CLI `Source入口.exe --input <即時又は遅延Source入力> --expected-sha <入力SHA> --output <新Source結果> --workers 8 --execute-after-f0`。各入力を独立に再生成し、native L0だけ採用する。native L1も出力されるが134へ混ぜない。
2. `work/134出生を固定入力へ渡す.py`で即時/遅延と共有133旧CSV Sourceのnative L0を三modelに分ける。この転送は当初の134パス・SHAを固定した段階scriptなので、新しいパスを使う際は別の再現記録を残し、旧原文を書き換えない。
3. 出生・取得・方向・固定入力を停止した後、後段CLI `固定取得の正逆評価.exe --input <固定入力> --sha256 <入力SHA> --output <新正逆観測> --workers 8`。正逆とも元geometryを通った取得原行の方向診断であり、反対側の注文cap/hold/riskを再構築しない。
4. 集計CLIへ実際の入力・観測SHAとパス照合を渡す。入力や原板版に差があれば旧結果を置換せず原因を記録する。

## 独立検算・閲覧・限界

[独立検算](../検査/独立検算.md)はRoot/124算術をimportせず、300条件・7,896集計末端値・26,662表セル、旧120条件/79case/3,160H幅観測とphaseを照合した。Raw内の最初touchを独立に再探索した証明やbootstrapの再実装ではない。

[CSV案内](../../../outputs/01a1889f-f2af-7943-a047-543275ee9ed2/134公表時計CSV/README.md)は正逆比較300×29・入口235×55・全73場×69。Rootの別再読は26,662セル/13,975数値同体、3プレビュー視認済み。Node24.22.1/Artifact2.8.129、今回CSV作成markerは3点分を一度。再生成する場合は保存済みbuilderへ同体三表JSONとSHAを明示し、適用するスプレッドシート手順・依存・新規出力先を用いる。xlsxは生成しない。

[事後監査](../根拠/事後の足形成診断.md)はCSV/Rawの形成・時計・指標差を示すが、134の損益差への寄与は未検証。三cohortを同じ取引として差分計算せず、未知を0にしない。真の受信時計、mini実約定、利益追尾、片側10枚口座の収益は証明範囲外である。
