## 保存結果だけを検算する

コードZIPを元位置へ復元し、結果gzipを`work/118入口比較/全70場の入口結果.json`へ展開する。同名が存在する場合は同SHAを確認し、上書きしない。正式のF1・完了・集計を同じworkフォルダの元ファイル名で復元する。

`python -X utf8 work/118入口比較/独立検算する.py`は許可4JSONの指紋・算術・全集計を照合する。出力`独立検算.json`は未作成が必須。既存の検算を残す場合は、4JSONと同コードを別の検算専用フォルダへ同bytesで置いて実行する。この検算はRawの再走査ではなく、約定・先着の最初性や未保存BBOによるcap拒否まで独立再証明しない。

CSVの入力表を再生成するには、結果だけを置いた別の集計専用フォルダへ`集計する.py`をコピーして実行する。`集計.json`と`CSV用の表.json`を新規保存するので既存出力を置かない。生成された集計SHAが上記正本、表JSONのSHAが `020745ba8cb8c4eb5b715e4753c9f750b60831643551d8d60a70056a8c11e6ce` と一致することを確認する。CSV器は次のCLIを使い、既存CSVを更新しない。

```powershell
node work/118入口CSV出力/出力する.mjs --input <新規集計先のCSV用の表.json絶対path> --sha256 020745ba8cb8c4eb5b715e4753c9f750b60831643551d8d60a70056a8c11e6ce --output <未作成CSVフォルダの絶対path>
python -X utf8 work/118入口CSV出力/CSVを独立再読する.py --input <同じ表JSONの絶対path> --sha256 020745ba8cb8c4eb5b715e4753c9f750b60831643551d8d60a70056a8c11e6ce --folder <新規CSVフォルダの絶対path> --output <未作成の確認JSON絶対path>
```

実際のCSVは転記器による型・全セル照合と標準csv/Decimalによる独立再読を完了した。[CSVの独立再読](../検査/CSVの独立再読.json)は219,254データセル・36,048数値セルの一致と前後SHA不変を記録する。元出力時の先頭プレビュー視認はRootで実施した。表の金額は独立mini1枚の期限評価で、運用口座の合計収支ではない。

## Rawから入口を再生する

共有`../JP_OSE_Data`と生成3gzipが必要。118コードZIPだけではRaw再生はできない。11/09は入力に含めず、読み込まない。F1のcode_sha256全件、入力SHA、[実行前原文](../実行前原文/README.md)と同設定表のSHAを照合する。

```powershell
Set-Location work/118入口比較
go test ./...
go vet ./...
go build -o 入口比較.exe ./cmd/run
.\入口比較.exe --input <入力.json絶対path> --sha256 574771f654937036b48c78eceadb46a4c5ff3c10265f60b0ec7879efb0d862c3 --output <未作成結果JSON絶対path> --workers 8
```

当時実行物SHAは `24f20eaf9e78b916c905f210f2a1cede38571bbb48030a2d09d8fb903c178ebe`。再buildが同SHAにならない場合は当時実行物と同一と呼ばず、環境・新SHA・結果比較を別記録に残す。当時の`実行する.py`はF1と実行物のSHAを厳密に要求し、既存結果を拒否するため、再現のために固定F1や旧完了を編集しない。

結果は70場全成功、3,906候補、1,170約定代用、2,156期限完了・184期限打切りが期待値。新規前後のコード・入力指紋とRaw受理数/契約/公表配送を検査し、保存正本へ比較する。固定条件を変更した研究は別試行にする。
