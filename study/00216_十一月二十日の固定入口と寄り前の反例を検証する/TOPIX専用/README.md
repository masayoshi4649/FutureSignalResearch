## 固定ルールと入力

212_06のデイは、旧入口が成立しても5分の方向感が弱く30分方向と矛盾するときは見送る210主3。ナイトは旧190が優先し、旧入口のない時は配信VWAPを固定参照とした価格の接近・回復・保持と量の支持が揃う209追加条件を使う。ナイトの上下幅は各15pt、期限60分。デイでは元の可変幅を継承した。開始待機なし、保有・予約中の追加禁止。ラージの原板でminiTOPIX 1枚の約定を代用し、往復手数料83.6円と往復想定追加滑り0.5pt（500円）を引く。デイの返済限界は15:30、ナイトは05:45。未知保有の時間で参加率を増やさない。[212の固定条件](../../00212_デイとナイトの見送りとnative入口を同じ口座で比較する/README.md)

同限月では旧83場を順に通して5・15・30分足の指標履歴を形成した。1分足から合成する方式と、各時間軸で直接形成する方式を独立に処理した。旧最終2場の各691・907判断が既存の純特徴と全項目一致した。追加7場は各3,049・3,666判断。両方式を原行・価格時計で結合すると3,673判断だった。配信VWAPは同じ判断原行までの数量・代金・価格から可用性を検査し、後続原行を使わない。

212で独立した追加入口が成立した旧6ナイトと、旧最終の11月16日夜・17日昼を照合した。8場4,460判断の売買・幅・由来・優先関係がすべて一致し、独立した追加入口の既存6成立を再現した。旧8場54建玉の金融台帳全列、保有終点、全注文の棄却・予約・失効監査も212正本と一致した。[固定照合](固定照合.json)

## 再現

2026年11月21日確認。Windows、Python 3.14.3、NumPy 2.5.4。213のデイ移植版と別の口座である。[212の再現手順](../../00212_デイとナイトの見送りとnative入口を同じ口座で比較する/再現.md)と[独立検算器の復元](../../00212_デイとナイトの見送りとnative入口を同じ口座で比較する/独立確認の再現.md)に従い元の共通部品・恒久入力を用意する。追加の板は共用の `../JP_OSE_Data/future/TOPIX` を参照し、展開済み物理行のSHA256と原順8列のSHA256を固定照合へ保存した。以下をリポジトリ直下から実行する。

