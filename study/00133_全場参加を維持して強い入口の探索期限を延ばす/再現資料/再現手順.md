## Rawを読まず保存観測から再集計する

Python標準ライブラリを使う。リポジトリルートから未作成work先を指定する。

```powershell
python -X utf8 "study/00133_全場参加を維持して強い入口の探索期限を延ばす/再現資料/保存資料を復元する.py" --destination work/133再現
```

ZIP CRC/源SHA・gzip解凍SHAを確認し、F1の92源中89源を作業用へ復元する。177MBのInput122と2実行体は意図して複製しない。履歴F0/F1はbytes同体で保持する。

集計CLIはF1の絶対パスを照合するため、別名`再現用パス台帳.json`を作業先へ作る。元F1の各源SHAを保持し、repo内の相対位置だけを復元先へ写す。作成時刻と元F1 SHAを記し、「金融前固定ではない」と明示する。これは実行体等の存在を保証する新F1ではなく、保存観測の再集計用の照合である。

```powershell
$replayRoot = (Resolve-Path -LiteralPath 'work/133再現').Path
$replayLedger = Join-Path $replayRoot 'work/133探索期限の評価/再現用パス台帳.json'
$replayLedgerSha = (Get-FileHash -LiteralPath $replayLedger -Algorithm SHA256).Hash.ToLowerInvariant()
python -X utf8 "$replayRoot/work/133期限別の集計/集計する.py" --f1 $replayLedger --f1-sha256 $replayLedgerSha --fixed-input "$replayRoot/work/133探索期限の評価/固定入力/固定取得入力.json" --fixed-input-sha256 5efb1b9ef1f1130d4507f926601f8cabe50757463d7523858351833abc6d0b5e --metadata "$replayRoot/work/133探索期限の評価/固定入力/方向と出生.json" --metadata-sha256 a328f6b902e9ace8d4d764974570f6beeacda91bd099933d1b716b68875a49d2 --result "$replayRoot/work/133探索期限の評価/固定取得の正逆観測.json" --result-sha256 ee0d7d48cb49dec48ebdcd8c16db305d722da988ebbbb4a34036c7fdfc80409a --output-dir "$replayRoot/work/133再集計"
```

新しい出力先を使い、元の停止済み正本を上書きしない。保存観測からの実再現では、集計JSONは`F1_SHA256`という台帳参照だけが異なり、他の全フィールドが原集計へ一致した。三表JSONは元のSHA `eab6af830eb9c68f68dfb4cc594d0c2f8e5f3f057e3997a92a1d056a7f00c59b`へbytes同体だった。[再現確認](../検査/保存観測からの再現確認.json)。Raw/Source再走査、177MB入力読取、新しい仮説の金融計算は行っていない。

## Source・転送・正逆観測から再現する場合

共用Input122は177,709,174 bytes、SHA `6a6cd13dfd00c9669b522e3c3c8e06a4066766f6075786f64d8c0feeb45513ec`。[122の手順](../../00122_E0固定条件を全セッションで検証する/再現資料/再現手順.md)を参照し、既存の同体入力を共用する。133用に恒久複製しない。原板は元の共用絶対パス・版・SHA/statを保つ。場所や版を変える場合は旧指紋を上書きせず別の入力版として記録する。

当時のSource/後段はGo1.24.2のローカルモジュール構成。ZIP内の相対go.mod依存を保ち、Sourceのディレクトリ`work/強い入口の探索期限を延ばす次仮説/Source入口の再生器`で`go test ./...`・`go vet ./...`・`go build -o Source入口.exe ./cmd/source133`。後段`work/133固定取得の正逆評価器`では同検査と`go build -o 固定取得の正逆評価.exe ./cmd/run`。実行体は重複保存せず、元exe SHAはF0/F1に残す。別作業場所のビルドが元exeとbytes同体であるとは保証しない。

再生は以下の順序で、全て未作成の出力先を指定する。

1. Source CLI `Source入口.exe --input <共用122入力> --expected-sha <上記SHA> --output <新Source結果> --workers 8 --execute-after-f0`。
2. `L0と旧79件を照合する.py --result <新Source結果> --expected-sha <新結果SHA> --output <新対照proof>`。旧79/73とgeometry・出生/要求/取得・当時方向を一致させる。
3. **転送版2** `133Source取得を固定入力へ渡す_版2.py --source <新Source結果> --sha256 <新結果SHA> --output-dir <新固定入力先>`。初回Root段階scriptはv1転送を呼ぶ履歴のままなので、この成功手順に代用しない。
4. 出生・取得・方向/入力を固定し、後段CLI `固定取得の正逆評価.exe --input <固定取得入力> --sha256 <入力SHA> --output <新正逆観測> --workers 8`。
5. 上記の集計CLIへ各実際のSHAとパス照合を指定する。

当初のSourceは各場一走査、転送補修後の再走査はしなかった。後段は固定取得から実正逆BBO/Lastを別に観測した。保存したSource/方向/固定入力と結果を照合し、差があれば旧正本を置き換えず原因を記録する。133のSource元geometryを通った時点の方向診断であり、選択後の逆注文のcap/hold/riskを再構築する手順ではない。
