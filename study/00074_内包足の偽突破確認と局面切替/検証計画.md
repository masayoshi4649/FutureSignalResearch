# 内包足の偽突破確認と局面切替

作成日：2026-11-06。前巡73完了台帳259対象の不変を確認して採番。全66場は既使用であり、新しい未見評価ではない。本書は入力計算・損益計算前の条件を記す。

## 仮説

73の直近C/E/Jは差分の発生順序を表さず、新分岐にも選ばれなかった。今回は新しい価格パターンを、方向・強弱・短期の勢いと直接組み合わせる。内包足から一方へ抜ける形が続かず、反対端を終値で回復した後の候補を、上位方向への再開又は上位と反対の反転として区別する。

心理の説明は、最初の方向を追った参加者の期待が崩れ、返済や反対側の参加が起きる可能性という仮説である。OHLC・総量から注文主体を特定できたとはしない。偽突破がそのまま進む、反対端を確認しても再び戻る、確認を待つ間に有利な位置を失う反例を含める。

原典はDan Chesler『Trading False Moves with the Hikkake Pattern』、Active Trader 2004年4月、印刷42〜46頁。[Brandt本人サイトの公開原記事](https://www.peterlbrandt.com/wp-content/uploads/2016/06/Hikkake-Dan-Chesler.pdf)を実読した[外部メモ](../../work/74設計/外部の順序条件.md)を参照する。原典の確認はprice-crossであり、以下の終値確認・定時使用・無効化・補助条件・fallbackは独自の適応である。modified版は使わない。原典はNK225の3分・15分条件、費用後の勝率や70%を実証していない。

## 入力と価格パターン

73の保存Q0純判断と、その特徴に保存された当時可視の連続3分足15本を使う。旧73のready、DI、FastK、ATR/D、ADX、15分終値位置を再計算しない。未準備を救済せず、当場・完全・公開key・足番号/end隣接を確認する。将来suffixは価格検査前に除外し、可視の参照10本/反応5本の不足を補完しない。市場結果をパターン計算へ渡さない。

隣接する3足をA、I、Bとする。価格は保存十進表現のFractionで比較し、epsilonを使わない。

| 段階 | 買い候補 | 売り候補 |
| --- | --- | --- |
| 内包足I | I高値<A高値、かつI安値>A安値 | 同じ |
| 次の偽突破足B | B安値<I安値、かつB高値<I高値 | B高値>I高値、かつB安値>I安値 |
| 反対端の終値確認C | B後の1〜3足で、最初に終値>I高値 | B後の1〜3足で、最初に終値<I安値 |
| C後の無効化 | 後の既知足で終値<=B安値 | 後の既知足で終値>=B高値 |

全てstrictの形成・確認とし、無効化だけ等号を含む。B足は確認へ兼用しない。OHLC内の高安の発生順序を推測せず、確認には終値だけを使う。最初のCを後の有利な足へ替えない。C後に無効になった形は復活させない。

使用するCの足終端は `(予定時刻−900秒, 予定時刻]`。公開keyは実判断key以下。同じ確認を次の15分枠へ持ち越さない。遅れて公開されたためこの窓を外れた確認も救済しない。各方向で有効な形を、Cの番号・Bの番号が新しい順に一つ選ぶ。全候補と除外理由・各A/I/B/Cの出典・反対端・無効化を保存する。形成IDはB時点で固定し、確認Cが後から現れても変えない。未確認・確認期限切れ・確認窓外・否定・有効の5状態を分け、否定は窓外より優先する。

## 複数技法による候補の判別

新パターンは単独では注文しない。方向sを買+1/売−1として、73の保存float64特徴へ次を要求する。未知を0へ補完しない。float32の学習・閾値探索はしない。

1. 3分FastKの実方向中央差F02>=0、かつ実方向進行F03>0。
2. 実方向DI優勢差F01>0なら順行候補。
3. F01<0なら反転候補とし、15分ADX現前変化有効F52=1、変化F48<0、実方向15分足内終値位置F15>0を追加する。
4. rawの上位DI方向が0なら、新パターン候補を採用しない。新パターンの役割はこのDI方向との一致で付け、価格パターン自体を必ず反転とは呼ばない。

FastK・DIの符号鏡像を検査するため、同時に両方向が適格なら入力不整合として停止する。一つの価格加工を独立した票へ増やさない。価格パターン、オシレーター、上位方向/強弱、ATRによる保護の役割を記録する。量の新条件は今回追加しない。

適格な新パターンがあれば、その方向を純候補にする。なければ73Q0の保存純判断へfallbackする。旧の実注文・保有・最終損益をfallbackの判断材料に使わない。同方向の再確認、旧待機からの追加、旧反対側からの切替を別計数する。
