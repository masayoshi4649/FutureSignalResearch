# 9月28日と10月14日の利益保護を板で比較する

SessionTradeViewerで[一覧.resources.json](一覧.resources.json)を開き、各日の「単純IFD」と「反対主信号2回で保護」を切り替える。I20は試行222の単純IFD、RC20は試行224の保護と再エントリー制限。ともに開始20分待機、固定入口の日経199_02、日経225mini換算1枚。時刻は日本時間。各場・各案とも全建玉が1件ずつで、再エントリーした建玉はない。

|日付と方向|共通の新規|I20の返済と費用後収支|RC20の返済と費用後収支|日次収支の差|
|---|---|---|---|---:|
|9月28日・売り|11:31:06、66,140pt|15:25:37、65,740ptで利確。＋38,923円|13:05:32、66,090ptで利益保護。＋3,923円|−35,000円|
|10月14日・買い|11:26:06、68,390pt|14:58:20、67,990ptで損切。−41,077円|14:19:14、68,420ptで利益保護。＋1,923円|＋43,000円|

9月28日は元の利確まで保有した売りで、RC20では13:01:03に保護を設定し、13:05:28の発動から4秒後に返済した。両案とも最終黒字だったが、RC20は元の利幅を35,000円失った。

10月14日は13:30:53にどちらの口座も費用後16,923円の含み益を記録した。I20はその後58,000円を失い、元の1R逆指値で決済。RC20は14:19:07に保護が発動し、7秒後に返済した。この建玉でも含み益の最大値から15,000円を手放したが、赤字に転じる前に返済できた。二日は出口変更の得失が対照的な場を成績確認後に選んだ。

四表示・計4建玉・8約定片の方向、時刻、価格、建玉ID、確定損益の変化を配布版の数値APIと照合した。日次の利益・損失・収支と全建玉の正式CSVも一致。場末は買玉・売玉・含み損益がすべて0。ラージの板を使い、約定片の片道費用538.5円には手数料38.5円と想定滑り5ptを含む。[照合記録](Viewer照合.json)・[I20の日次CSV](../../../outputs/00222_日経デイ開始待機と期限なしIFD/222_I20_両注文20分待機/デイ.csv)・[RC20の日次CSV](../../../outputs/00224_利益保護後の再エントリー/224_RC20_R02元価格まで待つ/デイ.csv)

再作成には222・224の口座元帳、正式CSV、隣接する原板リポジトリを使用する。配布版起動後、リポジトリ直下で次を実行する。移設後も同じ手順で一覧中の原板パスを更新できる。

```powershell
python -X utf8 (Get-Item 'study/00224*/Viewer/約定を出力する.py').FullName --api http://127.0.0.1:8091
```
