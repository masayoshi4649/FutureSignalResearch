# 206版2の主金融を恒久保存から再現する

2026-11-18。201の恒久復元を土台に206版2の正式Sourceを足し、別rootで全85口座を再計算した。**全85台帳と全統計3ファイルがgzipを含む物理バイトで一致した。** 主Source、版2条件、純封印、候補、費用、IFDは変更していない。

|確認|結果|
|---|---:|
|全85金融正本|全件byte同体|
|全85口座安定性・全85口座短表・旧五母体同体|全3ファイルbyte同体|
|主金融で読み込んだ研究module等|92本すべて復元先|
|主金融の元`work/`参照|0件|
|恒久入力の前後SHA|464資源一致|
|元・展開先の恒久入力への書込|監査フックで拒否。書込0件|

正本は[復元準備](監査/主金融復元準備206.json)、[主金融復元確認](監査/主金融復元確認206.json)、[追加Source展開確認](主金融再現Source展開確認.json)。同じ主実装の再現であり、[独立金融算術・枠検査](独立金融の再現.md)とは別の確認である。

## 保存と依存

[主金融再現追加Source.zip](主金融再現追加Source.zip)は3 Source、6,106バイト。SHA256は`3fc99d23057666c1f48aa476d0bbc85a6d6ed6862c17a9c731c8e244379de533`。[索引](主金融再現追加Source索引.json)に全memberと恒久依存のSHAを保存した。既存の[金融Source.zip](金融Source.zip)は変更していない。

1. [201の主金融再現追加ZIP](../00201_板数量の更新尺度を複合入口へ加える/主金融再現追加Source.zip)にある復元器を、内容同体のまま使用する。同ZIPの参照表が旧Source・固定生成入力154資源と既存ZIP11本を指定する。
2. 206の金融Source ZIP内89資源を元相対構造へ追加し、同一パスがあれば内容一致を要求する。初回条件・版2条件・両純封印は正式保存からコピーする。
3. `inputs/`は同じファイルシステム内のfile hardlinkで参照する。原板・大きい共用価格表を複製しない。151の約20MBの純特徴キャッシュは201復元器が恒久148から旧SHA同体に再生成する。
4. orjson 3.13.0とNumPy 2.5.4はpipで復元先の既定相対位置へ導入する。ライブラリ本体をZIPへ含めない。実行Pythonは3.14.3、タイムゾーンデータはtzdata 2026.6を使った。

準備段階で201補助を元の`work/`へ展開するが、正式ZIPからの復元物であり既存の作業キャッシュを信用しない。主金融で使用する研究コード・必要生成キャッシュはすべて新root側へ復元される。新rootへの金融出力は通常ファイルで、hardlinkされた入力は書込を拒否する。

## 実行

元リポジトリの正式`study/`と`inputs/`を保持する。別rootは未作成の名前を選ぶ。実行済みmarkerを削除せず、失敗済みフォルダも上書きしない。次の例はリポジトリ直下で実行する。

```powershell
$研究ルート = (Get-Location).Path
$python = Join-Path $研究ルート 'work/複合テクニカル学習環境/Scripts/python.exe'
@'
from pathlib import Path
import zipfile
root=Path.cwd().resolve()
archive=root/'study/00206_指数間の相対変化を複合入口へ加える/主金融再現追加Source.zip'
with zipfile.ZipFile(archive) as z:
    for item in z.infolist():
        target=(root/item.filename).resolve()
        assert target.is_relative_to(root)
        body=z.read(item.filename)
        if target.exists():
            assert target.read_bytes()==body, target
        else:
            target.parent.mkdir(parents=True,exist_ok=True)
            target.write_bytes(body)
'@ | & $python -X utf8 -

$展開先 = Join-Path $研究ルート 'work/206主金融再現/再実行_001'
& $python -X utf8 'work/206主金融再現/復元206.py' $展開先
& $python -X utf8 (Join-Path $展開先 'work/206主金融再現/実行を確認206.py') $研究ルート
```

Python環境がない場合は別にPython 3.14.3環境を作り、`pip install numpy==2.5.4 tzdata==2026.6`で準備して`$python`へ指定する。orjsonとSource検査用のNumPy配置は復元補助が構築する。確認済みの展開先は`work/206主金融再現/repo_0`であり、次回は別名を使う。

固定された`実行206_v2.py`の`finance()`をそのまま実行する。初回版へ戻したり、最高額の遅延へ条件を入れ替えたりしない。新rootの金融開始票は新規作成し、全85台帳と3統計が正式正本に一致することを最後に確認する。201の復元時に比較用の旧正本を読むが、206の再生成先へ全85結果を事前コピーして一致を作ることはしていない。

## 確認範囲と移転の限界

今回確認したのは、既存の固定q0母集団・純出生・共用IFD表から全85主金融を再生する経路である。元166原板から全旧研究や探索履歴を作り直したという意味ではない。純特徴は[純特徴と純条件の再現](純特徴と純条件の再現.md)に分けた。

同一PC上で元の恒久入力と正式正本を共有した別root再現である。入力台帳には旧配置の絶対pathが残り、元入力の前後SHA検査にも元配置を読む。完全に別PC・別ドライブへ無変更で移せることまでは確認していない。移転時は元の絶対入力位置を同体で提供するか、パス解決だけの変更を別に監査する必要がある。旧条件・封印を黙って修正しない。
