# 反対方向の主シグナルは、利益保護のタイミングに役立ったか

**日経199_02のデイでは、反対方向を確認してから保護を狭めることで、元の利確を途中で手放す回数が減った。** 20分待機で元の利確は76件。そのうち決済が変わったのは「反対シグナル2回」なら1件、「同方向2回」や「方向を問わず2回」なら各8件だった。元の利確取引の利益減少は、それぞれ35,000円と166,000円。方向を問わない条件も総損失を同額減らしたので、今回の差が大きく出たのは元々勝てていた建玉の扱いだった。

**信号の時刻も影響した。** 10月14日の買いは、元の損切が−41,077円、元のタイミングの反対2回なら＋1,923円、3分遅らせると再び−41,077円になった。10月21日の買いも元のタイミングで得た19,000円の改善が消えた。9月28日の売りは遅延によりさらに3,000円の利益減。3分遅延の収支は元の反対2回より計65,000円少なかった。これは情報がいつ使えるかを意図的にずらした実験で、返済注文を3分遅らせた比較とは異なる。

買い・売りの符号をそろえて同じ判定を適用し、各待機内の5候補は45日・133建玉の取得日時・側・価格がすべて同一。開始30分でも各対照の単純IFDとの収支差・損失差は同額だった。大きな値動きの中で同方向の継続シグナルまで出口の引締めに使うと、元の利確までの通常の押し・戻しでも決済しやすくなる、という解釈と整合する。市場参加者の意図はデータから検証していない。

収支差は元の反対2回でも前24日−5,000円、後21日＋43,000円。単純IFDに対する改善は4日、悪化は3日、改善上位3日を除いた差は−52,000円だった。30分待機を同じ45日で比較したため、双方の一致は独立した再現に数えない。結果はこの既使用期間で、反対シグナルを元の時刻で使った理由を確認する材料になる。[全10口座の保護件数・期間別・元決済別の結果](全条件の比較.md)・[候補別CSV](../../outputs/00226_反対信号の方向と公表時計/README.md)

## 条件と再現

2026年9月21日〜11月20日の日経デイ。日経225mini換算1枚、片道38.5円と想定滑り5pt、往復1,077円を控除。ラージの正常な最良気配で約定を代用した。固定IFD片幅Rは入口ごとに150・200・350・400pt。広幅は0.95R順行で起動、幅0.80R。狭い保護は順行歴0.25R以上・現在順行20pt以上で、対象の2信号が最新90秒以内・直前180秒以内にそろったときから幅0.25R。どちらも最低利益側20ptの床を有利にだけ更新する。固定価格注文を置き続け、追尾発動から最短1秒後の正常板で返済、元の±1Rか場末が来るまで次の新規を休止する。終了側15:30までに全決済、保有期限なし。[比較前の条件](比較方針.md)・[手法と尺度の設定表](設定と結果.md)

入力は[224の再現手順](../00224_利益保護後の再エントリーをシグナルで待つ/README.md)と同じ。226では各主シグナルの方向・公表時刻を変える処理だけを追加し、223のR02の床・執行、224のCの口座予約を呼び出す。リポジトリ直下のPowerShellで次を実行する。

```powershell

```

元反対X1と広幅X5は224のRCとPCに、判断・新規・決済・起動と発動の時刻および収支が全件で一致した。3種類の新規対照に対し候補ごとに日別・建玉・集計を出力し、18ファイル・21,654セルを照合。CSVの再生成は224と同じ共通出力器へ `work/226方向時刻/閲覧入力.json` を指定する。
