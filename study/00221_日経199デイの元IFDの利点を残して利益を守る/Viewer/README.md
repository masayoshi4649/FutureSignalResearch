# 60分の期限を延ばした二つの建玉

SessionTradeViewerで[一覧.resources.json](一覧.resources.json)を開き、同じ日付の「元IFD」と「元の利確・損切を場末まで維持」を切り替える。各表示には比較対象の建玉1件を収録した。どちらの1枠口座も同じ日に同じ原行で実際に取得した。以下は日本時間、日経225mini 1枚換算、片道手数料38.5円と想定滑り5ptを控除した値。

|取得|元IFDの60分期限|期限延長D04|費用後の収支差|
|---|---|---|---:|
|11月12日 10:35:01、61,580売り|11:35:01、61,820で返済、−25,077円|13:33:07、61,230で350pt利確、＋33,923円|＋59,000円|
|11月13日 10:38:01、61,950買い|11:38:07、61,970で返済、＋923円|12:30:47、61,600で350pt損切、−36,077円|−37,000円|

11月12日は11:19:48に含み損が最大31,077円になった。元の350pt損切に達する前に下落に転じたが、60分では回復が間に合わず、元の利確にはそこからさらに1時間58分6秒かかった。

11月13日は11:25:19に含み損23,077円、11:32:16には含み益3,923円まで戻った。60分期限では小幅の黒字を確定できた。延長した建玉は最高益を更新せず、元の損切に達した。翌日の買いと前日の売りは、いずれも期限到来後の結末が分かってから選んだ事例。期限時点でこれらを識別できたかはこの比較から判定できない。[期限78件の全体像](../元IFDの寄与/README.md)

生成は221の期限比較元帳を再現した後にリポジトリ直下で実行する。配布版の数値APIで各時刻・方向・価格・手数料反映後の残高を検算し、4表示とも最終建玉・含みはゼロで一致した。原板は隣接リポジトリを参照するため、移設時は一覧を再生成する。[照合記録](Viewer照合.json)

```powershell
python -X utf8 (Get-Item 'study/00221*/Viewer/約定を出力する.py') --api http://127.0.0.1:8091
```
