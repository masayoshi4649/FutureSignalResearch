# 00128：再現手順と固定範囲

2026-11-11。Windows amd64・Go 1.24.2・Python 3.14系で実行した。最短の金融再現は保存した2つの取得入力から行える。足の生成由来を検査する場合だけ、共用Rawから公表を再形成する。原板・177MB旧公表・exeは複製しない。

## 保存した正本

- [F0](../検査/F0.json)：SHA256 `16e1eb2ac52119e60180fa33322b36742646fb9a68f5ea34b38876cf739cc870`。足生成前のコード・文書・共有入力・当時exeを固定。
- [F1](../検査/F1.json)：SHA256 `8f94cebf15c8512b08778c31a5f7d87546ea504e0ac1d8a3d5e312c439dc4d2e`。生成した2モデルの公表・出生・取得入力を金融前に固定。
- [実行前文書gzip](../検査/実行前文書.json.gz)：F0に載る**9つのMD全文**を、結果追記前にUTF-8同bytesで保管。[原文の確認](../検査/実行前原文の確認.json)に各復元相対path・bytes・SHA。JSONの`原文[].utf8_text`をUTF-8で書き戻せば復元できる。現在のREADME/設定と金融前原文を混同しない。
- [取得入力2点](../../../inputs/00128_Raw価格時計の独立出生/README.md)：即時643出生/保留639出生と全73場のRaw参照・品質条件を含む。各gzipは1回だけ恒久保存。
- [結果・集計・足summary](../成果物/)：結果2点、集計2点、品質/数値可用性の小型summary。全出生と選択台帳・巨大CSV表JSONは保存結果から再計算する。
- [128コード.zip](128コード.zip)、[復元索引](コード復元索引.json)：F0のGo/Python/go.modを相対path付きで同梱。数値・DMIの原文/bridge・旧115/118・124費用集計も含み、旧ZIPの金融依存を別途展開する必要はない。CSV後処理・保存器・独立検算コードはF0後の補助であり金融条件を変更しない。

ZIPはリポジトリルートへ展開する。全entryのSHA/CRCを索引と照合する。Goの`replace`は元work相対配置を前提とする。独立検算だけは旧[124の検算追補ZIP](../../00124_逆行の原因と売買反転を同じ入口で検証する/再現資料/検算と保存の追補コード.zip)から`work/124正逆の独立検算/検算する.py`（SHA256 `0305f507a74f9728fbdb1ecabe406a3bfcb2f8657a4d1ee2556ca50dbe6585be`）を復元する。これはRootの金融集計moduleと別実装である。

## 最短：保存入力から金融再生

以下は再現する際の手順であり、正式化作業では金融再実行していない。新しい出力先を使い、元結果を上書きしない。`入力.json.gz`をgzip解凍し、以下の元pathへ同bytesで置く。

|モデル|元の取得入力|解凍SHA256|保存済み結果の解凍SHA256|
|---|---|---|---|
|即時gap300|`work/128Raw時計の評価/gap300入力.json`|474455be28a60248c7418fd69e123297738f6f782648b9c52aab076384e3c384|a13f7016ef55d9aed070b5fc4b3a8949999e2cbb739756fe967250ceae19e95f|
|保留gap300_delay60|`work/128Raw時計の評価/gap300_delay60入力.json`|a6c6b863c01e8f7e428ddf6df94a9056ba317df8421d03c8f7b241324343216b|4e5411490b82b05458db3dd7490039b6bc198d51e55d9cd3e7984d15958e26c5|

共用Rawのpathは入力に保存済み。ファイルを勝手に置換せず、SHA/stat/採用数/品質11項目/単一限月照合を通す。場0出生でもRaw照合する。

```powershell
Set-Location 'work/128Raw出生の再生器'
go test -count=1 ./...
go vet ./...
go build -o 独立出生の再生.exe ./cmd/run
.\独立出生の再生.exe --input '..\128Raw時計の評価\gap300入力.json' --sha256 474455be28a60248c7418fd69e123297738f6f782648b9c52aab076384e3c384 --output '..\128Raw時計の評価\再現_即時結果.json' --workers 4
```

保留はinputとSHAとoutputを上表の値へ替えて同じ固定再生器で実行する。出生RawのK/cap判定、後続原行かつ1秒後/30秒TTLの最初正常BBO、cap→hold→riskを保持する。買Ask/売Bidを使い、riskは10〜min(125,1.5ATR5)。原BBO/実逆BBO/Last正逆、H30/60×5幅の時計を変えない。正逆の勝敗を単に1−pにしない。

## 集計と閲覧CSV

リポジトリルートから、新結果の実SHAを明示して実行する。保存済みSource結果を使うなら上表の指紋を指定する。出力先は未作成又は該当3正本が無い場所が必要。

```powershell
python -X utf8 'work/128Raw出生の集計/集計する.py' --result 'work/128Raw時計の評価/gap300結果.json' --sha256 a13f7016ef55d9aed070b5fc4b3a8949999e2cbb739756fe967250ceae19e95f --input-sha256 474455be28a60248c7418fd69e123297738f6f782648b9c52aab076384e3c384 --input 'work/128Raw時計の評価/gap300入力.json' --output-dir 'work/128Raw時計の評価/再現_即時集計'
```

同様に保留を生成する。F0は最初の実取得、同Raw R→T→S→Q、同mode最小risk、同risk両sideはRaw全体見送り、同方向だけならID。FR/A0/系列先頭を主へ交換しない。未取得場/未知清算を0円取引で埋めない。Touch既知優先のIFD代用・Last金額null・費用C0/C5・全73場cluster bootstrap 5,000回/seed124を固定する。

CSV三表は各モデルの`CSV用の表.json`から作る。元の`gap300集計/`・`gap300_delay60集計/`配置へ復元した場合、`work/128閲覧表をまとめる.py --primary-sha256 <即時表SHA> --delayed-sha256 <保留表SHA>`で先頭に公表モデル列だけを加える。元セルの型・値・順を照合し、元金融表は変更しない。閲覧表の固定SHAは`64de21ec0fee86e767f394c1eef3b477720385f408528e14c9b6ea01a857ec39`。

`node work/128Raw時計CSV出力/出力する.mjs --input <閲覧表> --sha256 <SHA> --output <未作成先>`でCSVを生成する。元環境はNode.js v24.22.1、`@oai/artifact-tool` 2.8.129。固定コードのimportを解決できるよう依存を用意する。CSVは数値を再計算せず保存表から転記する。`python -X utf8 work/128Raw時計CSV出力/CSVを独立再読する.py --input <閲覧表> --sha256 <SHA> --folder <CSVフォルダ> --output <新規確認JSON>`で独立再読し、[確認正本](../検査/CSV独立再読.json)の280×29/432×41/146×41・31,818セル/19,549数値と照合する。プレビューは確認用、恒久成果は[CSV三表](../../../outputs/01a1889f-f2af-7943-a047-543275ee9ed2/128Raw時計CSV/README.md)。xlsxは作らない。

## 足と出生の由来から再構成する場合

この経路だけ旧177MB入力をメタデータsourceとして必要とする。[122の再現手順](../../00122_E0固定条件を全セッションで検証する/再現資料/再現手順.md)から`work/122全場入力/入力.json`を復元する。SHA256 `6a6cd13dfd00c9669b522e3c3c8e06a4066766f6075786f64d8c0feeb45513ec`。足生成器はここから場/Raw/品質/force_closeだけを読み、旧完成CSV/公表/助走値を生成に使わない。場メタデータは[124の共用入力](../../../inputs/00124_同入口正逆の共用入力/入力.json.gz)から`work/124入口の原因分析/入力.json`へ復元する（解凍SHA `b2368b1f42c16e8c96a3acd098c58a902807a3b6a5023d6d4b1e75261f3ee51b`）。

1. `work/128Raw価格時計の全場足生成`でGo人工test/vet/buildを実行し、`全場足生成.exe`を作る。固定73場を一巡し、入力を照合して`--input ..\122全場入力\入力.json --sha256 6a6cd13dfd00c9669b522e3c3c8e06a4066766f6075786f64d8c0feeb45513ec --output <未作成フォルダ> --carry validated-same-contract --execute-all`。最初cold、直前場成功かつ同限月だけ数値/BB/RVOL carry、形成/構造/量基準は場ごとreset、EOF補完禁止。
2. `gap300.json.gz`（即時）、`gap300_delay60.json.gz`（同値保留）、`gap60.json.gz`（品質診断）とsummaryを得る。[保存summary](../成果物/足生成summary.json.gz)・[同値検査](../検査/足完了の独立確認.json)へ照合する。Rawは1場1走査、金融ラベルを生成しない。受信時刻を持たないCurrentPriceTimeモデルである。
3. `work/128Raw足からの出生`でGo人工test/vet/build、`go build -o 出生を作る.exe .`。`出生を作る.exe --input <各モデル公表gzip> --sha256 <公表圧縮SHA> --output <未作成出生JSON>`でv4同体R/T/S/Qの技術出生を生成する。自然Rawを読み直さず、配送済み公表だけを使う。
4. `再生入力を作る.py --births <出生JSON> --births-sha256 <SHA> --publications <公表gzip> --publications-sha256 <圧縮SHA> --output <未作成入力>`で実取得入力へ転記する。ZIP内の旧`出生v4を渡す.py`は`frame_mask`だけをimportし、旧650出生や金融ラベルを混ぜない。保存入力2点の解凍SHAへ照合する。出生カウント全文を恒久複製する必要はない。

## 歴史的な固定手順と検査

F0は新足生成前、F1は金融再生前の別段階。`work/128段階を固定して実行する.py`が原文/コード/入力を各段階の前後に再照合した。結果更新済みREADME/設定をそのままF0検証に使わない。歴史的段階を再現する場合は、別作業コピーへ全9原文・F0/F1・全sourceを復元し、当時のexeSHAも照合する。異なるGo/絶対ビルドpath等でexe指紋が異なる場合、当時のF0全体同体を達成したとは報告せず、source・数値結果の再現を別に記録する。

[保存の確認](../検査/保存の確認.json)、[足生成器の人工検査](../検査/足生成器の人工検査.json)、[即時再生完了](../検査/gap300再生完了.json)、[保留再生完了](../検査/gap300_delay60再生完了.json)、[独立検算の完了](../検査/独立検算の完了.json)を参照。独立検算は2系統各3,460値と注文時計・実逆BBO・Last金額nullを確認し、Raw再走査・bootstrap再実装・実IFD/追尾運用を含まない。

## 再現性と清算可能性を分ける

この手順は128の旧BBO評価を再現するもので、プレクロージングの約定可能性を修正する手順ではない。[終端気配の限界](../検査/終端気配と清算可能性.md)が結果後に判明したため、特に終端を使う金額を口座損益と呼ばない。制度に対応した区間変更は別試行129で比較し、128の旧数値/CSVは変更しない。

結果後のR1診断も[小型gzip](../成果物/R先頭の損失診断.json.gz)へ保存した。元MD/診断コードは128コードZIPの`work/128R先頭の損失診断/`にあり、自作124検算helperを使う。新しいRawや先着ラベルを生成せず、旧128票の内訳を説明する追補である。
