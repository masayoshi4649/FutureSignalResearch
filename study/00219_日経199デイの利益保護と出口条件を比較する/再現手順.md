# 45日の再現と追加デイの固定適用

2026-11-22。Windows、Python 3.14.3、NumPy 2.5.4。図の再作成にはMatplotlib、CSVの作成と読み戻し検査にはNode.jsとリポジトリ共通の `@oai/artifact-tool` 出力器を使用した。以下はリポジトリ直下で実行する。

## 45日を再生する

[試行218の入力の準備](../00218_日経199デイの売買方向と建玉日時を検証する/片側対照/README.md)と[原板・口座の仕様](口座再生の仕様.md)に従い、共用原板と価格索引、旧当時特徴・新規取得対応を準備する。旧部品は[213の保存入力](../../inputs/00213_日経型TOPIXの純入口/README.md)から復元できる。実行環境の `python` にNumPyがなければ既存の `work/複合テクニカル学習環境/Scripts/python.exe` を指定する。

```powershell
$trial = (Get-ChildItem study -Directory -Filter '00219_*').FullName
$modules = [ordered]@{
    '219出口' = '出口候補.py'
    '219成熟' = '成熟時の出口.py'
    '219午後追尾' = '午後利確と必須追尾.py'
    '219期限前保護' = '期限前保護の切り分け.py'
    '219逆行' = '逆行時の出口.py'
    '219戻り' = '逆行後の戻り/出口定義.py'
    '219併用' = '午後利確と損切余裕/出口定義.py'
    '219延長' = '利幅延長/出口定義.py'
    '219遅延長' = '利幅延長/遅い起動の出口.py'
}
foreach ($case in $modules.GetEnumerator()) {
    python -X utf8 (Join-Path $trial '口座再生.py') --出口定義 (Join-Path $trial $case.Value) --出力 (Join-Path work $case.Key)
    if ($LASTEXITCODE -ne 0) { throw $case.Key }
}
$otherBooks = $modules.Keys | Where-Object { $_ -ne '219出口' } | ForEach-Object { Join-Path (Join-Path work $_) '比較元帳.json' }
python -X utf8 (Join-Path $trial '出口を集計する.py') --追加元帳 $otherBooks --閲覧 (Join-Path $trial '閲覧候補.json')
```

どの出口の元IFDも、原価・費用・日時と元の建玉181件が既存正本に一致することを検査する。中間の `成績.json` と `閲覧入力.json` は `work/219出口/` に作る。[全条件の正本](全出口の比較.md)は紙幅を抑えるためMarkdown表とし、常用の6候補は別々のCSVにした。

## CSVとチャートを照合する

下記は既存の公開CSVを保持したまま、空き作業先へ独立に作成する例。既存のファイルを上書きしない出力器なので、再実行時のフォルダ名には新しい名前を使う。

```powershell
$nodeDeps = Join-Path $env:USERPROFILE '.cache/codex-runtimes/codex-primary-runtime/dependencies/node'
$check = Join-Path 'work' ('219再現_' + (Get-Date -Format 'yyyyMMdd_HHmmss_fff'))
& (Join-Path $nodeDeps 'bin/node.exe') 'scripts/損益CSV/候補別に出力する.mjs' --input 'work/219出口/閲覧入力.json' --output (Join-Path $check 'CSV') --proof (Join-Path $check '照合') --dependencies $nodeDeps
python -X utf8 (Join-Path $trial '出口の収支を描く.py')
```

出力器が18 CSVについて型付きの全26,282セルを再照合する。図のスクリプトは `outputs/00219_日経199デイの出口比較` の公開CSVを読む。[経路と実気配の照合](経路診断/README.md) ・ [代表2日のViewer](Viewer/README.md) ・ [遅延条件の再生](返済遅延の感度.md)

## 次のデイを追加する

追加日用の母集団（当時特徴と固定取得入力）、`純入口.npz`（元の199_02）、その日の価格索引manifestを、[216の日経デイの生成手順](../00216_十一月二十日の固定入口と寄り前の反例を検証する/日経/README.md)と同じ時系列・原行対応で用意する。追加デイごとに別試行へ保存する。再生器の候補、入口・出口・約定部品の指紋は[固定条件](次の追加デイの固定条件.json)に含めた。元IFD、W31、M34、M28、W36、M04はそれぞれ元の全注文から1口座を再生し、元IFDの取得を固定した参考元帳も併記する。

以下は用意済みの**既使用**11月20日で動作を確かめる例。追加日にはその日の場名とファイルを指定し、`--既使用照合` を外す。最初の追加日以降は、各候補の総損失・費用後収支・両中央値・保有時間・赤字日を元と対にして追記する。不明の建玉は約定を作らず、各候補の同じ日・同じ欠測区間を確認する。

```powershell
$trial = (Get-ChildItem study -Directory -Filter '00219_*').FullName
$dest = Join-Path work ('219既使用照合_' + (Get-Date -Format 'yyyyMMdd_HHmmss_fff') + '.json')
python -X utf8 (Join-Path $trial '固定出口を追加デイに適用する.py') --母集団 'work/216日経/母集団' --純入口 'work/216日経/純入口.npz' --板索引 'work/216日経/前史十場と追加二場の索引参照.json' --場 '2026-11-20_Day' --既使用照合 --出力 $dest
```
