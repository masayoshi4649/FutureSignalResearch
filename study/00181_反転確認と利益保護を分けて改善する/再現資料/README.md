## 復元順と共用入力

2. 各親の必要正本も同じルートへ復元し、最後に181のSource.zipと比較正本.zipを重ねる。181が選択継承した旧174/179固定選択と179/180条件4件は、親正式ZIPと同じ元byteである。
3. 索引の「可逆圧縮保存」は、大きな独立検査JSONをgzip memberとして保存した対応票。対象を解凍して末尾の`.gz`を外し、元ファイルSHAへ照合する。元の18.9MB JSONを重複して保持してはいない。
4. 恒久`inputs/`を共用する。旧73は148当時入口・163共用価格索引/数値表、追加7は167入口/価格索引、終了前返済は179共用overlay、本日1は180当時入口/価格索引と固定終了前金融を使用する。由来と入力生成は各親の再現資料、[180恒久入力README](../../../inputs/00180_20261116デイの固定適用入力/README.md)を参照する。原板・既存価格索引・旧ZIPは181へ複製していない。

比較正本の`work/181共用接続/cache/`は、共用の純基準2案を金融表接続前に封印した小NPZと指紋票である。新しい入口16案の封印は別に`work/181反省を分解した改善/{旧73,追加7,本日1}_新入口.npz`へ保存した。純方向と金融は分離され、保有・予約1件の口座再生で新しい出口による後続取得も再計算する。

## 検査と保存範囲

`work/181共用接続/共用181.py --verify-fixed`で179主と旧178対照の2案×3期間を元179/180packへ照合する。独立追尾検査は比較正本の`work/181独立検査/README.md`と各検査Sourceを参照する。人工3,520セル・109,120属性、代表4案の全81場1,111取得・3,796要求・73,077属性が一致した。後から追加した181利益後赤字診断Source/結果は[182再現資料](../../00182_反転の危険局面と値幅に応じた保護を組み合わせる/再現資料/README.md)へ保存した。

全81場は既使用である。全80選択と前48選択、本日1/全81の診断を区別する。今回の独立監査は共用48byte索引を別の原行逐次算術で評価したもので、全原板JSONLの独立再走査ではない。181全体の完全なcache禁止隔離監査も行っていない。同体再現・計算検査は、探索選択偏りの解消や将来の安定利益を証明しない。
