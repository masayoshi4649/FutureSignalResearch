金融再計算に必要な恒久入力17資源は `Source索引.json` の `恒久入力参照` に全件記載した。入力そのものは `inputs/00194_20261116夜と1117昼の固定適用入力/` を参照する。独立監査では同索引の `原板参照` にある `../JP_OSE_Data/future/{NK225,TOPIX}/{場}/book.jsonl` も使用する。

ZIPのmember名はリポジトリルート基準。元の絶対配置 `S:\GitHub\masayoshi4649\FutureSignalResearch` で復元する場合は、次のコードをそのルートで実行すると、既存ファイルは同体確認し、不足分だけを正式ZIPから復元できる。

```powershell
@'
from pathlib import Path
import hashlib, json, zipfile
repo = Path.cwd().resolve()
trial = repo / 'study/00194_追加二場へ両指数の固定候補を適用する'
index = json.loads((trial / 'Source索引.json').read_text(encoding='utf-8'))
archive_path = trial / 'Source.zip'
assert hashlib.sha256(archive_path.read_bytes()).hexdigest() == index['archive']['sha256']
with zipfile.ZipFile(archive_path) as archive:
    for item in index['members']:
        target = (repo / item['path']).resolve()
        assert target.is_relative_to(repo)
        data = archive.read(item['path'])
        assert len(data) == item['bytes']
        assert hashlib.sha256(data).hexdigest() == item['sha256']
        if target.exists():
            assert target.read_bytes() == data, str(target)
        else:
            target.parent.mkdir(parents=True, exist_ok=True)
            target.write_bytes(data)
'@ | & 'work/194再現環境/Scripts/python.exe' -X utf8 -
```

## 再計算と独立監査

```powershell
$env:PYTHONUTF8 = '1'
$env:PYTHONIOENCODING = 'utf-8'
& 'work/194再現環境/Scripts/python.exe' -X utf8 'work/194追加二場/再計算194.py'
& 'work/194再現環境/Scripts/python.exe' -X utf8 'work/194追加二場/独立監査194.py' --audit
```

`再計算194.py` は既存194母集団へ固定179時計のIFDを計算し、封印された9候補だけを再生する。保存済み台帳の全項目、全集計、短表を固定UTF-8 JSON表現のSHA256で照合する。新しい金融開始票や正本を生成し直す `固定適用194.py --finance` は、既存の実行開始票があるため再現入口に使用しない。

`独立監査194.py` は評価器の呼び直しとは別の検査。NKは原BBO逐次走査と独自1枠再生、TOPIXは別BBO走査とTTL30秒予約再生を使う。全52取得、NK86要求、TOPIX126成立q0、集計3,474属性、4原JSONLの全SHAと54採用原行を確認済み。監査票は金融完了後の検査であり、金融前封印の代用とはしていない。

## 別workへの展開で確認した範囲

最終ZIPの150memberを `work/194隔離再現/repo_hardlink/` へ通常ファイルとして展開し、入力17資源だけを同一ボリュームのfile hardlinkで接続した。orjsonはpipから展開先へ導入した。可変出力の再計算票や金融正本はhardlinkにせず通常コピーとした。

固定Sourceを変更せず、展開先で全9台帳・全集計・短表の一致を確認した。監査driverを除く研究moduleは展開先から読み込まれた。open監査で恒久入力への書込みが0であることを確認し、終了後も入力17資源の全SHAが一致した。

ただし、194条件の絶対path参照により元workの66資源を指紋照合している。この66資源は全てZIPへ収録してあり、元相対構造へ復元できるが、今回の別work試験は**元配置を完全に隔離した移転試験ではない**。TOPIXの入力台帳にも元inputsへの絶対pathが残る。別ドライブ・別rootへ全面移転するには、元配置を保持するか、パス解決を変更した別の再現adapterで同体確認する必要がある。固定条件を書き換えて移転済みとはしない。

inputsをdirectory junctionで接続する方式は、NK純adapterの `resolve()` 後に復元root外となり、`relative_to()` の確認で停止した。固定Sourceを変更せずfile hardlinkへ切り替えた。hardlinkは元入力と同じ実体なので、入力を編集する処理に使用しない。失敗したjunctionの作業フォルダは削除せずworkへ残している。

## 検証していないこと

- 別OS・別Python/NumPy版・絶対配置を除去した完全独立再現。
- 実際の受信時刻や取引所での注文成立。ここで照合するのは研究上の約定代用と固定費用である。

入力生成CLI・Source・指紋を保存したことと、入力生成の全経路を今回再実行したことを区別する。今後workを整理しても、正式ZIPのmemberを元相対構造へ復元し、恒久inputsと指定ライブラリを用意することで、この9候補の金融再計算と元配置での独立監査を再開できる。
