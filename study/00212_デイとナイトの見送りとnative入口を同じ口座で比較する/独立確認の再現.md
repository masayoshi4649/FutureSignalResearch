# 212の第三者独立確認

確認日：2026-11-18。主実装担当とは別に、金融前の純結合と金融後の実約定・枠・集計を確認した。新しい候補・閾値・期限を追加せず、固定8候補の正しさを調べたもので、将来の収益性を保証する検査ではない。

## 保存物と結果

- [金融前の純結合](監査/純結合の第三者照合.json)：全35,361 q0×8候補。別式1,885,993属性と、符号鏡像・衝突の全組合せ180属性が一致。
- [金融後の独立照合](監査/金融の第三者照合.json.gz)：全3,903ユニーク成立セルを直接BBO走査で計算し、生産Routeと全属性同体。取得台帳・保有・予約74,112属性、既知3,032件の費用式、集計34,672属性も一致。
- [固定参照資源](監査/独立確認の参照資源.json)：純条件・金融開始票・元親4正本・83原順入力・監査核を束縛。
- [独立確認Source.zip](独立確認Source.zip)・[索引](独立確認Source索引.json)・[内容確認](監査/独立Source展開確認.json)：監査4Sourceと、再現に必要な小さな210親期待1件。主金融Sourceとは別保存。

金融前には親210 index 0/3、208 index 3、209 index 0/6/28を正式純入力から読み、同原行・同時計・当時帯・幅・origin・優先を確認した。Nightは旧符号をO、A適用後をA、独立FをFとしたとき、4条件の実側を `[O, A, O + 1[O=0]F, A + 1[O=0]F]` という別式で照合した。

Aが棄却した157 q0ではAFも0となり、元の旧入口がなかった6 q0だけでFが追加される。実データではA棄却と独立F成立の同時発生は0だったため、その衝突を人工全列挙で検査した。Fの持越し・後発q0への再要求は追加していない。

金融後は、旧0全packがID以外同体、親と14周辺帯の全台帳・保有・場順が同体。親210/208との比較だけは、旧幹の呼称として統一されたoriginを除く。AFのNightはDayの選択によらず同体。全8口座の合計取得は3,088件、未知は56件で、同じNight未知7件を8つの別口座に含む集計である。独立した未知事例が56個あるという意味ではない。

Fを使う各口座は純成立6 q0・実取得5件。Day条件を変えた重複口座を、Fの独立した支持数へ合算しない。

## 独立な部分と共用する部分

価格入力は既存の原順8列を共用する。独立核は時刻高水位を逐次処理し、取得後のBBO部分配列から最初の接触を線形に探す。生産側の到達木・Routeを期待値の作成には使わず、得た全成立セルを生産セルへ照合する。その上で、1件だけの保有/予約状態を別に再生し、後続要求の棄却、未知時の場末占有、返済同秒の新規禁止を確認した。

未知を損益0円にせず、既知費用式・保有下限/上限・両中央値の範囲・全場の分母・前48/後25/追加7/本日1/追加2を検査する。期間分割は候補数から推測せず、83場の固定順から直接定義した。

線形核は[211の恒久Source.zip](../00211_固定TOPIX入口に対するIFD期限の寄与を調べる/Source.zip)から `load_arrays` と `oracle` の2関数だけをASTで取り出す。ZIPと資源別SHAを確認し、独立集計器も同ZIPから読む。211の金融runnerや211の候補をimportしない。元原JSONから8列を作り直した検査、実注文の待ち行列や受信遅延の検証ではない。

## 再実行

確認環境はPython 3.14.3、numpy 2.5.4、tzdata 2026.6。主Sourceが任意importするorjsonは既存3.13.0。ライブラリバイナリはZIPへ重複保存していない。

主212のSourceと正式純入力、独立確認Sourceを索引通りに配置する。金融を再生した後、次を実行する。

```powershell
& 'work/複合テクニカル学習環境/Scripts/python.exe' -X utf8 'work/212独立確認/金融を照合212.py'
```

親期待の元照合には、209の正式2台帳、独立確認ZIPに収録した210主3の小台帳、211 Source.zipに収録した208主3の小台帳を、それぞれの元相対位置へ復元する。主212側の `金融前親期待.json.gz` も必要。純確認票は正式監査フォルダから元work相対位置へコピーする。

純結合検査は `純結合を照合212.py`。金融前の検査であることを守るため、同じ保存先に新金融開始票がある状態での実行は拒否する。新規の復元作業領域で主金融を実行する**前**に起動する。既存監査票や金融結果を削除して事前扱いへ戻さない。

独立監査の元原順台帳にも194の絶対pathが含まれるため、異なるrootへの無修正移転は確認していない。原位置の恒久inputsを参照する範囲の検査と、主担当による金融再現を区別する。主金融の隔離再現結果は本稿の監査だけから推定しない。
