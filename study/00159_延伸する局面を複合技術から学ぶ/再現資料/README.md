# 第159試行の再現資料

[snapshot抽出の再現コード.zip](snapshot抽出の再現コード.zip)は最初TP125時点の特徴抽出器、[実行コード.zip](実行コード.zip)は固定文法の学習・適用・保存経路合成とRoot集計/CSV/文書生成の小源。どちらもrepoルートからの元相対pathで格納する。[保管索引](保管索引.json)と[保存確認](../検査/再現資料の保存確認.json)へ全格納bytes/SHA/CRC・入力参照・依存・保存範囲を残した。

学習/集計/CSVや自然抽出を保存作業で再実行していない。型付き表、CSV/PNG、exe、node_modules、大入力、snapshot本体はZIPへ重複格納しない。モデル解釈と独立最終票は後発資料としてRootが追加するもので、先行F0へ遡及しない。

## 再現手順

保存snapshotを使う場合は抽出再実行不要。[snapshot準備](../検査/snapshot抽出の準備確認.json)・[停止](../検査/snapshot抽出の停止確認.json)・[保存時点検査](../検査/snapshot保存と時点の確認.json)が抽出器の元指紋と範囲を示す。コードを確かめるだけなら、親158 ZIPとsnapshot ZIPを復元し、抽出moduleで人工だけを実行する。

```powershell
Set-Location work/159延伸判断の特徴抽出
go test -count=1 -v ./...
go vet ./...
go build -o '<別のsnapshot159.exe>' ./cmd/run
```

本当にsnapshotを作り直す場合は、抽出器READMEのCLIで159条件/SHA・親結果両SHA・特徴manifestを指定し、既存恒久入力へ上書きしない。全149値の形/有限NULL/TTL/ref非未来を保存検査したが、149数式の別再実装や最初TPのRaw別再生ではない。158の公表時計・数値seed・Source早期限の限界を継承する。

固定snapshotと親結果からの学習/適用/合成（repo root、未作成の出力先）：

```powershell
& '<Python3.14.3/NumPy2.5.4のpython.exe>' -X utf8 'work/159複合条件の延伸選択/実行する.py' `
  --snapshot 'inputs/00159_延伸判断の特徴/判断時点の特徴.json.gz' `
  --snapshot-sha256 b7be610367196246af4125cabc10ea46157d4068896d29c35d0939084b41a148 `
  --snapshot-decoded-sha256 3ac97f2372c3c58b5c0e2584e0d72b27f08f3a50dec6c2cfcfe40e85db63fe7e `
  --parent-result 'study/00158_複合技術で出口の役割と局面を切り替える/成果物/出口結果.json.gz' `
  --parent-result-sha256 70a4c3178206bbb3c8641901c7515f2121da11c28403b88c3f8e6f93cc0baa6c `
  --parent-result-decoded-sha256 3c3df90244de838056ca7c98857ffe7b8f85514807e90194c07f73129ec277c7 `
```

元9モデル/6訓練窓・保存選択・合成出力は[学習完了票](../成果物/完了の確認.json)から参照できる。新checkoutの絶対path/実行物/mtimeが変われば、元JSONの物理SHAが変わり得る。絶対由来pathを書き換えて旧物理SHAと称さず、数値/選択/状態一致とbytes同体を区別する。

## 後発の診断と独立票

[モデルの解釈](../モデルの解釈.md)と[48KBの要点](../成果物/モデル解釈の要点.json)を正式追加した。[追加診断コードZIP](追加診断コード.zip)は結果後の分析器・作者停止票とRootの文書確認器だけを保存する。全件の反復転記を避け、詳細な群別中間JSONはwork内に置く。元の金融・学習F0へ遡及して含めない。[保存確認](../検査/追加診断資料の保存確認.json)で元短報とリンク整理後の正式短報を区別する。

[独立確認コードZIP](独立確認コード.zip)は、作者学習器をimportせず整数ビット集合/Fractionで全候補を再計算した小源、共通経路/選択/合成と三表の検算器を保存する。[モデル・選択・合成の独立票](../検査/モデルと選択と合成の独立確認.json)は全6訓練窓×12,464規則・5,022採否・20,088合成状態、[三表の独立票](../検査/総合三表の独立確認.json)は全147,312状態から508,640データセルを対象とした。CSVの508,748セルはヘッダーを含む別検査である。[独立コードの保存確認](../検査/独立確認コードの保存確認.json)に復元・人工・由来を記録した。最初の私有検算器のメタデータ対応不足による停止と、検算器だけの修正後の一致も独立票へ残す。
