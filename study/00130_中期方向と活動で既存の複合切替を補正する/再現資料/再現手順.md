## 原板なしで復元・人工検査する

リポジトリルートから、新規の作業先を指定する。コードZIPのCRC/各源SHA、旧共用gzipの解凍SHA、方向票SHAを照合する。金融前F1に含まれる方向票の人工検査・準備確認JSONも正式検査票から復元し、全23源の指紋を追跡できる。共有正本は作業先へ必要時だけ解凍し、元の恒久資源は更新しない。

```powershell
python "study/00130_中期方向と活動で既存の複合切替を補正する/再現資料/保存資料を復元する.py" --destination work/130再現
```

展開先のstudy/README等は実行前版を含む。正式な閲覧は元リポジトリの現行130資料を使い、復元版は条件の追跡に使う。展開先の`work/T8の活動による切替案`と`work/130既存入口の活動切替評価`でそれぞれ`python -X utf8 人工検査.py`。自然金融を読まない人工検査で、未知/0/閾値等号・売買鏡像・主副包含・全73/0件扱い・phase停止等を確認する。

## 固定評価を再計算する

別の新規作業先へ`--inputs-only`で復元すると、正本集計を置かずコード/固定入力を用意する。

```powershell
python "study/00130_中期方向と活動で既存の複合切替を補正する/再現資料/保存資料を復元する.py" --destination work/130再計算 --inputs-only
```

再現ルートを`work/130再計算`として、以下を実行する。全79取得と全73場を保持し、主V2・副V1・O0/B0/T8の方向票を変更しない。

```powershell
python -X utf8 work/130既存入口の活動切替評価/評価する.py --f1 work/130既存入口の活動切替評価/F1.json --f1-sha256 6d09694cb22abbbbe5de62f0aa66afa927ad01e99faf02f75dcbba0df5229f03 --evaluate-fixed-choices 93c204569d7a9828708d3891d984551784961138534c3cbde80759b602b24a9e --output-dir work/130既存入口の活動切替評価
```

F1とSource/choices/コードのSHAを検査してから旧正逆outcomesを読み、全政策のentry/touch/endpointが各場End−300より前かを検査する。違反時は停止し、取得やラベルを後から除外しない。旧O0/B0/T8の180条件は126へ一致することをassertする。結果は全体/前48/後25の各100条件・計300、前後は既使用期間の参考分解である。

出力は`集計.json`、`CSV用の表.json`、`評価完了.json`。保存表SHAは `1f21a01e09eba835f0f5498b865ffb8a12290e7a7bd4a5fda35bcc42b21c8ed4`。Direction票そのものの再生成は、125/126の準備資源まで[旧126の手順](../../00126_複合切替を時系列に分けて学習評価する/再現資料/再現手順.md)から復元する。固定方向票による本評価にはモデルの再学習は不要である。

## CSVの再作成

出力器は`work/130既存入口CSV出力/出力する.mjs`、独立再読は同フォルダの`CSVを独立再読する.py`。同版Artifactの既存runtimeへ`node_modules`を接続し、依存を大量複写しない。旧正本へ上書きしない新規先へ出力する。

```powershell
node work/130既存入口CSV出力/出力する.mjs --input work/130既存入口の活動切替評価/CSV用の表.json --sha256 1f21a01e09eba835f0f5498b865ffb8a12290e7a7bd4a5fda35bcc42b21c8ed4 --output work/130再現CSV
python work/130既存入口CSV出力/CSVを独立再読する.py --input work/130既存入口の活動切替評価/CSV用の表.json --sha256 1f21a01e09eba835f0f5498b865ffb8a12290e7a7bd4a5fda35bcc42b21c8ed4 --folder work/130再現CSV --output work/130CSV再読.json
```

[正式CSV案内](../../../outputs/01a1889f-f2af-7943-a047-543275ee9ed2/130既存入口CSV/README.md)。300×26/79×47/73×65、全16,258データcell/11,878数値を独立再読し、Rootが3画像を確認した。xlsxは生成していない。BBO/Last、主/副/固定対照、評価区分/費用後の利益・損失・未知を混ぜない。

この保存は新規注文のcap/I/TTL適格性、実mini約定、利益追尾、片側10枚口座収支を再現したものではない。全73場の既使用と過去のT8選択偏りを維持し、未知期の独立成功へ言い換えない。

## 結果後の独立検算

[追補コード](検算と保管の追補コード.zip)と[追補索引](追補コード索引.json)は、研究F1とは別の結果後コード。`work/130独立検算/検算する.py`は標準ライブラリ/Fractionだけで全方向・率・費用・PF・表を再構成し、評価器や旧124算術をimportしない。全300条件・旧180条件・16,258表セル・計31,437値が一致した[独立短報](../検査/独立数値検算.md)を保存した。

再計算で三表JSONまで用意した後に同コードを実行すると、全入力のSHAを確認して未作成`work/130独立検算/独立検算.json`へ証跡を保存する。既存の正本証跡へ上書きしない。bootstrap区間の独立再実装と原板先着の再走査はこの検算の対象外である。
