# NK225原順8列・81セッションの共用数量入力

2026-11-17生成。2026-09-21 Day～2026-11-16 Dayの81場（41Day/40Night）、3,354,040状態を約11.90 MiBのnpzへ一度だけ保存した。原板13,545,784行の全8属性が同じ連続状態だけを省略し、原行番号・順序を保持する。原板自体は複製しない。

目的は187の共通価格入口へ、188以降で数量可用性・相対量・持続を別要因として追加すること。この入力生成では指標の入口、先着、損益、採用候補を計算していない。

|列|意味|
|---|---|
|now|CurrentPriceTimeのUnix秒。受信時刻ではない|
|line|原板の物理行番号|
|last|CurrentPrice|
|bid/ask|Buy1/Sell1の価格|
|valid|正常価格順序と両気配の正数量を満たすか|
|volume|累積TradingVolume。完全な約定フローとは呼ばない|
|volume_time|TradingVolumeTime。価格時計と別に保存|

[入力台帳](入力台帳.json.gz)は全81ファイルのSHA/サイズ、原板実所在/物理SHA/展開後SHA、限月、欠測・時計後退・数量監査を持つ。旧60場は[試行2の固定台帳](../../study/00002_複数時間足と四系統の要因比較/入力台帳.json)へcache指紋と原板展開後指紋を照合して再用、追加21場を同じ[8列パーサ](../../scripts/複合検証/データ準備.py)で生成した。

[生成器](../../scripts/共通入力/NK原順数量を準備する.py)、[入力予約](入力予約.json)、[生成前固定](入力生成前固定.json)にSourceと元資料の指紋がある。旧資料の再用元はworkだったが、研究用の読み取り先はこの恒久入力だけでよい。

一部原板は `inputs/105生成原板/` に保存された既存の生成入力であり、全てが隣接JP_OSE_Data配下とは限らない。初回生成時の相対path記録だけを修正し、未登録だった3場を再生成して8列すべて一致を確認した。[実装修正確認](実装修正確認.json)。価格・数量の数式、旧パーサ、旧固定結果は変更していない。

再実行は、入力予約を元の `work/187共通対照/188向け数量入力の所在.json` へ同じbyteで配置し、生成器を実行する。既存キャッシュは上書きしない。既存81npzの利用にはこの再生成は不要。

```powershell
python -X utf8 scripts/共通入力/NK原順数量を準備する.py --workers 3
```

旧workの60cacheがない環境で原板から作り直す場合は、台帳のcurrent_rawを入力として旧パーサbuild_oneを別保存先へ実行し、8列の内容と由来を照合する。原板からの全件再生成と、保存npzの再利用を区別する。生成器自体の復元には、予約・旧60cacheを同じSHAで用意する。

数量時計が価格時計より未来の観測、累積減少、欠測、古い数量は、その利用時に明示的に扱う。欠測数量を0へ置換したり、過去の足へ未来の数量を遡及配置したりしない。可視数量の存在は真の全約定量の完全性を保証しない。
