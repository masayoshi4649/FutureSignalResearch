旧118の70場入力を再用し、末尾3場の公表だけを一度恒久保存する。[指紋](指紋.json)と[公表生成計画](公表生成計画.json)を正本とし、73場入力全体・Raw・Native・exeはここへ複写しない。

公表は11-09 Day 122件、11-09 Night 230件、11-10 Day 122件、計474件。candle300→115公開wrapper→当場Raw配送で生成し、予定Endの前史CSV seedを継承した。Raw EOF seedを後場へcarryせず、指標/seed・Raw/CSV参照とSHA・品質を同梱する。金融結果は生成していない。

旧118入力は77,606,890 bytes、SHA256`574771f654937036b48c78eceadb46a4c5ff3c10265f60b0ec7879efb0d862c3`。[118再現手順](../../study/00118_指値待機と複数技法の取得確認で入口を比較する/再現資料/再現手順.md)を参照する。旧12,320公表は同値再用し、合計73場・12,794公表へ結合した。前史anchorは2026-09-21 Dayのまま。

[122再現手順](../../study/00122_E0固定条件を全セッションで検証する/再現資料/再現手順.md)に従い、新規公表を`work/122全場入力/新規公表.json`へ解凍し、固定計画・旧70同体・既知公表照合を同じ作業パスへ復元する。`入力を結合する.py`で旧118入力と結合した出力は177,709,174 bytes、SHA256`6a6cd13dfd00c9669b522e3c3c8e06a4066766f6075786f64d8c0feeb45513ec`へ一致する。旧70を再整形したため入力全体の容量は増えているが、重複する73場全体は恒久保存しない。

Stage A固定前に新3場を読まず、固定後に指紋処理を行った。解除成立時刻と初読実時計の区別、版同体と公表配送検査の範囲は[結果と限界](../../study/00122_E0固定条件を全セッションで検証する/結果と限界.md)へ記録した。
